# MediaHub

一个使用 C++20 和 Qt 5.14.2 开发的 Windows 桌面媒体播放器。

> **当前状态：v0.1、v0.2、v0.3 与 v0.4 均已按本地自用版本完成。**

## 这是什么

MediaHub 已完成四个本地自用版本：

| 版本 | 能力 | 状态 |
|---|---|---|
| v0.1 | 播放本地音频和视频文件 | 本地自用已封存 |
| v0.2 | 输入直播地址，解析远程清单 URL，并分开显示本地与直播列表 | 本地自用已封存 |
| v0.3 | 区分本地音频、本地视频和直播场景的界面重构 | 本地自用已完成 |
| v0.4 | 恢复列表和直播 URL，增加历史、取消、静音与快捷键帮助 | 本地自用已完成 |

播放内核采用 libVLC，但藏在一个自定义的 `PlayerEngine` 纯虚接口之后。界面代码
完全不知道 libVLC 的存在，使界面、核心逻辑和真实播放能力可以分别测试和维护。

设计取舍的完整理由见
[docs/设计/播放内核选型.md](docs/设计/播放内核选型.md)。

## v0.3 界面重构

- 本地音频采用明亮留白、低饱和绿色、真实 PCM 波形和沉浸歌词的音乐界面。
- 本地视频采用冷黑影院画布、深色信息卡和低干扰控制台，活动视频仍由 libVLC
  直接输出，不被 Qt 样式覆盖。
- 直播采用紧凑深色工具界面，把远程清单地址、载入、定位和状态集中在信号源工具区，
  频道列表使用暖黄色状态与高密度行。
- 三种模式复用同一组按钮、快捷键、列表模型和 Presenter 路由；换肤不会重建控件、
  重复连接信号或改变播放命令。
- 默认 `960x720`、`1200x800`、最小窗口、全屏及 100%/125%/150% 模拟缩放均纳入
  GUI 回归。详细证据见
  [docs/测试/v0.3界面重构测试.md](docs/测试/v0.3界面重构测试.md)。

## v0.4 状态与快捷键

- 本地播放列表会保存顺序和列表内显示名，重新启动时恢复但不会自动播放。
- 最后直播清单 URL 会回填；成功载入的清单保留最近 20 项历史，可在独立窗口中
  选择回填或删除，回填不会自动发起网络请求。
- 清单载入期间可用原按钮取消；`F11` 双向切换全屏，`Ctrl+下键` 静音，
  `Ctrl+上键` 恢复声音，单独 `F5` 继续刷新直播。
- “帮助 → 快捷键”集中列出当前版本支持的键盘操作。
- “帮助 → 直播源”或主窗口 `Ctrl+M` 可打开独立的地址与备注保存窗口；它不会解析
  或播放，也不会替换现有播放列表。保存按钮和仅限该窗口的 `Ctrl+S` 都会先请求
  确认，返回与 `X` 会处理未保存修改。

## v0.1 已完成能力

- 打开本地音频和视频文件（菜单、拖放、命令行参数）
- 播放、暂停、继续、停止
- 视频画面输出；音频播放时显示声音强度驱动的固定单曲线
- 进度显示、拖动或单击定位，媒体结束后可定位并自动续播
- 进度条与全部播放控制同排，悬停调节音量，点击音量按钮静音或恢复
- 空格播放/暂停、方向键调音量和按可配置秒数快进后退，`Ctrl+左/右` 切换曲目
- 播放列表，支持顺序、列表循环、单曲循环和随机播放，并可折叠或展开
- 纯音频在线歌词：内嵌歌词优先，酷狗、网易云、LRCLIB 和 TheAudioDB 逐级降级
- 播放失败的明确中文提示
- 终端结构化日志（不写日志文件、不记录完整媒体路径）

- 媒体库、播放历史、封面刮削

## v0.2 已完成能力

- 从“文件 → 打开网络地址”输入用户自己提供的直播 URL。
- 首批支持 `http`、`https`、`rtsp`、`rtmp`、`rtmps`、`udp`、`rtp` 和 `srt`。
- 直播连接由 libVLC 异步执行；未知总时长或不可定位时禁用主进度条。
- 连接期间显示缓冲百分比；点击停止可立即取消，15 秒未播放会显示
  连接超时，取消或超时后可点播放重试。
- 网络失败使用可读中文错误；完整 URL、凭据、查询参数和片段不进入界面
  错误或日志。
- 真实 libVLC 控制命令在专用线程串行执行；取消网络流时立即换用新播放器，
  切换媒体时进一步换用独立 libVLC 实例。旧流的慢回收不会卡住界面、覆盖新媒体
  或改变新播放器的音量和静音状态。
- 第三增量保留最多 10 条、去重且不持久化的会话内最近地址。早期有限自动重连虽已
  完成验收，但公网流复验表明应用无法可靠区分源站短暂停顿和真实断流，因此最终
  版本取消自动重连和活动停滞推断。
- 当前网络直播会显示“刷新直播”按钮；无论正在播放、缓冲、连接失败还是用户观察到
  普通画面停顿，点击按钮或按 `F5` 都会立即重开当前地址。刷新不新增列表项、不重复
  最近地址；本地歌曲和视频按 `F5` 不执行播放命令。
- 第四增量完成正常直播与慢连接、本地 MP3/MP4 往返、进度、音量、歌词、波形、
  全屏、15 秒超时、重试取消和安全关闭的完整实机回归，项目版本元数据更新为
  `0.2.0`。后续公网 HLS/HTTP-FLV 复验确认直播始终保持不可定位语义，直播源之间
  切换后再返回本地歌曲会立即恢复声音，无需触碰音量。
- 单 URL 直播现已封存。第五增量新增纯核心 `LiveChannel` / `LiveChannelLibrary` 和
  UTF-8 M3U 解析、序列化、重复/跳过统计及往返一致性测试；Debug/Release 全量
  CTest 均为 `67/67`。
- 用户已取消频道分类、本地 `channels.m3u` 和逐频道维护方案。直播页现在可输入
  远程 M3U/M3U8 清单 URL，软件只读取清单文本并显示其中的扁平直播条目，不下载
  MP3、MP4 或任何音视频文件。
- 播放列表侧栏已明确分为“本地播放列表”和“直播列表”；本地文件与直播条目互不
  混入，切换页面不会停止正在播放的媒体。
- 清单读取限制为 10 秒、5 次安全重定向、2 MiB 正文和 5000 项；新清单失败时保留
  上一次有效直播列表，普通 HLS 分片清单不会被错误显示成频道列表。
- `Ctrl+L` 可直接输入直播流或 M3U/M3U8 清单 URL：`.m3u` 始终作为频道清单展开，
  读取失败时不会被加入为一个直播文件；`.m3u8` 只有检测到真实 HLS 控制标签后才
  回退为直接播放。Windows 版使用系统 HTTPS 能力读取清单，不依赖 Qt 5.14 环境中
  未部署的 OpenSSL 1.1 运行库。
- 直播条目不提供分类、重命名、排序或删除；右键可播放/暂停、停止当前源、会话内
  标记不可用或收藏，选择后复用现有 libVLC 网络连接、停止、刷新、超时和迟到事件
  隔离链路。
- 当前 Debug/Release 全量 CTest 均为 `72/72`，Core-only 为 `52/52`；用户已使用
  自己的清单 URL 完成可见页面与真实音画人工验收。
- 软件不内置、搜索、抓取或托管第三方频道；Logo、EPG、分类、收藏持久化和定时订阅
  不在当前范围。

详细范围和验收规则见
[docs/规划/v0.2直播播放.md](docs/规划/v0.2直播播放.md)；远程清单详细规划见

## 安全边界

MediaHub 只**读取**用户的媒体文件。程序不修改、不移动、不删除、不重命名任何
文件，也不提供任何清理或整理功能。

MediaHub 不内置任何直播源列表，不提供源搜索能力，也不实现任何绕过访问控制的
手段。v0.2 只负责播放用户自己提供的地址，用户需自行确保所播放内容的来源合法。
完整直播 URL 只在当前进程内用于播放；日志和列表名称不记录 URL 用户信息、查询
参数或片段。

在线歌词只发送标题、艺术家、专辑和歌曲时长，不上传音频内容或本地文件路径。查询
结果写入应用缓存目录；酷狗和网易云歌词源属于非官方接口，当前仅按个人本地使用
范围接入。

## 构建

### 需要什么

| 组件 | 版本 | 说明 |
|---|---|---|
| Qt | 5.14.2 msvc2017_64 | 已在本机 `C:\Qt\Qt5.14.2` |
| MSVC | VS 2022 | 已在本机 |
| CMake | 3.20 以上 | 已在本机 |
| Ninja | 任意 | VS 2022 自带 |
| libVLC | 3.0.21 win64 SDK | 已在本机 `C:\SDK\vlc-3.0.21` |
| GoogleTest | 1.17.0 | 已固定在 `Third_Party/googletest` |

libVLC 不随仓库分发。获取和接入步骤见
[docs/交付/依赖接入与部署说明.md](docs/交付/依赖接入与部署说明.md)。

### 怎么构建

普通终端找不到 `cl.exe` 和 `ninja.exe`。使用 VS 开发者命令提示符，或在
Qt Creator 中配置构建套件。

```powershell
cmake -S . -B cmake-build-debug -G Ninja ^
      -DCMAKE_BUILD_TYPE=Debug ^
      -DCMAKE_PREFIX_PATH="C:/Qt/Qt5.14.2/5.14.2/msvc2017_64" ^
      -DMEDIAHUB_VLC_ROOT="C:/SDK/vlc-3.0.21"

cmake --build cmake-build-debug
ctest --test-dir cmake-build-debug --output-on-failure
```

只构建并测试不依赖 Qt、libVLC 的核心层：

```powershell
cmake -S . -B cmake-build-core-debug -G Ninja ^
      -DCMAKE_BUILD_TYPE=Debug ^
      -DMEDIAHUB_CORE_ONLY=ON

cmake --build cmake-build-core-debug
ctest --test-dir cmake-build-core-debug --output-on-failure
```

运行当前程序：

```powershell
.\cmake-build-debug\MediaHub.exe
```

### 更换窗口图标

构建和正式安装会在 `MediaHub.exe` 旁生成 `icons` 目录。完全退出 MediaHub 后，
直接替换以下同名文件并重新启动即可生效，无需重新编译：

- `icons/taskbar.png`：Windows 任务栏使用的图标。
- `icons/window.jpg`：窗口标题栏左上角使用的小图标。

两个文件独立读取；任一文件缺失、损坏或无法解码时，只会将对应位置回退到程序内置
图标。Windows 资源管理器显示的 `MediaHub.exe` 文件图标属于可执行文件资源，仍使用
编译时内置图标，不会被运行时图片改写。

当前 `MediaHub.exe` 已提供文件菜单、网络地址入口、音视频输出区域、键盘控制、状态
提示和播放列表。选择本地媒体或输入通过校验的直播 URL 后会自动开始播放。控制区
只有一行，依次放置进度条、上一首、
播放/暂停、下一首、停止、音量、歌词、倍速、左右键跳转秒数、播放模式和全屏。

上一首、下一首、播放/暂停、停止、音量、播放模式和全屏均使用图标；播放/暂停、
喇叭/静音和进入/退出全屏会随当前状态切换图标。同一个全屏按钮可进入或退出全屏。
音量按钮悬停后向上弹出竖向滑块，提示只显示百分比数值；点击按钮可静音或恢复，
静音时滑块显示 0% 并切换为静音图标，恢复时回到原音量。

纯音频打开后，音量右侧的圆形“词”按钮可在波形页和歌词页之间切换。程序优先读取
MP3 内嵌歌词，再按酷狗、网易云、LRCLIB、TheAudioDB 的顺序在线查询并缓存。酷狗
会结合歌曲分组和音频条目哈希选取 LRC，并排除 DJ、Live、Cover、纯音乐等不一致
版本。带时间戳歌词会跟随主进度逐行高亮，普通歌词显示为可滚动全文；断网或无结果
不影响播放。第三方时间轴存在固定误差时，可在歌词页按 0.5 秒步进校准：`+0.5s`
让歌词变快，`-0.5s` 让歌词变慢；校准值按歌曲哈希保存，不会影响其他歌曲，也不会
记录本地完整路径。进入全屏或调整
窗口尺寸时，同步歌词、普通歌词、左上角文件名、来源标签和时间校准控件会按实际
歌词区域宽高自动缩放，保证大屏可读且校准按钮仍便于点击。

播放 MP3、WAV、FLAC 等纯音频时，主画面只显示文件名和一条位于画面底部、不横向
移动的连续线；当前 PCM 被归并为 24 个圆滑控制段，只从底部基线向上形成疏密适中的
高波峰，并按当前歌曲的实际声音强度快速升起和回落。波形窗口
内部不再重复显示进度条和百分比，控制行的主进度条保持可定位。音频支持双向全屏；
曲线固定为 192 个绘制点并缓存静态背景，全屏不会随屏幕宽度增加计算量。

支持 0.5×、0.75×、1.0×、1.5×、2.0×、3.0× 播放倍速。倍速和左右键跳转
步长均可通过向上展开的悬停菜单选择；跳转值为 5、10、15、20 秒，默认 5 秒，
三个选项菜单使用不抢占鼠标的独立悬浮窗，鼠标离开控件与菜单后会自动收起。
轻按右方向键按当前跳转值快进一次，长按则临时
以固定 2.0× 播放并显示 2.0×，松开后恢复用户原先选择的速度。

### 生成发布目录

阶段 12 使用单独的 Release 配置生成干净发布目录。目标 Qt 安装必须包含匹配版本的
源码许可证文件；目标机器需预先安装 Microsoft Visual C++ 2015-2022
Redistributable（x64）。发布前缀应使用新的空目录：

```powershell
cmake -S . -B cmake-build-stage12-release -G Ninja ^
      -DCMAKE_BUILD_TYPE=Release ^
      -DCMAKE_PREFIX_PATH="C:/Qt/Qt5.14.2/5.14.2/msvc2017_64" ^
      -DMEDIAHUB_VLC_ROOT="C:/SDK/vlc-3.0.21" ^
      -DMEDIAHUB_PACKAGE_RELEASE=ON
cmake --build cmake-build-stage12-release
cmake --install cmake-build-stage12-release --config Release ^
      --prefix dist/MediaHub-0.1.0-win64
cmake -DMEDIAHUB_PACKAGE_DIR=dist/MediaHub-0.1.0-win64 ^
      -P tools/validate_release_package.cmake
```

发布目录和构建目录均被 `.gitignore` 排除。隔离启动与依赖来源检查见
`tools/stage12_isolated_smoke.ps1`。

“打开文件”按钮位于播放列表底部。列表支持拖放、双击播放以及右键播放、暂停、停止、
置顶、上移、下移、移出列表和仅修改列表显示名的重命名；重命名不会改动电脑中的
原文件名。右键当前项时，播放、暂停和停止会按实际播放状态互斥启用；右键其他项时
只允许切换播放，避免控制到正在播放的另一项。
按住 `Ctrl` 可选择多个独立项目，按住 `Shift` 可连续选择；多选右键时只允许移出列表，
其他操作会置灰。播放模式支持顺序、列表循环、单曲循环和随机播放。
悬停播放模式按钮可从列表选择，直接点击按钮则依次循环切换，
悬停列表的勾选项会同步更新。列表旁的箭头可折叠或展开列表，音视频区域会自动占用释放出的
空间。`Ctrl+左/右` 可直接切换上一首/下一首，命令行可以一次传入多个本地媒体路径。

## 架构一句话

```text
apps/gui  ──依赖──>  mediahub_core（抽象接口）  <──实现──  mediahub_engine_vlc
   ↑                                                              ↓
只知道接口                                                     libVLC
```

界面不认识 libVLC，核心不认识 Qt。只有 `main.cpp` 同时认识两者，负责组装。

## 已知限制

以下限制在规划阶段就已确定：

- 仅支持 Windows x64。
- 具体格式的播放能力取决于 libVLC 与所携带的插件，项目不做能力承诺。
- 音画同步由播放内核负责，项目不提供同步质量指标。
- 视频画面、声音输出和音画同步不能只靠自动化判断，阶段 6 已完成单一 MP4 实机验收。
- 发布包体积较大，主要来自 libVLC 插件目录。
- Qt 5.14.2 已是归档版本，长期维护应单独评估 Qt 6。

## 许可证

- 项目自身源码许可证**尚未决定**。
