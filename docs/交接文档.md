## 1. 使用说明

本文件用于在不同开发窗口之间传递当前状态。开始新会话时先阅读本文件和项目根
目录的 `AGENTS.md`，然后执行：

```powershell
git status --short --branch
```

实际 Git 状态优先于本文档。如果两者不一致，先查明原因并更新本文档，不要直接
开始下一阶段。

每个阶段实现完成、规定测试通过且阶段测试文档回填后，自动创建本地 Git 提交；
测试失败或存在阻塞项时不提交。远程认证可用且没有冲突时自动推送，然后继续下一
阶段；禁止覆盖远端历史。

## 3. 长期开发规则

- 使用 C++20、CMake、Ninja、Qt 5.14.2 和 GoogleTest。
- 公共核心头文件放入 `include/mediahub/core/`，实现放入 `src/core/`。
- 内核实现放入 `src/engine_vlc/`，公共头文件放入 `include/mediahub/engine_vlc/`。
- GUI 代码放入 `apps/gui/`。
- 测试分别放入 `tests/unit/`、`tests/integration/` 和 `tests/gui/`。
- 每个阶段编写独立的 `docs/测试/阶段N测试.md`。
- 第三方源码统一放入 `Third_Party/<library>/`，不直接修改。
- **libVLC 不进入仓库**，通过 `MEDIAHUB_VLC_ROOT` 指向本机目录。
- **核心层不得依赖 Qt 和 libVLC。**
- **GUI 层不得链接 libVLC。**
- **内核事件回调中不得操作 Qt 控件。**
- `main.cpp` 只处理程序边界、对象组装和异常兜底。
- 项目自有代码注释必须使用中文。
- 涉及线程的函数，注释必须写明调用线程。
- 测试媒体在运行时生成，不依赖固定盘符或个人路径。
- 不提交任何有版权的音视频素材。
- 不提交 `build/`、`cmake-build-*/`、`.idea/` 和 `.vs/`。

## 6. 下一步：阶段 5

**目标**：建立正式音频控制界面，并把 libVLC 内核线程事件安全投递到 Qt 主线程。

**具体工作**：

1. 建立正式主窗口菜单、打开文件入口、播放、暂停、停止按钮和状态文字。
2. 建立 `PlayerPresenter`，统一维护状态机和控件启用规则。
3. 建立 `EngineEventBridge`，只负责把值类型事件排队投递到 GUI 主线程。
4. 在 `main.cpp` 构造 `VlcPlayerEngine` 并完成依赖组装，GUI 支持库仍不链接 libVLC。
5. 打通打开本地音频、播放、暂停、继续和停止链路。
6. 使用 `FakePlayerEngine` 与 Qt Test 覆盖控件状态、基本控制和线程投递。
7. 编写 `docs/测试/阶段5测试.md` 并同步交接与变更记录。

**通过条件**：

- 界面操作不阻塞，内核事件的业务处理全部发生在 Qt 主线程。
- 控件启用状态只由 `PlayerPresenter` 决定，窗口不重复判断业务规则。
- Qt Test 覆盖打开、播放、暂停、继续、停止和跨线程事件基本流程。
- `mediahub_gui_support` 只依赖核心接口与 Qt，不链接 libVLC。
