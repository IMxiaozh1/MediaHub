# MediaHub 代码规范（C++20）

> 状态：规划中，随第一笔代码开始生效。目标是让代码容易阅读、测试和解释，
> 不追求形式上的复杂。
>
> 分类：设计。

## 1. 基本原则

- 正确性和可读性优先于炫技。
- 用类型表达约束，避免依赖注释补救模糊设计。
- 一个函数只承担一个清晰职责。
- 优先值语义和 RAII，不手工管理资源生命周期。
- 只使用能解决实际问题的 C++20 特性。

## 2. 语言与构建

- 语言标准固定为 C++20，关闭编译器扩展。
- 源文件统一使用 UTF-8。
- Debug 和 Release 都必须能够构建。
- 新增警告不得被忽略；禁止通过全局关闭警告掩盖问题。
- 构建产物只能放在源码目录之外的 build 目录。

## 3. 格式

- 缩进使用 4 个空格，不使用 Tab。
- 左花括号与声明放在同一行。
- 建议单行不超过 100 个字符；长参数按语义换行。
- 头文件使用 `#pragma once`。
- 每个文本文件以换行结尾。
- 后续用 `.clang-format` 固化格式，规则经双方确认后再添加。

## 4. 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 类、结构体、枚举 | `PascalCase` | `MediaItem` |
| 函数、方法 | `lowerCamelCase` | `openMedia` |
| 局部变量、参数 | `lowerCamelCase` | `sourcePath` |
| 私有成员 | `lowerCamelCase_` | `currentIndex_` |
| 编译期常量 | `kPascalCase` | `kMaxVolume` |
| 命名空间 | `snake_case` | `mediahub` |
| 文件名 | `snake_case` | `player_engine.h` |

- 名称应表达业务含义，避免 `data`、`temp`、`obj` 等模糊命名。
- 布尔值使用 `is`、`has`、`can`、`should` 等前缀。
- 表达“请求做某事”的方法直接用动词，不加 `request` 前缀；接口注释说明其为
  异步请求。

## 5. 注释

注释遵循 [Google C++ Style Guide 的 Comments 章节][google-comments]，并采用
以下项目约定：

- 项目自有代码的注释必须使用中文；类型名、函数名、参数名及必要的技术术语
  可以保留英文。
- 优先使用 `//`，同类位置保持一致。
- 公共接口和非显然的类、结构体、枚举必须说明用途、使用方式及重要约束。
- 函数声明注释说明用途、输入、输出、所有权和错误行为，不展开实现细节。
- 函数定义只在实现存在关键步骤、取舍或容易误解的行为时补充说明。
- **凡是涉及线程的函数，注释必须写明它会在哪个线程被调用。** 这是本项目的
  额外强制要求，原因见第 10 节。
- 注释重点解释“为什么”和调用约束，不逐行复述读者从代码即可看出的行为。
- 注释使用语法完整、标点正确的句子，并在代码行为变化时同步更新。
- 能通过清晰命名和拆分表达的内容，优先改进代码，不依赖注释挽救模糊设计。
- `TODO` 仅用于临时或短期方案，必须包含 Issue、负责人或其他可追踪标识，
  例如 `// TODO: issue #12 - 移除旧的音量映射。`。
- 不添加无依据的作者署名或许可证声明；项目确定许可证后统一补充文件头。
- 第三方源码保持上游原貌，不翻译或修改其注释。

[google-comments]: https://google.github.io/styleguide/cppguide.html#Comments

## 6. 头文件与依赖

- include 顺序：当前头文件、C++ 标准库、第三方库、项目头文件。
- 各组之间空一行，同组按字母排序。
- 头文件中禁止 `using namespace`。
- 能前向声明时可前向声明，但不能牺牲可读性。
- 公共头文件不得依赖应用层或界面层。
- 不在头文件中放无必要的实现，模板与短小内联函数除外。

本项目的硬性依赖禁令：

| 位置 | 禁止出现 |
|---|---|
| `include/mediahub/core/` | Qt、libVLC、Windows 头文件 |
| `include/mediahub/engine_vlc/` | Qt 头文件、libVLC 类型 |
| `src/engine_vlc/` | Qt 头文件 |
| `apps/gui/` | libVLC 头文件 |

## 7. 接口设计

- 单参数构造函数默认使用 `explicit`。
- 不修改对象状态的方法使用 `const`。
- 调用方不应忽略的重要返回值使用 `[[nodiscard]]`。
- 确实不会抛异常的函数使用 `noexcept`，不机械添加。
- 优先返回对象，不用输出参数同时返回多个结果。
- 避免过长参数列表；相关参数应组合为有含义的结构体。
- 枚举使用 `enum class`。
- 抽象接口只在确实需要替换实现的位置使用，不为了“将来可能扩展”提前抽象。

抽象接口的额外要求：

- 析构函数必须是 `virtual`。
- 禁止在接口中提供默认实现，除非该默认行为对所有实现都正确。
- 接口方法的注释必须说明它是同步完成还是异步请求。

## 8. 所有权与生命周期

- 默认使用栈对象和值语义。
- 独占动态资源使用 `std::unique_ptr`。
- 只有确实存在共同所有权时才使用 `std::shared_ptr`。
- 裸指针和引用只表示非拥有关系，且不得超过被引用对象生命周期。
- 禁止直接使用 `new`、`delete`、`malloc` 和 `free`。
- 文件、线程和锁必须由 RAII 对象管理。

### 8.1 C 库句柄的包装

libVLC 是 C 库，所有句柄都需要成对的创建和释放。规定：

- 每一种句柄必须用带自定义删除器的 `std::unique_ptr` 包装。
- 包装类型在使用它的实现文件或私有头文件中定义，不进入公共头文件。
- 禁止在业务代码中直接调用 `libvlc_*_release`。
- 释放顺序必须显式说明并在注释中记录。

### 8.2 释放顺序

播放内核的释放顺序在实现中必须固定，且不得依赖成员声明顺序的巧合。正确顺序在
[02-v0.1-实现设计.md](02-v0.1-实现设计.md) 中给出，实现时用注释标注。

## 9. 错误处理

- 打开失败、格式不支持、设备不可用等预期失败必须显式返回或通过事件上报，
  不得静默忽略。
- 内核返回的错误码必须转换为项目自己的失败类别，不把原始码直接传给界面。
- 面向用户的提示必须是中文完整句子，说明哪个文件出了什么问题。
- 捕获异常后必须补充上下文或在应用边界统一转换，禁止空 `catch`。
- `assert` 只检查程序员错误，不用于处理用户输入或运行时失败。
- 日志不得包含媒体文件完整路径、凭据或个人信息。

## 10. 并发

播放器的并发问题集中在一处：**播放内核的事件回调发生在内核自己的线程上。**
这一节的规则全部围绕这个事实。

- **禁止在内核事件回调中操作任何 Qt 控件。** 事件必须先投递到 GUI 主线程。
- **禁止在内核事件回调中调用可能阻塞等待内核线程的接口**，例如停止和释放。
  需要这些操作时，先投递到主线程，由主线程发起。
- 每个可能被多线程访问的成员必须明确说明同步方式。
- 优先通过消息传递减少共享可变状态。
- 需要跨线程读取的状态快照使用原子变量或互斥量保护，二选一并写明理由。
- 禁止分离线程；每个线程都必须有明确所有者和结束路径。
- 持锁期间不执行文件 I/O、内核调用或未知外部回调。
- 涉及线程的每个函数，注释必须写明调用线程。

推荐在实现中使用统一的线程标注：

```text
// 调用线程：GUI 主线程。
// 调用线程：libVLC 事件线程，禁止在此操作控件。
// 调用线程：任意，内部自行加锁。
```

## 11. 测试

- 核心逻辑必须能脱离 Qt、libVLC 和音频设备单独测试。
- 每个测试只验证一个行为，名称说明场景和预期。
- 播放逻辑测试使用假内核，不使用真实播放。
- 内核集成测试使用哑音频与哑视频输出，不依赖真实声卡和显示设备。
- 测试媒体在运行时生成，不依赖固定盘符、个人路径和有版权素材。
- 测试不得依赖执行顺序。
- 涉及异步事件的测试必须有明确的等待条件和超时上限，禁止用固定 sleep 碰运气。
- 修复缺陷前先补充能够复现问题的测试。

## 12. 明确禁止

- 全局可变状态。
- C 风格强制转换。
- 魔法数字和散落的路径常量。
- 为简单问题引入复杂继承层次。
- 在 `main.cpp` 中堆积业务实现。
- 在界面代码中直接调用播放内核 API。
- 在内核事件回调中直接刷新界面。
- 用固定时长 `sleep` 代替明确的同步条件。
- 把本机绝对路径写入项目 CMake 或源码。
- 未经讨论新增第三方依赖。
- 在仓库中提交任何有版权的音视频素材。
