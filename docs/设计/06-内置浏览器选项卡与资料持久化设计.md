# MediaHub 内置浏览器选项卡与资料持久化设计

> 状态：原选项卡三阶段实现及规定自动化验证已完成；日常增强阶段一已完成当前实现，
> 普通 Windows Runtime 与人工验收仍待补；阶段二设计已冻结并进入实现，不代表已通过。
>
> 范围：MediaHub 内置网页展示模块。网页功能与本地媒体、直播播放链路相互独立。

## 1. 目标与边界

本增量只扩展内置浏览器，不改变 `mediahub_core`、libVLC 播放器、播放列表或直播
清单模型。主窗口只负责展示模式切换；网页模块内部拥有自己的选项卡、导航状态、
历史记录和收藏夹。

WebView2 使用 MediaHub 专用持久 Profile。所有选项卡共享该 Profile，因此 Cookie、
LocalStorage、IndexedDB、Service Worker、缓存、已保存密码和自动填充资料由 WebView2
自己保存并跨重启恢复。MediaHub 不读取、解析、记录或写入 QSettings 的敏感资料；Edge
个人 Profile 不复用、不修改。

## 2. 组件关系

```text
MainWindow
└── BrowserPage (网页展示模块)
    ├── BrowserTabController (GUI 主线程，标签模型与当前标签)
    │   ├── BrowserTab 0..N (地址、标题、前进/后退状态、WebView 控制器)
    │   └── BrowserHistory / BrowserFavorites (QSettingsBrowserDataStore)
    └── BrowserBackend (抽象)
        └── WebView2BrowserBackend (共享 Environment/Profile，按标签创建 Controller)
```

`BrowserBackend` 的公开接口保持 Qt 值类型和稳定事件，不暴露 COM、HWND 或 WebView2
接口。每个标签的 WebView2 Controller 都绑定同一个 Environment/Profile，但有独立的
导航栈和可见边界。所有 WebView2 回调先带标签代次，再由 Controller 投递到 GUI 主线程。
普通事件即使发生在 GUI STA 也必须通过 Qt 队列离开 COM 事件栈后再操作控件；
`NewWindowRequested` 先取得 deferral 并保存为带稳定请求 ID 的未决项，再排队请求 GUI
创建标签，成功、失败或关闭都只能完成一次。

## 3. 选项卡语义

- 页面顶部显示选项卡栏；每项显示页面标题，空白页显示“新标签页”。
- 地址栏在加载完成后仍可编辑；点击或 `Ctrl+L` 聚焦并全选当前地址。
- 地址栏提交复用当前标签，不创建新窗口。
- `window.open`、链接 target=_blank 和“在新窗口打开”统一请求新标签；弹窗与主页面
  共享 Profile，不再创建独立浏览器资料。
- 网站脚本用于后续写入内容的精确 `about:blank` 新窗口也转换为标签；地址栏和收藏等
  用户输入入口仍不接受内部协议。新窗口 deferral 无论创建成功或失败都只完成一次。
- 每个标签保存 WebView、可见地址、标题、`canGoBack`、`canGoForward` 和当前导航
  代次。每次显式导航按 WebView2 `NavigationId` 绑定对应代次，晚到完成事件不得覆盖
  后续地址提交。切换标签只改变可见 Controller，不销毁网页会话。
- 标签保存自己的正常/失败页面状态和最后错误类型；切换时同步恢复网页宿主、错误页、
  状态文字与导航按钮。关闭后台标签不得拒绝当前标签仍在等待用户回答的安全请求。
- 切换或关闭当前标签前先请求旧网页退出 Fullscreen API，并立即恢复宿主工具栏状态，
  防止旧标签的全屏外观泄漏到新标签。
- 关闭标签只关闭该标签的 Controller；最后一个标签关闭后立即创建空白标签。
- 历史/收藏夹默认当前标签打开；Ctrl+点击或鼠标中键新建标签。

## 4. 历史记录与收藏夹

历史项字段为网址、页面标题、访问时间（UTC 毫秒）。成功的顶层导航完成后写入历史，
按规范化网址去重并移到最前，数量限制为 500 条。收藏项字段为网址、页面标题和备注，
按规范化网址去重，数量限制为 5000 条。两者均由浏览器专用
`QSettingsBrowserDataStore` 保存到 MediaHub 自己的配置组，跨进程和跨重启恢复；不得
进入播放器 `AppStateSnapshot` 或播放列表持久化模型。

QSettings 永远不写入密码、Cookie、Token、表单值、Profile 路径或网页正文；日志也不
记录这些内容。清除网页数据只调用 WebView2 Profile API，不删除 MediaHub 自己的历史
和收藏夹。历史和收藏 URL 持久化前必须移除用户信息、查询参数和片段，避免 OAuth
`code`、Token 或页面内敏感状态进入 QSettings；页面实际导航地址不受此存储规则影响。
单纯的网页标题变化只更新已有历史项的标题，不改变排序或访问时间，不虚构一次访问。
用户停止正在进行的导航时恢复现有页面与 Ready 状态，但同样不得写入一条成功访问历史。

## 5. 清除网页数据

确认后对共享 Profile 调用全量 `COREWEBVIEW2_BROWSING_DATA_KINDS_ALL_PROFILE`，明确
覆盖 Cookie、LocalStorage、IndexedDB、缓存、Service Worker、下载历史、浏览历史、
已保存密码和通用自动填充。确认清除后先关闭除当前标签外的所有 Controller，防止后台
网页在清除期间重新写入 Profile；当前存活 Controller 完成 Profile、证书例外和内部
`about:blank` 导航后，界面只保留该真实 WebView 支撑的空白标签。当前标签无论是最初
Controller 还是后建标签 Controller，都必须执行同一清除序列。Edge Profile 不受影响。
若当前 Runtime 不支持某个 Profile API，显示失败，不直接删除被占用的资料目录。

## 6. 线程与生命周期

标签模型、QSettings、Qt 控件和后端命令只在 GUI 主线程操作。WebView2 事件回调不得操作
Qt 控件或等待浏览器线程；回调仅构造稳定值事件并通过 Qt 队列投递。关闭窗口时先解绑
监听、拒绝未完成请求、关闭全部标签 Controller，再关闭共享 Environment/Profile。
只有当前可见标签的权限、屏幕捕获、下载、证书和外部协议请求可进入宿主确认流程；
后台标签请求立即按安全默认值拒绝，避免确认对话框跨标签串线。后台标签的普通导航、
重定向和标题变化仍继续更新该标签自己的地址、历史和前进/后退状态。

## 7. 日常增强阶段一冻结设计

本节是后续“内置浏览器日常使用增强”的阶段一实现契约。若实现发现 WebView2 Runtime
能力与本节冲突，必须先修正文档和测试，不得用“隐藏即静音”“隐藏即挂起”等旧行为
临时兼容。

### 7.1 状态模型与后端接口

宿主可见性、用户静音、全局静音、网页音频活动和睡眠状态必须独立保存：

- `BrowserTabRecord` 增加 `isUserMuted`、`isPlayingAudio`、`hasActiveMedia`、
  `activeDownloadCount` 和 `isSuspended`。用户静音属于标签状态；网页音频和媒体活动是
  Runtime 上报的瞬时状态，不进入历史或日志。
- `BrowserPage` 单独保存 `isGlobalAudioMuted`，不能把全局静音写回每个标签的
  `isUserMuted`。
- 后端可见性接口冻结为宿主显示语义：现有 `setVisible(bool)` 只控制当前标签 Controller
  是否显示，不再连带调用静音或挂起。标签切换仍由 `activateTab(tabId)` 选择唯一可见
  Controller，但不得改变任何标签的静音状态。
- 后端增加按标签设置用户静音和设置全局网页静音的接口；实现可缓存期望状态，但最终
  生效值必须统一按下式计算，不允许从可见性或当前标签身份继续推导静音：

```text
effectiveMuted(tab) = isGlobalAudioMuted || tab.isUserMuted
```

- 睡眠继续使用独立的按标签命令。阶段一不得从 `activate()`、`deactivate()`、窗口最小化
  或标签切换调用睡眠命令；后续阶段也只能在 7.6 的门禁通过后调用。

新标签默认 `isUserMuted=false`，但创建时仍要叠加当时的全局静音。解除全局静音只恢复
各标签原有用户选择；全局静音期间新建、关闭或切换标签都不得重置其他标签的选择。
若后端应用静音失败，界面不得伪造已生效状态，只记录不含网址的固定错误类别并允许用户
重试。

### 7.2 页面模式切换

从网页切换到本地或直播时，`BrowserPage::deactivate()` 按以下顺序处理：

1. 结束旧标签泄漏到宿主的网页全屏外观，并按 7.5 处理未决敏感请求。
2. 调用可见性接口隐藏 Controller。
3. 保留全部 Controller、导航、用户静音、全局静音和网页活动状态，不调用
   `TrySuspend`，也不重新导航。

切回网页时，`activate()` 只恢复当前 Controller 的可见性、物理像素边界和工具栏状态。
后台标签仍保持隐藏，但继续运行；切换标签同样只交换可见 Controller。MediaHub 只保证
宿主不主动暂停、静音或挂起，网站脚本、DRM、Runtime 节流和自动播放策略仍可能改变
实际播放结果。

### 7.3 单标签静音、全局静音与声音提示

单标签声音按钮只修改目标标签的 `isUserMuted`，不激活标签。全局“全部网页静音”只修改
`isGlobalAudioMuted`。界面上的有效静音图标由两者合成，同时要保留“用户单独静音”和
“因全局静音而无声”的可区分提示。

主窗口不读取 WebView2 或播放器内核对象。`BrowserPage` 只向主窗口发出稳定的“可听网页
标签数量”和值类型状态；主窗口再与本地媒体、直播的播放/静音状态合成统一媒体状态提示。
该提示仅用于定位当前声音来源，不获得跨模块控制权，也不得显示完整网址。

### 7.4 每标签网页音频事件

`BrowserEventListener` 增加按标签的音频活动事件，语义冻结为
`onTabAudioStateChanged(tabId, generation, isPlayingAudio)`：

- 调用线程：WebView2 事件先离开 COM 回调栈，再排队到 GUI 主线程调用。
- `isPlayingAudio` 表示 Runtime 报告该文档正在播放音频，与用户静音、全局静音和标签
  可见性无关；界面上的“正在出声”按
  `isPlayingAudio && !effectiveMuted(tab)` 推导。
- 事件必须携带稳定 `tabId` 和标签代次。标签已关闭、代次不匹配或后端正在关闭时丢弃
  迟到事件，不得更新复用后的标签或触发对话框。
- 状态只在布尔值实际变化时通知。标签就绪后先同步一次当前值；能力不可用时保持安全的
  “未知”能力标记，不能伪造为“未播放”。

### 7.5 后台敏感请求

连续播放不扩大网页权限。权限、屏幕捕获、证书例外、外部协议、下载目标选择和网页全屏
只有在“网页宿主可见且请求标签为当前标签”时才能进入宿主交互：

- 后台标签或宿主位于本地/直播页面时，新请求立即按安全默认值拒绝或取消，不排队到
  用户稍后处理。
- 显示中的确认窗口若因模式或标签切换变为后台，必须关闭窗口并只完成一次拒绝；迟到
  的超时和用户点击不得二次回答。
- 已由用户选择目标并开始的数据下载不是未决敏感请求，可在网页隐藏后继续；新的目标
  选择请求仍须取消。
- 普通导航、重定向、标题更新、音频事件和已经开始的媒体播放不经过敏感请求门禁。

### 7.6 睡眠硬门禁

手动睡眠和自动睡眠共用同一个资格判断。存在以下任一状态时必须拒绝睡眠，不得先静音
再尝试 `TrySuspend`：

```text
isPlayingAudio
|| hasActiveMedia
|| activeDownloadCount > 0
|| hasPendingSensitiveRequest
|| isPinned
```

媒体活动必须来自可靠的 Runtime 能力或后续明确设计的受控信号，不能靠页面标题、网址、
超时或可见性猜测。当前 Runtime 若无法可靠区分静音视频等媒体活动，则该 Runtime 不启用
睡眠功能；自动睡眠仍默认关闭。`TrySuspend` 失败时保持原静音和运行状态，并向界面报告
固定失败类别，不能显示为已睡眠。

### 7.7 后续阶段边界

完整增量仍按六阶段推进：阶段一实现后台连续播放、声音控制和统一媒体状态；阶段二实现
Bing 首页、主动标签、标准快捷键、网页内查找和标签右键菜单；阶段三统一资料窗口主题、
完善历史/收藏、网站权限以及收藏导入导出；阶段四实现关闭标签恢复、重启会话和启动页；
阶段五实现 FavIcon、缩放、标签搜索、分组、固定、安全睡眠和标签崩溃恢复；阶段六实现
多任务下载中心。各阶段不得越过本文件第 1、5、6 节的数据、线程和生命周期边界。

## 8. 日常增强阶段二冻结设计

本节冻结 Bing 默认首页、主动新标签、常用快捷键、网页内查找和标签右键菜单的阶段二
契约。阶段二可以与阶段一普通 Windows 验收并行开发，但阶段提交仍受阶段一 Runtime 和
人工验收门禁约束。实现或自动化通过都不能替代真实网页音画、系统交互和进程退出验收。

### 8.1 首页与首次导航

阶段二固定默认首页为 `https://www.bing.com/`，主页地址的用户配置留到阶段四。当前没有
会话恢复能力，因此首次创建网页页时按以下顺序工作：

1. `BrowserPage` 先建立唯一的主标签模型，再异步初始化 WebView2，不在构造函数中访问
   网络。
2. 主 Controller 第一次成功就绪后，只提交一次 Bing 导航。重复就绪事件、页面隐藏后
   再显示、标签切换、窗口最小化和尺寸变化均不得再次提交首页导航。
3. Runtime 初始化失败时保留失败页，不循环重试或伪造已打开 Bing；用户后续明确重试时
   才能重新初始化。
4. 清除网页数据成功后仍停留在内部 `about:blank`。该流程必须取消待执行的首次首页标记，
   不能刚清除 Profile 就自动访问 Bing；用户下一次点击 `+`、按 `Ctrl+T` 或主页按钮时
   才重新访问首页。

`about:blank` 只允许用于网站新窗口和清除资料等受控内部流程，不作为普通主动新标签的
默认地址。首次 Bing 导航失败时显示当前标签失败状态，但保留存活 Controller 和重试入口。

### 8.2 新标签来源与创建事务

标签栏增加独立 `+` 按钮。新标签入口必须携带来源语义，不能只传一个可能被覆盖的 URL：

| 来源 | 初始导航目标 | 是否切换到新标签 |
| --- | --- | --- |
| `+`、`Ctrl+T`、标签菜单“新建标签” | Bing | 是 |
| 网站 `window.open`、`target=_blank` | 经弹窗策略接受的原请求地址，精确 `about:blank` 也保留 | 是 |
| 历史、收藏的 Ctrl+点击或中键 | 对应记录地址 | 是 |
| 标签菜单“复制标签” | 目标标签当前安全 HTTP(S) 地址；没有安全地址时使用 Bing | 是 |

主动新标签不得复用网站 `NewWindowRequested` 的 request ID；网站新窗口 deferral 仍按第 2
节的单次完成规则收口。所有入口共用一个创建事务：先检查关闭状态、标签上限和地址策略，
再请求后端创建 Controller；只有后端接受创建后才加入标签模型、标签栏并切换。同步创建
失败、达到上限或地址被拒绝时不得增加 `tabId` 可见项、改变当前标签或留下假 Controller。

阶段二默认标签上限固定为 20；5 至 100 的用户配置随阶段四设置界面实现。异步创建已经
被接受、但 Controller 随后初始化失败时保留可关闭的失败标签，并只显示固定错误类别；
不能把请求 URL、Profile 路径或 HRESULT 详情放入用户可复制日志。

### 8.3 关闭与切换语义

`Ctrl+W` 只关闭当前网页标签，不关闭 MediaHub 主窗口。关闭逻辑按稳定 `tabId` 执行：

- 多个标签时关闭目标 Controller；关闭当前标签后优先激活其右侧标签，没有右侧时激活
  左侧标签。关闭后台标签不得切换当前标签。
- 只剩一个标签时不调用 `closeTab`，而是复用存活 Controller：退出网页全屏、拒绝该标签
  未决敏感请求、停止页内查找，递增代次，清空标题、前进后退、错误和网页音频瞬时状态，
  保留全局静音，并把单标签用户静音恢复为默认未静音，然后导航 Bing。
- 最后一标签重置或 Bing 导航失败时仍保留一个真实 Controller 支撑的标签，不关闭主窗口、
  不创建只有 GUI 记录的假标签。清除网页数据仍走第 5 节的 `about:blank` 专用流程。
- 网站自请求关闭、中键关闭、标签关闭按钮和 `Ctrl+W` 复用同一关闭规则；后续阶段加入
  固定标签后，固定标签须先经过轻量确认。

`Ctrl+Tab` 和 `Ctrl+Shift+Tab` 分别按标签栏当前顺序向后、向前环形切换。单标签时不发
后端命令；切换只激活已有 Controller，不导航、不重建、不改变用户静音、全局静音或音频
活动状态。标签拖动后立即使用新的可见顺序。

### 8.4 快捷键统一路由

阶段二的稳定动作枚举至少包含 `NewTab`、`CloseTab`、`NextTab`、`PreviousTab` 和
`FindInPage`，并保留已有地址栏、前进、后退、刷新和退出全屏动作。Qt 控件焦点与原生
WebView2 子窗口焦点必须产生相同动作：

- Qt 控件路径使用窗口级 `QShortcut`，仅在网页页可见并处于当前主窗口时生效。
- WebView2 `AcceleratorKeyPressed` 回调只读取虚拟键和修饰键、把匹配按键标记为已处理，
  然后携带稳定 `tabId`、代次和动作排队到 GUI 主线程。回调中不得关闭 Controller、切换
  标签、操作 Qt 控件或等待浏览器线程。
- GUI 收到动作后再次验证标签仍存在、代次匹配、目标仍是当前活动标签且后端未关闭；
  关闭或切换期间到达的旧快捷键事件直接丢弃。
- `Ctrl+Shift+T` 在阶段四实现；阶段二不得把它误识别为 `Ctrl+T`。网页正文自己的普通
  `Tab`、`Shift+Tab`、`Ctrl+W` 以外组合和文本编辑快捷键不得被宿主吞掉。

`Esc` 的优先级固定为：先关闭页内查找条，再退出网页全屏，最后交回网页默认处理。

### 8.5 网页内查找

`Ctrl+F` 打开位于工具栏下方、网页内容上方的当前标签查找条；查找条包含输入框、
“上一个”“下一个”、`当前序号/总数` 和关闭按钮。打开后聚焦并全选现有查询；Enter 查找
下一个，Shift+Enter 查找上一个，`Esc` 关闭。

后端按标签提供开始查找、上一个、下一个和停止查找命令，并把结果以
`tabId + generation + activeMatchIndex + matchCount` 的稳定值事件排队回 GUI 主线程。
查询只绑定打开查找条时的当前标签：切换或关闭标签、开始新的顶层导航、清除网页资料和
关闭应用都必须停止旧查找并清空结果；迟到结果按标签和代次丢弃。空查询等价于停止查找。

优先使用当前 SDK 的 WebView2 Find API。若 Runtime 不支持对应接口或调用失败，查找条
显示固定的“不支持页内查找”状态，网页继续可用；不得注入 JavaScript 搜索网页正文，
也不得因查找失败重载或修改页面。

查找词只存在于当前进程的查找输入框和 WebView2 查找对象，不写入历史、收藏、QSettings、
会话、剪贴板、日志或测试文档。关闭查找条时清空宿主保存的查询文本。

### 8.6 标签右键菜单

标签栏右键菜单在弹出时保存目标标签的稳定 `tabId`，不以可能变化的行号延迟执行。右键
本身不激活标签。阶段二提供：新建标签、复制标签、重新加载、复制地址、复制标题、静音或
取消静音、关闭、关闭其他标签和关闭右侧标签。

- 复制标签、重新加载、复制地址、复制标题和静音都作用于右键目标，不默认改成当前标签。
- 重新加载后台标签时先激活目标标签，再提交刷新，避免调用只面向当前 Controller 的旧
  接口；复制地址或标题是用户明确触发的剪贴板操作，但不得同时写日志。
- 批量关闭按点击菜单时的标签顺序计算，并逐项使用稳定 ID；已关闭或代次失效的目标跳过。
  阶段五加入固定、媒体活动和每标签下载状态后，这些受保护标签默认不参与批量关闭。
- 菜单打开后目标已关闭时，所有后续动作安全无操作。空地址禁用复制地址，空标题禁用复制
  标题；创建失败和复制失败不改变标签模型。
- “移动到分组”在阶段五分组模型完成后再加入，不显示无效占位项。

### 8.7 失败、线程和隐私边界

阶段二所有标签模型、菜单、剪贴板、查找条和 Qt 控件操作只在 GUI 主线程执行。WebView2
快捷键、查找结果、Controller 就绪和失败回调必须先离开 COM 回调栈再排队；任何回调都
不得同步等待 GUI 或销毁正在回调的对象。

错误提示和生产日志只使用固定动作与错误类别，例如“标签创建失败”“查找能力不可用”。
不得记录完整 URL、查询参数、片段、页面标题、查找词、剪贴板内容、Profile 路径、Cookie、
Token 或密码。自动化使用 loopback 或固定非敏感地址，测试失败输出不得打印实际私人网址。
阶段二不改变密码、Cookie、自动填充和 Profile 的既有边界，也不增加脚本注入或跨标签
读取网页内容的能力。
