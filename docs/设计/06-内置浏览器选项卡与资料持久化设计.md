# MediaHub 内置浏览器选项卡与资料持久化设计

> 状态：已确认，分三阶段实施。
>
> 范围：MediaHub 内置网页展示模块。网页功能与本地媒体、直播播放链路相互独立。

## 1. 目标与边界

本增量只扩展内置浏览器，不改变 `mediahub_core`、libVLC 播放器、播放列表或直播
清单模型。主窗口只负责展示模式切换；网页模块内部拥有自己的选项卡、导航状态、
历史记录和收藏夹。

WebView2 使用 MediaHub 专用持久 Profile。所有选项卡共享该 Profile，因此 Cookie、
LocalStorage、IndexedDB、Service Worker、缓存、已保存密码和自动填充资料由 WebView2
自己保存并跨重启恢复。MediaHub 不读取、解析、记录或写入 QSettings 的敏感资料；Edge
个人 Profile 不复用、不修改。

## 2. 组件关系

```text
MainWindow
└── BrowserPage (网页展示模块)
    ├── BrowserTabController (GUI 主线程，标签模型与当前标签)
    │   ├── BrowserTab 0..N (地址、标题、前进/后退状态、WebView 控制器)
    │   └── BrowserHistory / BrowserFavorites (QSettingsAppStateStore)
    └── BrowserBackend (抽象)
        └── WebView2BrowserBackend (共享 Environment/Profile，按标签创建 Controller)
```

`BrowserBackend` 的公开接口保持 Qt 值类型和稳定事件，不暴露 COM、HWND 或 WebView2
接口。每个标签的 WebView2 Controller 都绑定同一个 Environment/Profile，但有独立的
导航栈和可见边界。所有 WebView2 回调先带标签代次，再由 Controller 投递到 GUI 主线程。

## 3. 选项卡语义

- 页面顶部显示选项卡栏；每项显示页面标题，空白页显示“新标签页”。
- 地址栏在加载完成后仍可编辑；点击或 `Ctrl+L` 聚焦并全选当前地址。
- 地址栏提交复用当前标签，不创建新窗口。
- `window.open`、链接 target=_blank 和“在新窗口打开”统一请求新标签；弹窗与主页面
  共享 Profile，不再创建独立浏览器资料。
- 每个标签保存 WebView、可见地址、标题、`canGoBack`、`canGoForward` 和当前导航
  代次。切换标签只改变可见 Controller，不销毁网页会话。
- 关闭标签只关闭该标签的 Controller；最后一个标签关闭后立即创建空白标签。
- 历史/收藏夹默认当前标签打开；Ctrl+点击或鼠标中键新建标签。

## 4. 历史记录与收藏夹

历史项字段为网址、页面标题、访问时间（UTC 毫秒）。成功的顶层导航完成后写入历史，
按规范化网址去重并移到最前，数量限制为 500 条。收藏项字段为网址、页面标题和备注，
按规范化网址去重，数量限制为 5000 条。两者均由 `QSettingsAppStateStore` 保存到
MediaHub 自己的配置组，跨进程和跨重启恢复。

QSettings 永远不写入密码、Cookie、Token、表单值、Profile 路径或网页正文；日志也不
记录这些内容。清除网页数据只调用 WebView2 Profile API，不删除 MediaHub 自己的历史
和收藏夹。

## 5. 清除网页数据

确认后对共享 Profile 调用全量 `COREWEBVIEW2_BROWSING_DATA_KINDS_ALL_PROFILE`，明确
覆盖 Cookie、LocalStorage、IndexedDB、缓存、Service Worker、下载历史、浏览历史、
已保存密码和通用自动填充。清除完成后所有标签导航到空白页并保留一个空白标签；Edge
Profile 不受影响。若当前 Runtime 不支持某个 Profile API，显示失败，不直接删除被占用
的资料目录。

## 6. 线程与生命周期

标签模型、QSettings、Qt 控件和后端命令只在 GUI 主线程操作。WebView2 事件回调不得操作
Qt 控件或等待浏览器线程；回调仅构造稳定值事件并通过 Qt 队列投递。关闭窗口时先解绑
监听、拒绝未完成请求、关闭全部标签 Controller，再关闭共享 Environment/Profile。
