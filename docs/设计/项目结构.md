# MediaHub 项目结构

> 状态：阶段 5 已建立正式 GUI、播放展示逻辑、线程桥接和 Qt 自动化测试。
>
> 分类：设计。

## 1. 设计目标

- 核心业务不依赖 Qt、libVLC 或任何具体播放内核。
- 每个 CMake 目标职责单一，依赖方向清晰。
- 公共接口与私有实现分离。
- 单元测试和集成测试能够独立运行。
- 后续替换播放内核时不重写界面和核心逻辑。

## 3. 目录职责

### `include/mediahub/core`

- 存放 `mediahub_core` 对外公开的头文件。
- 定义 `PlayerEngine` 抽象接口和事件监听接口。
- 定义媒体项、播放状态、播放位置、失败信息等值类型。
- 定义播放列表和播放控制逻辑。
- **不得包含 Qt 头文件、libVLC 头文件或 Windows 头文件。**

这是全项目最严格的一条约束。核心层的编译不应该需要 Qt 和 libVLC 存在。

### `src/core`

- 存放核心模块实现与不公开的辅助头文件。
- 负责状态机转换规则、播放列表规则、失败分类等纯逻辑。
- 不负责窗口控件、内核调用和线程调度。

### `include/mediahub/engine_vlc` 和 `src/engine_vlc`

- 存放基于 libVLC 的 `PlayerEngine` 实现。
- 负责 libVLC 实例、媒体对象、播放器对象的 RAII 包装。
- 负责把 libVLC 事件映射为核心层定义的抽象事件。
- 公共头文件只暴露一个工厂函数或一个类声明，不暴露任何 libVLC 类型。
- 不依赖 Qt。

libVLC 的头文件只允许出现在 `src/engine_vlc/` 的实现文件中，不能出现在
`include/` 下的任何位置。

### `include/mediahub/logging` 和 `src/logging`

- 存放标准 C++20 结构化日志记录、格式化和线程安全终端输出。
- 不依赖 Qt 和 libVLC，不记录媒体文件的完整路径，不负责持久化日志文件。
- 核心层不反向依赖日志设施；应用层负责建立日志记录。
- 阶段 9 才引入，之前不创建这两个目录。

### `apps/gui`

- 存放 Qt GUI 入口、窗口、展示逻辑和 Qt 专属适配代码。
- `main.cpp` 只负责创建 `QApplication`、构造具体内核、组装并显示主窗口。
- **`main.cpp` 是全项目唯一知道 `VlcPlayerEngine` 存在的地方。**
- `PlayerPresenter` 是控件状态的唯一来源，界面不各自维护状态。
- `EngineEventBridge` 负责把内核回调线程的事件安全投递到主线程。
- `VideoOutputWidget` 提供原生窗口句柄，并处理尺寸变化。
- 只读视图模型不复制业务对象，只持有对播放列表的引用或轻量索引。

### `tests/unit`

- 测试单个类或函数。
- 使用假内核，不依赖 libVLC、Qt 和音频设备。
- 不启动完整应用。

### `tests/integration`

- 测试“打开媒体 → 播放 → 定位 → 停止 → 释放”的完整内核链路。
- 使用真实 `VlcPlayerEngine`，但配置为哑音频和哑视频输出。
- 测试媒体在运行时生成，不依赖个人路径和有版权素材。

### `tests/gui`

- 测试主窗口、展示逻辑、事件桥接和视图模型。
- 使用假内核，避免依赖真实播放能力。
- 不使用整窗口像素截图比较。

### `Third_Party`

- 集中保存固定版本的第三方源码及其许可证。
- 当前计划只放 GoogleTest。
- CMake 从本地目录接入，避免不同构建目录重复下载。
- 不直接修改上游源码；新增或升级依赖必须单独审查并使用独立提交。
- 第三方库只链接到实际使用它的最小目标。

**libVLC 不放入 `Third_Party/`**。它是开发机上的外部 SDK，体积过大且包含数百个
插件文件，通过 CMake 变量指向本地解压目录。理由见
[播放内核选型.md](播放内核选型.md) 第 5.1 节。

## 4. CMake 目标

| 目标 | 类型 | 职责 |
|---|---|---|
| `mediahub_core` | 静态库 | 抽象接口、值类型、状态机和播放列表 |
| `mediahub_engine_vlc` | 静态库 | libVLC 内核实现 |
| `mediahub_gui_support` | 静态库 | 主窗口、展示逻辑、事件桥接和视图模型 |
| `mediahub_gui` | GUI 可执行程序 | 组装内核与主窗口，输出 `MediaHub.exe` |
| `mediahub_tests` | 测试程序 | 不依赖 Qt/libVLC 的核心单元测试 |
| `mediahub_vlc_tests` | 测试程序 | 使用哑输出和运行时媒体的 libVLC 集成测试 |
| `mediahub_gui_tests` | 测试程序 | GUI 展示逻辑与视图模型测试 |
| `mediahub_logging` | 静态库 | 结构化日志（阶段 9 引入） |

### 4.1 构建选项

| 选项 | 默认 | 作用 |
|---|---|---|
| `MEDIAHUB_VLC_ROOT` | 空 | 指向本机 libVLC SDK 解压目录 |
| `MEDIAHUB_BUILD_TESTS` | `ON` | 是否构建测试目标 |
| `MEDIAHUB_CORE_ONLY` | `OFF` | 只构建不依赖 Qt/libVLC 的核心库与单元测试 |

完整程序配置中，`MEDIAHUB_VLC_ROOT` 为空时配置失败并给出清晰的错误提示，不静默
降级。本机路径通过 CMake 命令行、Qt Creator 构建配置或环境变量提供，不写进项目
CMake 文件。`MEDIAHUB_CORE_ONLY=ON` 时不检查 libVLC，也不查找 Qt。

Qt SDK 路径通过 `CMAKE_PREFIX_PATH` 提供，处理方式与 libVLC 一致。

### 4.2 部署

Windows GUI 链接完成后，CMake 使用同一 Qt 套件中的 `windeployqt`，把 Qt 运行库
和平台插件部署到可执行文件目录，并把 libVLC 的两个 DLL 与插件目录一并复制。

部署命令显式优先使用目标 Qt 套件的 `bin` 目录，避免机器上其他 Qt 或 Python
发行版污染依赖解析。构建产物由 `.gitignore` 排除。

具体步骤见 [依赖接入与部署说明.md](../交付/依赖接入与部署说明.md)。

## 5. 依赖方向

```text
mediahub_gui ──┬──> mediahub_gui_support ──> mediahub_core
               │                                  ▲
               └──> mediahub_engine_vlc ──────────┘
                            │
                            └──> libVLC

mediahub_gui_support ──> Qt5::Widgets
mediahub_gui_tests   ──> mediahub_gui_support ──> Qt5::Test
mediahub_tests       ──> mediahub_core
mediahub_vlc_tests   ──> mediahub_engine_vlc
```

硬性规则：

- `mediahub_core` 不得依赖任何其他项目目标、Qt 或 libVLC。
- `mediahub_engine_vlc` 不得依赖 Qt。
- `mediahub_gui_support` 不得依赖 libVLC，也不得链接它。
- 只有 `mediahub_gui` 同时链接界面支持库和具体内核。
- 第三方库必须由使用它的最小目标链接，避免污染整个项目。

**验证手段**：如果有人在窗口代码里直接调用了 libVLC，`mediahub_gui_support`
会因为找不到头文件和符号而编译或链接失败。依赖规则由构建系统强制，不靠自觉。

## 6. 文件放置规则

- 一个主要类或一组紧密相关的小类型对应一对 `.h/.cpp`。
- 公共头文件路径与命名空间保持一致。
- 私有辅助类型不放入 `include/`。
- 测试文件使用 `<被测模块>_test.cpp` 命名。
- 平台相关实现必须隔离，不能在业务代码中散落大量条件编译。
- Qt Designer 的 `.ui` 文件与对应窗口类放在同一目录。
