# MediaHub v0.6 WebView2 集成设计

> 状态：设计已建立，尚未实现。
>
> 分类：设计。

## 1. 设计目标

本设计把 WebView2 作为独立网页内核接入 MediaHub，重点保证以下边界：

- 网页浏览不进入 `mediahub_core`，不改变 `PlayerEngine` 或 libVLC 播放协议。
- `mediahub_gui_support` 不包含 WebView2 头文件，不直接链接 WebView2 Loader。
- GUI 自动化可以注入假浏览器，不要求真实 Edge Runtime、网络或用户账号。
- WebView2 的所有创建、导航、事件和释放都发生在 GUI 主线程的 STA 中。
- 用户资料由 WebView2 管理，MediaHub 不接触账号密码、Cookie 或令牌内容。

## 2. 目标依赖关系

```text
mediahub_gui ───────────────┬──> mediahub_gui_support ──> mediahub_core
                            │            │
                            │            └──> BrowserBackend 抽象
                            │
                            ├──> mediahub_browser_webview2 ──> WebView2 SDK
                            │                 │
                            │                 └──> Edge WebView2 Runtime
                            │
                            └──> mediahub_engine_vlc ──> libVLC

mediahub_gui_tests ──> mediahub_gui_support + FakeBrowserBackend
mediahub_tests     ──> mediahub_core
```

`apps/gui/main.cpp` 继续作为组合根，构造真实 `VlcPlayerEngine` 和真实 WebView2 后端后
注入主窗口。测试程序只构造假内核与假浏览器。这样 WebView2 和 libVLC 都不会进入
GUI 支持库，也不会破坏现有三条架构约束。

## 3. 计划文件与 CMake 目标

### 3.1 GUI 支持层

| 文件 | 职责 |
|---|---|
| `apps/gui/browser_backend.h` | 定义导航、资料清除、全屏和生命周期抽象 |
| `apps/gui/browser_event_listener.h` | 定义只含稳定值的浏览器事件接口 |
| `apps/gui/browser_page.h/.cpp` | 地址工具栏、错误页、原生子窗口占位和状态渲染 |
| `apps/gui/main_window.h/.cpp` | 增加网页模式、中央栈切换和响应式布局 |
| `apps/gui/player_presenter.h/.cpp` | 协调进入网页时暂停原生媒体，不保存网页凭据 |

浏览器抽象允许依赖 Qt 值类型，因为它属于 GUI 边界；不得包含 WebView2、COM 或 Windows
SDK 类型。所有输入和事件方法必须注明调用线程为 GUI 主线程。

### 3.2 WebView2 适配层

| 文件 | 职责 |
|---|---|
| `include/mediahub/browser_webview2/webview2_browser_backend.h` | PImpl 公共入口，不暴露 COM 类型 |
| `src/browser_webview2/webview2_browser_backend.cpp` | 环境、Controller、WebView 和事件实现 |
| `src/browser_webview2/webview2_handles.h` | COM 指针和事件令牌的 RAII 辅助类型 |
| `src/browser_webview2/webview2_url_policy.cpp` | 顶层 URL 与外部协议策略 |

新建静态目标 `mediahub_browser_webview2`，只由 `mediahub_gui` 链接。SDK 头文件、Loader
和 Windows 库不传播到 `mediahub_gui_support`。非 Windows 配置明确报告 v0.6 浏览器
后端不受支持，不静默替换成 Qt WebEngine。

### 3.3 测试支持

| 文件 | 职责 |
|---|---|
| `tests/gui/fake_browser_backend.h` | 同步记录命令并精确触发浏览器事件 |
| `tests/gui/browser_page_test.cpp` | 页面控件、状态、URL 策略和模式切换测试 |
| `tests/integration/webview2_browser_test.cpp` | 可选真实 Runtime、本机 HTTP 与临时资料测试 |

真实 WebView2 集成测试只访问 `127.0.0.1` 受控服务，用户数据目录由临时目录提供；不
读取 Edge 个人资料，不登录公共网站，也不依赖真实账号。

## 4. 浏览器接口

`BrowserBackend` 计划提供以下最小语义，不把 WebView2 接口逐项照搬到 GUI：

```cpp
class BrowserBackend {
 public:
  virtual ~BrowserBackend() = default;
  virtual void setEventListener(BrowserEventListener* listener) = 0;
  virtual void initialize(void* parentWindowHandle,
                          const QString& userDataDirectory) = 0;
  virtual void navigate(const QString& normalizedUrl) = 0;
  virtual void goBack() = 0;
  virtual void goForward() = 0;
  virtual void reloadOrStop() = 0;
  virtual void setVisible(bool isVisible) = 0;
  virtual void clearBrowsingData() = 0;
  virtual void answerPermission(std::uint64_t requestId,
                                BrowserPermissionDecision decision) = 0;
  virtual void chooseDownloadPath(std::uint64_t requestId,
                                  const QString& destination) = 0;
  virtual void resize(const QSize& pixelSize) = 0;
  virtual void shutdown() noexcept = 0;
};
```

正式接口实现时按代码规范使用 4 空格，并为每个涉及线程的方法写明“调用线程：GUI
主线程”。这里只记录职责，不把此草图视为已经冻结的 ABI。

事件接口只传递以下稳定信息：

- 初始化成功或稳定错误类别。
- 导航开始、完成、失败和是否可后退/前进。
- 当前可展示 URL、页面标题和载入状态。
- 网页全屏进入或退出。
- 新窗口、权限、下载和关闭请求。
- 网页资料清除成功或失败。

事件中不得传递 Cookie、请求头、POST 数据、网页正文、表单内容或完整诊断转储。

## 5. 页面与模式状态

### 5.1 展示结构

现有中央 `mediaDisplayStack_` 包含视频输出和歌词。v0.6 在外层增加展示模式栈：

```text
主窗口内容
├── 原生播放页
│   ├── 视频/歌词栈
│   ├── 本地或直播列表
│   └── libVLC 控制行
└── 网页页
    ├── 地址与导航工具栏
    ├── WebView2 原生子窗口占位
    └── 初始化/错误覆盖层
```

“本地列表”“直播列表”“网页”成为三个展示入口。前两个继续复用现有播放页和列表
模型；网页入口不创建第三个 `core::Playlist`，也不进入播放模式枚举。

### 5.2 状态机

浏览器页使用独立状态，不复用 `core::PlaybackState`：

```text
Unavailable -> Initializing -> Ready -> Navigating -> Ready
                         \-> Failed
Ready/Navigating -> ClearingData -> Ready/Failed
任意活动状态 -> ShuttingDown -> Unavailable
```

状态切换只在 GUI 主线程完成。初始化、导航和清除数据都携带单调递增的请求代次；窗口
关闭、后端替换或新请求开始后，旧代次的迟到回调被丢弃。

### 5.3 与原生播放的协调

1. 从本地或直播进入网页时，仅当状态为 Opening、Buffering 或 Playing 才请求暂停。
2. 暂停请求走现有 Presenter 和状态机，不从浏览器页直接调用播放内核。
3. 离开网页时调用 WebView2 静音和挂起能力，避免隐藏页面继续出声或消耗解码资源。
4. 返回网页时恢复页面环境，但不注入脚本、不自动触发网页播放按钮。
5. 返回原生播放页时不自动继续 libVLC，用户仍通过现有播放按钮决定是否恢复。

## 6. WebView2 初始化与原生窗口

1. `main.cpp` 在 GUI 主线程建立 STA 生命周期；若 COM 已以不兼容模式初始化，返回
   稳定错误并保持主窗口可用。
2. `BrowserPage` 的占位控件取得稳定原生 `HWND` 后，异步创建
   `CoreWebView2Environment` 和 Controller。
3. Environment 指定 MediaHub 专用用户数据目录；主页面和登录弹窗共享同一个
   Environment 和 Profile。
4. Controller 的边界始终跟随占位控件客户区；resize 和 DPI 变化只提交最新尺寸。
5. 初始化期间允许切换回本地/直播页，但不重复创建环境；完成事件通过代次判断是否
   仍然有效。
6. WebView2 Runtime 缺失、资料目录不可用、Controller 创建失败分别映射为稳定中文
   错误，不把本地完整路径或 COM 消息直接展示到日志。

不使用阻塞等待把异步 WebView2 API 伪装成同步接口。GUI 主线程不得等待 Controller、
网页加载、资料清除或子进程退出。

## 7. 用户资料与持久登录

### 7.1 目录和所有权

用户数据目录通过 `QStandardPaths::AppLocalDataLocation` 推导，并使用版本化子目录，
例如 `WebView2/Profile-v1`。代码和 CMake 不写入个人绝对路径，结构化日志也不记录
解析后的完整目录。

WebView2 独占管理目录中的 Cookie、缓存、LocalStorage、IndexedDB、Service Worker
和网络状态。MediaHub 不直接读取、枚举、复制或编辑这些文件。

### 7.2 默认 Profile 设置

- 使用持久而非 InPrivate Profile。
- 启用 JavaScript、Cookie、DOM 存储和网站正常上下文菜单。
- 关闭密码自动保存，不提供 MediaHub 密码管理器。
- Release 默认关闭开发者工具和远程调试入口。
- 不注册 Host Object，不注入初始化脚本，不建立网页到本地的消息桥。

### 7.3 清除网页数据

“清除网页数据”操作按以下顺序执行：

1. 自绘确认窗口说明会退出全部内置网页账号，但不影响 Edge。
2. 暂停新的导航和弹窗创建，进入 `ClearingData`。
3. 调用 WebView2 Profile Browsing Data API 清除全部网站数据。
4. Profile 和会话证书动作清除成功后，由后端直接请求内部 `about:blank`；只有匹配的
   `navigationId` 成功完成、确认旧 document 和连接已被替换后，才通知 GUI 恢复 Ready。
   内部空白导航不进入普通地址、标题或导航失败事件；任一步失败都归类为
   `ClearDataFailed`。
5. 关闭期间若仍在清理，只取消界面等待并按正常关闭顺序释放，不递归删除目录。

## 8. URL 与导航策略

### 8.1 用户输入

1. 去除首尾空白，空输入不导航。
2. 没有协议时补 `https://`，不自动转为搜索关键词。
3. HTTP/HTTPS 要求非空主机和合法端口；本地路径必须由用户输入或文件选择器产生，
   规范化为只读 `file:` URL 后再次确认。
4. 用户可在地址栏看到当前完整地址，但该地址不写入结构化日志或 MediaHub 历史。

### 8.2 页面导航

- 主框架 HTTP/HTTPS 跳转允许；顶层 `about:blank` 仅供内部初始化。
- 用户明确选择或确认的 `file:` 允许只读浏览；网页不能在后台自行扩大到其他本地文件。
- 地址栏顶层 `javascript:` 和 `data:` 取消，`edge:`、`devtools:` 等 WebView2 不支持
  的内部页面显示说明；网站自身 JavaScript、Data URL 子资源和 `blob:` 不受影响。
- 网页内部 iframe、脚本、媒体子资源和 `blob:` 由 Edge 正常处理，不尝试自行解析。
- `mailto:`、`tel:`、`magnet:` 等外部协议分别显示规范化请求来源和完整目标，说明将由
  Windows 默认应用处理；MediaHub 不伪装识别具体应用，用户确认后才交给 Windows。
- 文件上传使用 WebView2/Windows 文件选择器，网页只能取得用户当次明确选择的文件。

日志最多记录规范化的来源摘要或不可逆标识；带查询、片段、用户信息的完整 URL 永不
进入终端日志。错误 UI 可以显示用户当前看得见的地址，但不附带 Cookie 或请求头。

### 8.3 证书错误

WebView2 报告服务器证书错误时暂停导航并显示站点主机、错误类型和风险说明。用户可以
返回安全页面，也可以仅为当前会话继续：

- 不提供命令行级“忽略所有证书错误”。
- 临时例外只匹配当前来源和证书错误，关闭 MediaHub 时清除。
- 证书、Cookie、请求头和完整 URL 不进入结构化日志。
- 网站自身不允许绕过的错误继续遵循 WebView2/Windows 限制。

## 9. 登录弹窗、权限和下载

### 9.1 登录弹窗

`NewWindowRequested` 不简单改写为主页面导航，因为 OAuth/SSO 可能依赖 opener 关系。
实现创建有限数量的受控子窗口，并把共享 Profile 的新 WebView 指定给请求：

- 最多同时存在 3 个子窗口，超过上限拒绝并提示。
- 子窗口只有网页内容和最小标题栏，不提供第三个独立 Profile。
- 主窗口关闭时先阻止新弹窗，再关闭现有弹窗和 Controller。
- 弹窗关闭不清除资料，不影响主页面和 Edge。

### 9.2 权限

摄像头、麦克风、地理位置、通知和剪贴板读取都通过标准权限事件处理；每次请求先显示
真实来源和权限类型，由用户选择“允许一次”“对本站记住”或“拒绝”。屏幕捕获不在
`COREWEBVIEW2_PERMISSION_KIND` 中，必须通过 `ICoreWebView2_27` 的主 WebView
`ScreenCaptureStarting` 独立事件处理，只提供“仅本次允许”和“拒绝”：

- 用户未响应、来源无效、窗口正在关闭或弹窗超过上限时拒绝。
- “对本站记住”只写入 MediaHub WebView2 Profile，不影响 Edge。
- WebView2 没有屏幕捕获的 `SavesInProfile` 语义；对话框禁用记住按钮，后端收到记住
  决定也按拒绝处理，不把它降级为一次允许。
- 屏幕捕获来源只从 `OriginalSourceFrameInfo::get_Source` 读取并规范化为 origin；不注册
  frame 级重复事件。接口查询或主事件注册失败会阻止浏览器进入 Ready。
- 设置页可以查看和撤销已记住权限；“清除网页数据”同时清除权限决定。
- 网页视频全屏不是设备权限，按第 10 节处理。
- 不提供忽略来源的全局“所有网站始终允许”。

### 9.3 下载与上传

v0.6 支持网站正常发起的基础下载和文件上传：

1. 下载开始前显示建议文件名、来源、大小（若已知）和 Windows 保存窗口。
2. 用户取消保存窗口时进入 Cancelling，但在 WebView2 报告 Cancelled 前仍占用唯一下载
   槽位；同步 Cancel 失败显示“取消失败，可重试”，不伪装为终态。
3. 目标已存在时必须再次确认或选择新名称，不静默覆盖、修改、移动或删除已有文件。
4. 下载由 WebView2 写入用户选择的目标，MediaHub 不扫描文件内容，也不把下载自动
   加入本地播放列表。
5. 上传只使用 WebView2/Windows 文件选择器；网页只能读取用户当次选中的文件，不
   允许宿主代码替网页自动选择路径。
6. v0.6 不提供批量下载中心、断点续传、自动分类或后台无提示下载。
7. GUI 和后端都会静态校验父目录、目标不存在与 Windows 文件名；由于 WebView2 直接写入
   最终路径，检查与 Runtime 创建文件之间不具备原子性。本地自用威胁模型接受这一
   TOCTOU 残余，不声称能抵御并发创建同名文件或目录联接替换。

权限、外部协议、证书和下载事件取得 deferral 后必须 exact-once 完成。下载在事件订阅、
活动任务存储或第二次静态路径校验失败时，统一设置 Cancel、取消 operation、撤销已绑定
token 并 Complete；不得只取消 operation 后遗留 WebView2 deferral。DownloadStarting 的
Cancel、Handled、operation 和 deferral 获取彼此独立执行，保留首个 HRESULT 但不允许它
短路后续安全动作；证书和外部协议也遵循“先写安全决定、仍尽力取得并完成 deferral”。
活动下载始终先读取 State；终态不得因字节或总量读取失败而泄漏 operation 和事件 token。

## 10. 网页媒体与全屏

1. 网页视频、直播、音频、MSE 和 EME 完全由 WebView2 处理。
2. 不添加关闭站点隔离、全局忽略证书、强制自动播放或绕过 DRM 的命令行参数。
3. `ContainsFullScreenElementChanged` 进入时隐藏 MediaHub 标题说明、侧栏和网页工具栏，
   只保留网页内容；退出时恢复先前布局。
4. `Esc` 优先退出网页全屏，不触发现有 libVLC 全屏或播放快捷键。
5. 网页全屏窗口仍由主窗口管理，不创建不受控的独立 Edge 窗口。
6. 网站禁止 WebView、DRM 不可用或编解码失败时，只呈现网站结果或稳定兼容性说明。

## 11. 线程与关闭顺序

### 11.1 线程规则

- WebView2 后端的公共方法调用线程：GUI 主线程。
- WebView2 回调线程：创建 Environment 的 GUI STA；回调中不调用会等待子进程的接口。
- 后端事件同步交给 `BrowserPage` 时仍检查 QObject 生命周期和请求代次。
- 文件资料由 WebView2 子进程管理，MediaHub 不另建线程读取 Profile 文件。

### 11.2 关闭顺序

```text
1. 标记 ShuttingDown，递增请求代次并禁止新导航、弹窗和权限请求
2. 清空 BrowserEventListener，避免后端继续访问 Qt 控件
3. 退出网页全屏，关闭全部登录子窗口
4. 关闭主 Controller 和 WebView，撤销全部事件令牌
5. 释放 Environment、COM 智能指针和原生占位窗口关联
6. 结束 STA 生命周期，再继续主窗口和 libVLC 的既有关闭流程
```

关闭过程不得固定 `sleep`，不得杀死系统 Edge 或其他应用的 WebView2 进程。测试使用
有界条件确认属于本次 MediaHub 会话的 Controller 已释放。

## 12. 错误与日志

计划稳定错误类别：

| 类别 | 用户提示方向 |
|---|---|
| `RuntimeUnavailable` | 安装或修复 Microsoft Edge WebView2 Runtime |
| `InitializationFailed` | 网页组件初始化失败，可重试或继续使用播放器 |
| `ProfileUnavailable` | 无法建立本机网页资料目录，未启动网页组件 |
| `InvalidAddress` | 输入完整、合法的 HTTP/HTTPS 网站地址 |
| `NavigationFailed` | 页面打开失败，检查网络或网站状态 |
| `BlockedScheme` | 地址栏命令不安全，或 WebView2 不支持该内部地址 |
| `ExternalProtocolFailed` | 用户确认后仍无法打开目标应用 |
| `CertificateRejected` | 用户返回安全页面，或 WebView2 不允许继续 |
| `PermissionDenied` | 用户拒绝、请求超时或来源无效 |
| `DownloadFailed` | 下载取消、目标不可写或 WebView2 报告失败 |
| `ClearDataFailed` | 网页数据未清除，可关闭页面后重试 |

日志字段不包含完整 URL、网页标题、Profile 路径、COM 诊断正文或表单数据。需要定位
问题时只记录稳定类别、HRESULT 数值、请求代次和生命周期阶段。

## 13. 构建与部署

1. SDK 固定在 `Third_Party/webview2/`，包含上游许可证和版本记录。
2. x64 构建只选择 x64 WebView2 Loader；不得误带 x86/ARM64 产物。
3. 优先使用官方静态 Loader 方案减少额外 DLL；若固定 SDK 不支持，则显式部署匹配的
   `WebView2Loader.dll` 并纳入发布检查。
4. Evergreen Runtime 不复制到仓库和普通发布目录；启动时通过官方 API 检测版本。
5. 隔离 Release 目录必须包含 WebView2 SDK 许可证，并确认没有测试程序、Profile、
   Cookie、缓存或开发机个人数据。
6. `MEDIAHUB_CORE_ONLY=ON` 时不查找 WebView2；关闭测试的完整 GUI 构建仍需要 SDK。

## 14. 自动化边界

可以自动化：

- 页面模式、工具栏、快捷键、URL 规则和按钮启用状态。
- 假后端命令、迟到事件、初始化失败、权限决定、下载、清除数据和关闭顺序。
- 本机受控 HTTP 页面的导航、Cookie 持久化、资料清除和基本视频元素事件。
- 依赖隔离、构建矩阵、发布目录和敏感日志扫描。

必须人工验收：

- 用户真实账号登录及网站自身二次验证。
- 公共网站直播/视频的真实画面、声音、编解码器和 DRM 行为。
- OAuth 登录弹窗、网页全屏、显卡加速和真实 Windows DPI 观感。
- 网站明确拒绝嵌入式 WebView 时的兼容性结论。

详细用例和完成门槛见
[`28-v0.6-内置网页浏览器测试.md`](../测试/28-v0.6-内置网页浏览器测试.md)。
