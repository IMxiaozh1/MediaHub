# MediaHub 文档导航

> 状态：v0.1 至 v0.6 均已按本地自用版本完成；v0.6 最终发布目录、自动化矩阵、
> 真实 WebView2 Runtime 及规划 12/13 的人工门禁已于 2026-08-15 收口。
> 本目录记录产品边界、工程设计、测试策略、学习材料和交付标准。

## 命名与排序

- `docs/` 根目录及每个分类目录分别使用独立的两位序号，从 `01` 开始排列。
- 文件名统一采用 `NN-主题.md`；版本文档采用 `NN-v0.x-主题.md`。
- 阶段号和增量号统一补为两位，例如 `阶段01`、`直播增量06-07`。
- 序号表示推荐阅读和展示顺序；新增文档使用所在目录的下一可用序号。

## 状态口径

- 当前项目状态以 [02-开发交接.md](02-开发交接.md) 最后一个日期段和对应版本交付说明为准。
- 规划、实施计划和增量测试保留当时的失败、待验收与停止门禁，作为过程证据；这些历史
  文字不自动代表当前版本仍在开发。
- 未逐项补证的真实账号、公共网站、DRM、外部协议和跨机器场景继续作为兼容性或公开
  发布限制保留，不因本地自用版本完成而改写为通过。

## 当前已确定

- 项目使用 C++20 和 Qt 5.14.2 Widgets。
- 播放内核采用 libVLC，藏在 `PlayerEngine` 纯虚接口之后。
- 播放输入支持本地音视频和用户提供的直播 URL；联网也用于按标签查询歌词与元数据。
- v0.2 已完成单 URL 直播稳定性、纯核心 M3U、远程清单读取、本地/直播双列表和本地
  自用 Release 交付；v0.3 三场景界面重构、响应式回归和人工确认已完成。
- v0.4 已完成本地列表与直播 URL 持久化、直播源历史、清单取消和快捷键帮助。
- v0.5 已完成直播搜索、收藏持久化、最近播放和安全断点续播；用户已在仓库外独立
  生成并保留 v0.5 ZIP。
- v0.6 已使用固定 WebView2 SDK 增加独立网页模式，并完成多标签、隔离 Profile、历史与
  收藏、会话恢复、下载中心、网站权限、后台连续运行、性能优化和 Edge 风格统一侧栏。
- v0.7 已完成本地/直播成熟播放器风格、深浅主题、自定义 RGB 与背景、单向波形、帮助
  子窗口和跨页 WebView2 边界同步；用户最终确认通过。
- v0.7 Release 全量 CTest 为 `93/93`；Debug 历史为 `91/92`，唯一失败是本机
  `127.0.0.1` WebView2 页面超时，相关定向测试和 Release Runtime 均通过。
- 原 W-M01 至 W-M18 中未逐项补证的真实账号、DRM、外部协议和跨机器场景保留为
  兼容性与公开发布限制，不扩大解释为通过。
- 核心层不依赖 Qt 和 libVLC；GUI 层不链接 libVLC。
- `main.cpp` 是全项目唯一知道具体内核存在的地方。
- 内核事件回调发生在 libVLC 线程，必须经统一的桥接层投递到 GUI 主线程。
- 内核事件回调中禁止操作控件，禁止调用会等待内核线程的接口。
- 播放内核的释放顺序固定为六步，第一步必须是解除事件监听。
- 位置事件节流在内核实现层完成，不在界面层。
- libVLC 不进入 Git 仓库，通过 `MEDIAHUB_VLC_ROOT` 指向本机 SDK 目录。
- 测试使用假内核与哑音视频输出，不依赖真实声卡和显示设备。
- 音画输出效果依赖人工验收，没有自动化覆盖，交付文档必须如实声明。
- 不在仓库中提交任何有版权的音视频素材。
- 采用小步结对开发：每次只实现一个可审查增量。

## 协作约定

1. 每个增量开始前先说明目标、文件范围和验收方式。
2. 单次尽量只改 1～3 个文件。
3. 改动完成后先展示 diff、构建结果和设计理由。
4. 阶段测试和文档通过后自动提交；远程无冲突且认证可用时自动推送并继续下一阶段。
5. 推送失败时保留本地提交并记录原因，禁止强制覆盖远端，不扩展计划外功能。
