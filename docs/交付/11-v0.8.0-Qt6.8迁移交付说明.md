## 1. 交付目标

v0.8.0 把项目构建依赖从 Qt 5.14.2 切换为 Qt 6.8.3。项目仍在原仓库目录开发，Qt SDK
位于开发机外部路径 `C:\Qt6.8\6.8.3\msvc2022_64`，不进入仓库或发布包的源码目录。

## 3. 依赖和部署变化

- CMake 使用 `find_package(Qt6 6.8 ...)` 和 `Qt6::` targets。
- `windeployqt` 从 `Qt6::qmake` 同一 SDK 的 `bin` 目录定位。
- 发布校验器允许 Qt6 Release TLS/网络插件，精确拒绝 Qt6 Debug 模块和 Qt5 DLL。
- Qt6 播放状态写入独立 `MediaHubQt6` 配置；首次启动从旧 `MediaHub` 配置完整导入，已有
  Qt6 直播源备注优先，旧版独有地址按 URL 追加一次。
- Qt 许可证材料更新为 Qt 6.8.3 对应材料；libVLC、WebView2 和 GoogleTest 不变。
- Release 安装显式携带 WebView2 所需的 `dxcompiler.dll` 与 `dxil.dll`，避免在新安装
  前缀中因依赖缺失而无法启动网页组件。
- 主窗口固定 `Microsoft YaHei UI` 12px 字体基线；直播列表在所有响应式断点保持
  12px，并缩小行高和内边距，恢复接近 Qt5 的显示密度。
- Windows 正式播放实例固定使用 `--aout=directsound`，波形分析实例固定使用
  `--aout=dummy`，规避 libVLC `mmdevice` 音频输出初始化死锁。
- 目标机器仍需 MSVC 2022 x64 Redistributable 和 WebView2 Evergreen Runtime。

## 4. 正式包切换记录

正式包切换前的门禁均已满足：

1. 隔离 MP3/MP4 播放、包内 Qt6/libVLC 模块来源和正常关闭通过。
2. 用户使用当前可用直播源确认画面、声音和切网页后台播放正常。
3. 旧版 5 条帮助直播源地址和备注全部迁移并在 Qt6 窗口中确认。
4. 候选路径已重新执行结构校验与隔离冒烟。
5. 用户已确认本地 MP3 声音、音量/静音/倍速、真实直播首次播放、连续刷新切台以及长时间
   播放后恢复全部正常。

自动化同时覆盖切回直播、刷新当前源和继续播放；本轮 Debug/Release 全量 CTest 均为 `94/94`
通过，Release 总耗时 `122.89s`。与上述人工音画结果共同解除正式交付门禁。正式包结构校验
通过，隔离 MP3 播放 5 秒后正常关闭，退出码为 `0`。
按用户指定顺序，v0.8 源码与文档先普通推送到 `origin/main` 和 `github/main`，随后旧版本
包移入 Windows 回收站，v0.8 候选改名为唯一正式目录。正式路径继续执行结构校验，并完成
5 秒隔离 MP3 播放、包内模块来源和退出码 `0` 复验。
