历史与收藏、会话恢复、后台连续运行、下载中心、性能优化和 Edge 风格两层 Chrome/统一
侧栏。网页模块继续与 `mediahub_core`、libVLC 播放列表和直播清单隔离。

自签名证书、公共网站和跨机器场景不改写为通过，继续作为公开发布与兼容性复核边界。

## 3. 已交付能力

- “本地 / 直播 / 网页”使用固定尺寸的浅色分段入口；网页页使用两层顶部 Chrome 和
  历史、收藏、下载、声音、标签搜索、分组、权限共用的右侧侧栏。
- 地址栏、后退/前进、刷新、主页、网页内查找和原生内容区快捷键使用统一路由；首次
  就绪和主动新标签默认打开 Bing。
- 每个标签拥有独立 Controller 和导航状态，支持切换、拖动、关闭、恢复、固定、分组、
  搜索、缩放和会话恢复；网站新窗口请求转为共享 Profile 的新标签。
- 网页切到本地或直播时只隐藏，不主动挂起、静音、销毁或重新导航；后台网页和下载
  继续运行。进入网页仍暂停活动的原生媒体，离开网页不自动续播。
- 历史和收藏使用有界缓存与延迟持久化；收藏支持编辑和 HTML 导入导出。重复打开未变
  更侧栏不重新读取存储或重建列表。
- 下载中心支持并发任务、取消、可恢复中断和受控进度合并；终态立即展示，退出时会对
  活动任务给出明确确认。
- MediaHub 使用独立 WebView2 Profile，不读取或修改 Edge 个人资料。权限、下载/上传、
  证书和外部协议都经过显式安全决策；日志不记录完整 URL、凭据或 Profile 路径。

## 5. 安装与运行

目标系统为 Windows x64，需要 Microsoft Visual C++ 2015-2022 Redistributable（x64）
和 WebView2 Evergreen Runtime（x64）。WebView2 Loader 静态链接，发布目录中不应出现
`WebView2Loader.dll`。

正式运行目录仍为 `dist/MediaHub-0.6.0-win64/`。现有发布目录不依赖构建树；本次修复包
完成后应清理 `cmake-build-debug/`、`cmake-build-release/` 和替换前发布包备份。

## 6. 数据与安全边界

- 浏览器资料与播放器状态分开存储，不进入播放列表、最近播放或直播清单。
- Cookie、密码、Token、LocalStorage 和 IndexedDB 由 WebView2 Profile 管理，不写入
  MediaHub 的 `QSettings`、文档或日志。
- 历史、收藏和会话只保存经过边界检查的宿主元数据；完整查询、片段和用户信息不进入
  生产日志。
- 测试只访问受控环回页面或用户自行选择的网站，不提交账号、私人截图或版权媒体。

## 7. 已知限制

- 仅交付 Windows x64；尚未在无开发环境的第二台 Windows x64 机器或虚拟机复测。
- 项目自身源码许可证尚未决定，不能据此宣称已满足公开分发条件。
- 网站兼容性、DRM、账号风控、地区限制和网页自身后台策略由 Runtime 与网站共同决定。
- 原 W-M01 至 W-M18 中未逐项补证的登录、真实权限设备、外部应用、自签名 HTTPS 和
  跨环境 DPI 组合继续作为公开发布前检查项。
