## 1. 什么算“交付完成”

一个版本要同时满足以下条件才算交付完成，缺一不可：

| 条件 | 判断方式 |
|---|---|
| 功能完整 | MVP 文档中的验收用例全部通过 |
| 构建可重复 | Debug 与 Release 都能从干净目录构建成功 |
| 测试通过 | 全部 CTest 通过，跳过项有明确原因 |
| 隔离可运行 | 在没有开发环境的干净目录中能启动并播放 |
| 资源无残留 | 播放中关闭窗口，进程干净退出，无残留线程 |
| 文档可用 | 新用户仅凭文档就能构建、运行和测试 |
| 许可证齐备 | 第三方许可证文本已随发布目录提供 |
| 限制已声明 | 已知限制写入交付清单，不隐瞒 |

**不算交付完成的情况**：

- 只在开发机上验证过。开发机的 PATH 会掩盖缺失的依赖。
- 测试有失败项但“不影响主要功能”。失败就是失败，要么修，要么明确记录为
  已知问题并说明影响。
- 文档写的是计划而不是实际结果。

## 4. 已经可以预见的 v0.1 限制

以下限制在规划阶段就已确定，交付清单中必须包含：

- 仅正式支持 Windows x64。
- 不支持任何网络地址和直播流。
- 不支持字幕、多音轨、截图和录制；倍速已经实现。
- 不提供媒体库、播放历史和收藏。
- 具体格式的播放能力取决于 libVLC 与所携带的插件，项目不做能力承诺。
- 音画同步由播放内核负责，项目不提供同步质量指标。
- 视频画面、声音输出和音画同步依赖人工验收，没有自动化覆盖。
- 视频文件的自动化测试只覆盖失败路径和状态转换，不覆盖真实播放效果。
- 发布包体积较大，主要来自 libVLC 插件目录。
- Qt 5.14.2 已是归档版本，长期维护应单独评估 Qt 6。
- 项目自身的源码许可证尚未决定。

倒数第四条和倒数第五条是本项目诚实性的关键：播放器最核心的“能不能正常播”这件
事，自动化测试覆盖不到。不能因为 CTest 全绿就宣称播放功能已验证。
