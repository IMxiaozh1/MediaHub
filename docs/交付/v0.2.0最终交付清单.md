## 3. 已交付能力

- 本地 MP3、MP4、WAV 等 libVLC 可解码媒体播放，以及播放列表、进度、音量、倍速、
  快捷键、播放模式、波形、歌词和全屏。
- 用户自带八种白名单协议的直播 URL；缓冲状态、15 秒连接超时、立即取消和按钮/`F5`
  手动刷新。
- 用户自带远程 M3U/M3U8 清单；10 秒读取超时、5 次安全重定向、2 MiB 正文、5000
  条上限、UTF-8、相对地址补全、重复统计和失败保留。
- 本地与直播列表完全分开；切换标签不停止媒体，直播条目保持来源顺序且不提供删除、
  重命名或排序。
- 直播右键播放/暂停、停止、会话内标记和会话内收藏，以及按源地址定位正在播放。
- 卡顿直播连续切换时先完整停止旧 vout，再启动最终请求，避免脱离主窗口的 libVLC
  独立视频窗口。
- `icons/taskbar.png` 和 `icons/window.jpg` 分别控制任务栏与标题栏图标；替换文件并
  重启即可生效，缺失或损坏时按位置回退内嵌资源。

## 4. 安全与隐私边界

- 清单和媒体 URL 的凭据、查询参数及片段不进入显示名、状态文案、错误提示或日志。
- 远程清单服务不下载、保存或缓存 MP3、MP4 及其他音视频文件，不使用 Cookie。
- `.m3u` 失败不会伪装成单路直播；`.m3u8` 只有检测到真实 HLS 控制标签后才回退为
  直接播放。
- 不绕过登录、DRM、证书校验或访问限制；用户负责确认直播地址和内容来源合法。
- 程序不修改、移动、删除或重命名用户磁盘中的媒体文件。
- 用户真实清单地址、媒体、缓存、设置和本机构建产物均不提交仓库。

## 6. 快速复现

在 VS 2022 x64 开发者终端执行：

```powershell
cmake -S . -B cmake-build-v02-release -G Ninja ^
      -DCMAKE_BUILD_TYPE=Release ^
      -DCMAKE_PREFIX_PATH="C:/Qt/Qt5.14.2/5.14.2/msvc2017_64" ^
      -DMEDIAHUB_VLC_ROOT="C:/SDK/vlc-3.0.21" ^
      -DMEDIAHUB_PACKAGE_RELEASE=ON
cmake --build cmake-build-v02-release
ctest --test-dir cmake-build-v02-release --output-on-failure
cmake --install cmake-build-v02-release --config Release ^
      --prefix dist/MediaHub-0.2.0-win64
cmake "-DMEDIAHUB_PACKAGE_DIR:PATH=dist/MediaHub-0.2.0-win64" ^
      -P tools/validate_release_package.cmake
```

隔离播放：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass ^
  -File tools/stage12_isolated_smoke.ps1 ^
  -PackageDirectory dist/MediaHub-0.2.0-win64 ^
  -MediaPath "C:/path/to/owned-test-media.mp3"
```

## 7. 已知限制

- 仅正式支持 Windows x64，格式和协议能力取决于 libVLC 3.0.21。
- 直播源可用性、延迟、音画质量和同步无法可靠自动化，只保留真实人工验收证据。
- 不提供频道分类、Logo、EPG、多订阅、定时刷新、测速、录制或收藏持久化。
- Qt 5.14.2 已归档；歌词部分备用 HTTPS 源仍受本机 OpenSSL 1.1 缺失影响，远程清单
  在 Windows 使用系统 WinHTTP，不受此限制。
- 没有第二台无开发环境 Windows 或虚拟机，也未复测 Windows 系统级 125%/150%。
- MediaHub 自身源码许可证尚未决定，完整 VLC 插件许可尚未逐项裁剪复核。

上述限制不阻塞本地自用交付，但解决前不得宣称已正式公开发布。
