## 2. libVLC SDK 获取

### 2.1 选择版本

- 使用 VLC **3.0.x 系列**的 Windows **64 位**发行包。
- 不使用 4.x 开发版本，接口仍在变动。
- 必须与 MSVC 64 位工具链匹配，不下载 32 位包。

官方下载来源：VideoLAN 官方站点的 `win64` 目录，选择 `.7z` 格式的压缩包
（不是安装程序 `.exe`，压缩包才包含 SDK）。

```text
实际版本：VLC 3.0.21 win64（libVLC 版本字符串为 3.0.21 Vetinari）
下载日期：2026-08-03
下载文件：vlc-3.0.21-win64.7z（38,914,921 字节）
SHA-256：9D2B24D6BC4196B3DA8D181A3878678BA272E2A7690321F8826DA76A69B2FB9C
校验来源：VideoLAN 官方同目录 vlc-3.0.21-win64.7z.sha256
校验结果：实际值与官方值一致
```

### 2.2 解压位置

实际解压到固定的本机目录，与项目源码分开：

```text
C:\SDK\vlc-3.0.21\
```

不要解压到项目目录内。libVLC 不进入 Git 仓库，理由见
[01-播放内核选型.md](../设计/01-播放内核选型.md) 第 5.1 节。

### 2.3 解压后的目录结构

压缩包解压后应包含以下内容（这是编译和运行都需要的）：

```text
vlc-3.0.x/
├── libvlc.dll            运行时需要
├── libvlccore.dll        运行时需要
├── plugins/              运行时需要，数百个插件文件
└── sdk/
    ├── include/
    │   └── vlc/          编译需要的头文件
    └── lib/
        ├── libvlc.lib        链接需要
        └── libvlccore.lib    链接需要
```

阶段 1 的第一件事是确认这四类内容都存在。如果下载的包里没有 `sdk/` 目录，
说明下载了安装程序而不是压缩包，需要重新下载。

## 3. CMake 接入方式

### 3.1 指定路径

libVLC 的处理方式与 Qt 一致：作为开发机上的外部 SDK，通过变量指向本机目录。

```powershell
cmake -S . -B cmake-build-debug -G Ninja ^
      -DCMAKE_BUILD_TYPE=Debug ^
      -DCMAKE_PREFIX_PATH="C:/Qt6.8/6.8.3/msvc2022_64" ^
      -DMEDIAHUB_VLC_ROOT="C:/SDK/vlc-3.0.21"
```

**硬性规则**：

- 项目 `CMakeLists.txt` 中不得出现任何本机绝对路径。
- `MEDIAHUB_VLC_ROOT` 未提供时，配置阶段直接失败并给出清晰提示，说明需要
  设置什么变量、指向什么目录。不静默降级，也不猜测默认路径。
- 头文件目录和库文件只链接到 `mediahub_engine_vlc` 这一个目标，不污染其他
  目标。
- 正式打包还需要匹配 Qt 版本的 `LICENSE.LGPLv3` 和 `LICENSE.GPLv3`；安装 Qt Sources
  后可使用默认位置，否则通过 `MEDIAHUB_QT_LICENSE_DIR` 指向包含这两个文件的目录。

### 3.2 依赖隔离的验证

配置完成后，`mediahub_gui_support` 和 `mediahub_core` 都不应该能看到 libVLC
的头文件。如果有人在这两个目标里写了 `#include <vlc/vlc.h>`，编译应该失败。

这是[03-项目结构.md](../设计/03-项目结构.md)第 5 节依赖规则的强制手段。

## 4. 开发环境配置

### 4.1 方式一：Qt Creator（推荐日常开发）

1. 打开 Qt Creator，加载项目根目录的 `CMakeLists.txt`。
2. 在构建套件中选择 Qt 6.8.3 msvc2022_64 + MSVC 2022 64bit 编译器。
3. 在构建配置的 CMake 参数中添加 `MEDIAHUB_VLC_ROOT`。
4. 构建目录使用 `cmake-build-debug` / `cmake-build-release`。

Qt Creator 还提供 `.ui` 文件的可视化编辑，界面阶段会用到。

### 4.2 方式二：VS 开发者命令提示符

启动“x64 Native Tools Command Prompt for VS 2022”，然后使用第 3.1 节的命令
配置和构建。这个终端已经加载了 `cl.exe` 和 Windows SDK 环境。

### 4.3 方式三：Visual Studio 直接打开文件夹

VS 2022 支持直接打开 CMake 项目文件夹，通过 `CMakeSettings.json` 配置变量。
这个文件属于个人 IDE 配置，不提交到仓库。

## 5. 运行时部署

### 5.1 需要携带的文件

`MediaHub.exe` 运行需要三类文件：

| 类别 | 内容 | 来源 |
|---|---|---|
| Qt 运行库 | `Qt6Core.dll`、`Qt6Gui.dll`、`Qt6Network.dll`、`Qt6Widgets.dll` 等 | `windeployqt` 自动处理 |
| Qt 平台插件 | `platforms/qwindows.dll` 及图像插件 | `windeployqt` 自动处理 |
| libVLC | `libvlc.dll`、`libvlccore.dll`、`plugins/` 整个目录 | CMake 按使用目标复制 |
| WebView2 | 静态 Loader；运行时由系统 Evergreen WebView2 提供 | 目标机器需安装 |
| MSVC 运行库 | Visual C++ 2022 x64 Redistributable | 目标机器需安装 |

### 5.2 目录布局

```text
MediaHub-发布目录/
├── MediaHub.exe
├── Qt6Core.dll
├── Qt6Gui.dll
├── Qt6Network.dll
├── Qt6Widgets.dll
├── platforms/
│   └── qwindows.dll
├── libvlc.dll
├── libvlccore.dll
└── plugins/
    └── （libVLC 的插件子目录，保持原有结构）
```

**关键点**：`plugins/` 目录必须与 `libvlc.dll` 保持原有的相对位置关系。缺少
插件目录时，libVLC 能初始化成功但无法播放任何媒体 —— 这是一个很隐蔽的失败，
表现为"程序能开但什么都播不了"。

### 5.3 自动化部署

CMake 当前按目标执行部署：

1. GUI 程序和 Qt Test 调用 Qt 6.8.3 套件的 `windeployqt` 部署 Qt 运行库和插件。
2. libVLC 探针和集成测试复制两个 libVLC DLL 与整个 `plugins/` 目录。
3. 正式 GUI 程序构造 `VlcPlayerEngine`，因此同步部署两个 DLL 与完整插件目录。
4. Release 安装显式复制 `dxcompiler.dll` 与 `dxil.dll`，保证 WebView2/图形依赖在全新
   安装前缀中完整，不依赖构建目录残留文件。

`windeployqt` 必须显式使用目标 Qt 套件 `bin` 目录下的那一个，避免机器上其他
Qt 安装或 Python 发行版携带的同名工具干扰依赖解析。

### 5.4 隔离验证

阶段 12 交付前必须在干净环境验证：

1. 把发布目录复制到一个没有开发环境的位置。
2. 清空 `QT_PLUGIN_PATH`、`QML2_IMPORT_PATH`、`VLC_PLUGIN_PATH` 环境变量。
3. 把 PATH 缩减为只含 Windows 系统目录。
4. 启动 `MediaHub.exe`，打开并播放一个媒体文件。
5. 正常关闭，确认退出码为 `0`。

只在开发机上"能跑"不算通过。开发机的 PATH 里有 Qt 和 VLC，会掩盖缺失的依赖。

## 6. 许可证

### 6.1 Qt

- 使用 Qt 6.8.3 `msvc2022_64` 动态链接。
- 开源许可为 LGPLv3 / GPLv3。
- 发布目录需包含 Qt 的许可证文本副本。

### 6.2 libVLC

- libVLC 核心库使用 LGPLv2.1 或更高版本。
- 动态链接的情况下，调用方代码不必开源，但必须允许用户替换该库，并提供
  许可证文本。
- **VLC 官方发行包中的部分插件使用 GPLv2 或更高版本。** 如果发布包中包含
  这些插件，整个发布可能需要遵守 GPL 条款。

### 6.3 需要完成的动作

| 时机 | 动作 |
|---|---|
| 阶段 1 | 记录 libVLC 实际版本，保存官方许可证文本副本 |
| 阶段 12 | 发布目录中包含 Qt 与 VLC 的许可证文本 |
| 对外分发前 | 逐个确认所携带插件的许可证，或裁剪 GPL 插件 |
| 对外分发前 | 决定 MediaHub 自身源码的许可证 |

自用和学习不受上述条款的实际影响。只有在向他人分发二进制时才需要完成完整
合规确认。这一点不能等到交付前才发现，因此在阶段 1 就记录下来。

## 8. 阶段 12 Release 交付进度

使用 `MEDIAHUB_PACKAGE_RELEASE=ON` 配置 Release 后，通过 `cmake --install` 生成
独立发布目录：

```powershell
cmake --install cmake-build-stage12-release --config Release ^
      --prefix dist/MediaHub-0.1.0-win64
cmake -DMEDIAHUB_PACKAGE_DIR=dist/MediaHub-0.1.0-win64 ^
      -P tools/validate_release_package.cmake
```

发布前缀必须是新的空目录。当前安装规则固定使用 Release Qt DLL，不复制测试程序、
静态库、PDB、构建日志或 VC++ 运行库安装器。目标机需预装 Microsoft Visual C++
2015-2022 Redistributable（x64）。

2026-08-04 实际结果：

- 空目录 Debug 与 Release 全目标构建成功，CTest 均为 `44/44`。
- Release GUI 套件连续 5 轮通过。
- 发布目录共 396 个文件、185.86 MiB，其中 VLC DLL 插件 365 个。
- 生成的 `MediaHub-0.1.0-win64.zip` 为 78.91 MiB，SHA-256 为
  `A84E629E23EC0171B21B150156A21F34E402A7CC7CFFBF09532954E5AFE8A2E2`。
- Qt LGPLv3/GPLv3、VLC `COPYING.txt` 和第三方说明均位于 `licenses/`。
