> 状态：已完成（2026-08-03）。
>
> 测试范围：纯 C++ 核心值类型、`PlayerEngine` 与事件接口、8 状态转换表、

## 1. 实现边界

阶段 3 实际完成以下内容：

- 定义 `MediaItem`、`MediaSourceKind`、`PlaybackState`、`PlaybackPosition`、
  `PlaybackError`、`PlaybackErrorKind` 和 `PlaybackMode`。
- 集中实现本地路径、文件 URI 和网络 URI 的来源识别，并能从来源推导默认显示名。
- 定义纯虚 `PlayerEngine` 和 `PlayerEventListener`，接口只使用标准 C++ 类型。
- 明确控制方法只提交请求，完成结果必须等待异步事件。
- 明确事件回调可能来自任意内核线程，快照读取必须由实现保证线程安全。
- 实现 `PlaybackStateMachine`，区分改变、重复和拒绝三类转换结果。
- 实现仅链接到测试目标的 `FakePlayerEngine`，请求只记录，事件只由测试主动触发。
- 增加 `MEDIAHUB_CORE_ONLY`，允许不提供 Qt 和 libVLC 路径时构建核心及单元测试。

本阶段没有实现 `VlcPlayerEngine`，没有解码、声音、视频、播放控件或网络请求。
`MediaHub.exe` 的可见行为仍是阶段 2 的空窗口。

## 3. 状态机规则

正式转换表记录在[02-v0.1-实现设计.md](../设计/02-v0.1-实现设计.md)第 2.2 节。测试穷举全部
8×8 共 64 个有序状态对，其中：

- 37 个跨状态转换必须返回 `Changed` 并更新状态。
- 8 个同状态重复事件必须返回 `Unchanged` 并保持状态。
- 19 个非法转换必须返回 `Rejected`，原状态不得被污染。
- 任意状态都可以通过显式 `reset()` 回到 `Idle`。

回到 `Idle` 是解除当前媒体时的显式重置，不伪装成内核状态事件。切换媒体通过活动
状态进入 `Opening` 表达；失败后只允许重新打开或停止恢复。

## 4. 接口与假内核验证

`FakePlayerEngine` 完整覆盖接口的八类控制请求：

| 请求 | 验证内容 |
|---|---|
| `open` | 完整复制并记录 `MediaItem` |
| `play`、`pause`、`stop` | 保持调用顺序且不自动改变状态 |
| `seek` | 保留毫秒类型和目标值 |
| `setVolume` | 保留 0 至 100 范围内的输入值 |
| `setMuted` | 保留静音布尔值 |
| `setVideoSurface` | 只透传不透明句柄，不引入 Windows 类型 |

五类事件 `state`、`position`、`duration`、`end` 和 `error` 均由测试显式触发，回调
在调用者线程同步发生。测试验证：

- 事件到达顺序与测试发出顺序完全一致。
- 快照在回调前更新。
- 未知时长使用 `std::nullopt`，不使用特殊整数。
- 解除监听后不再调用旧监听器。
- 非法状态事件被状态机拒绝后，后续合法事件仍从未污染的状态继续处理。
- 编译期断言确认假内核不是抽象类，证明其完整实现 `PlayerEngine`。

## 8. 首轮失败与修复记录

第一次从普通 PowerShell 直接执行构建时，CMake 能找到缓存中的 `cl.exe`，但 MSVC
标准库环境变量没有初始化，编译器因此报告找不到 `chrono`、`array` 和
`type_traits`。这与仓库说明中“普通终端必须先进入 VS 开发者环境”的已知限制一致。

随后通过 VS 2022 的 `VsDevCmd.bat` 初始化 x64 开发环境，再执行相同构建命令，
Debug、Release 和核心独立构建全部通过。正确开发环境下没有发生源码编译失败，也
没有功能测试失败。本节不把普通终端的失败写成通过。

## 9. 已知问题

- `MediaHub.exe` 仍是空窗口，没有真实播放能力，这是阶段边界而不是缺陷。
- `PlayerEngine` 的线程安全约定已固定，但真实 libVLC 事件线程和释放顺序要到阶段 4
  用集成测试验证。
- 声音、视频画面、音画同步和真实格式兼容性不属于本阶段自动化范围。

## 10. 阶段结论

阶段 3 实现验收通过：

- 核心公共接口没有泄漏任何具体播放库、GUI 框架或 Windows 类型。
- 状态机穷举验证全部合法、重复和非法转换，拒绝事件不会污染状态。
- 假内核完整实现接口，并能精确控制请求与事件时序。
- 核心层在完全不查找 Qt 和 libVLC 的配置中独立构建和测试。
- 阶段 1 libVLC 探针与阶段 2 GUI 测试保持回归通过。
