# MediaHub 测试策略与阶段模板

> 状态：执行中。阶段 1 至阶段 9 已完成；当前进入阶段 10。
>
> 分类：测试。
> 本目录保存每个阶段的测试范围、命令和**实际结果**。
> 尚未执行的测试不得写入结果，也不得预先声称通过。

## 1. 本目录的规则

- 每完成一个阶段，创建一份 `阶段N测试.md`。
- 文档记录的是实际执行结果，不是计划。命令没跑过就不写结果。
- 人工验收和自动化验证必须分开写，不能混为一谈。
- 失败和跳过的项目必须记录，并说明原因，不得只写通过的部分。
- 如果某项能力无法自动化验证，明确写出“人工验证”，不假装有覆盖。

最后两条是本项目最容易出问题的地方：播放器有大量“看起来能播就算对”的部分，
必须诚实标注验证方式。

## 2. 测试分层

### 2.1 单元测试（`tests/unit`）

**依赖**：GoogleTest。不依赖 Qt、libVLC 和音频设备。

覆盖对象：

| 对象 | 验证内容 |
|---|---|
| 播放状态机 | 每种状态下每个操作的结果，包括非法操作被拒绝 |
| 播放列表 | 三种模式的下一项计算、边界、空列表、单项列表 |
| 媒体来源识别 | 本地路径与 URL 的区分 |
| 错误映射 | 各类失败输入得到正确的类别和中文提示 |
| 时间格式化 | 零、不足一分钟、超过一小时、时长未知 |
| 音量边界 | 0、100、越界值的处理 |

这一层使用 `FakePlayerEngine`，测试可以精确控制事件时序。

### 2.2 集成测试（`tests/integration`）

**依赖**：GoogleTest + 真实 libVLC。配置为哑音频和哑视频输出。

覆盖对象：

| 对象 | 验证内容 |
|---|---|
| 内核初始化 | 创建成功、参数生效、版本可读 |
| 打开媒体 | 有效文件成功，无效文件失败并给出错误 |
| 播放链路 | 打开 → 播放 → 状态到达 `Playing` |
| 定位 | 定位后位置变化符合预期 |
| 停止与释放 | 播放中释放内核，无崩溃、无残留线程 |
| 反复创建释放 | 多轮创建释放后资源不增长 |
| 中文与空格路径 | 能正常打开 |
| 事件线程 | 事件确实来自非主线程（验证线程模型假设成立） |

最后一项容易被忽略但很重要：如果某天 libVLC 改成在调用线程上回调，整个跨线程
设计的前提就变了，测试应该能发现。

### 2.3 GUI 测试（`tests/gui`）

**依赖**：Qt Test + `FakePlayerEngine`。不使用真实播放。

覆盖对象：

| 对象 | 验证内容 |
|---|---|
| 控件启用状态 | 按[第一版实现.md](../设计/第一版实现.md)第 6.2 节表格逐状态验证 |
| 事件桥接 | 从非主线程发出事件，断言处理发生在主线程 |
| 进度拖动 | 按下、拖动、松开的完整序列 |
| 播放列表视图 | 数据角色、当前项高亮、选择联动 |
| 打开文件流程 | 多选、拖放、命令行参数三条路径结果一致 |
| 失败提示 | 失败后界面状态与提示内容 |
| 窗口关闭 | 播放中关闭时内核被确定性释放 |

**不使用整窗口像素截图比较**。这类测试脆弱且难以维护，改一个边距就全红。

### 2.4 人工验收

以下内容无法可靠自动化，只做人工验收并记录在阶段测试文档中：

- 声音是否正常输出。
- 视频画面是否正确显示。
- 音画是否同步。
- 各种真实媒体格式的播放效果。
- 高 DPI 缩放下的界面布局。
- 长时间播放的稳定性。

人工验收记录必须包含：使用的文件类型、观察到的现象、是否通过。不写“测试通过”
这种没有信息量的结论。

## 3. 测试数据

### 3.1 原则

- 音频测试文件在运行时用代码生成，测试结束后由 RAII 清理。
- 不使用固定盘符和个人路径。
- **不在仓库中提交任何有版权的音视频素材。**
- 需要真实媒体的人工验收，由验收者使用自己合法持有的文件，不提交到仓库。

### 3.2 可生成的测试数据

| 数据 | 生成方式 | 用途 |
|---|---|---|
| 短音频文件 | 用代码写出结构简单的无损音频容器，内容为静音或正弦波 | 打开、播放、定位 |
| 空文件 | 创建零字节文件 | 打开失败路径 |
| 损坏文件 | 写入随机字节并使用媒体扩展名 | 格式无法识别路径 |
| 文本冒充媒体 | 写入文本内容，改名为媒体扩展名 | 格式无法识别路径 |
| 中文空格路径 | 在临时目录下创建含中文与空格的子目录 | 路径编码 |

**已知限制**：视频文件难以用少量代码生成。视频相关的自动化测试只覆盖到“打开
失败”和“状态转换”，真实视频播放依赖人工验收。这一点在阶段 4 和阶段 6 的测试
文档中必须明确写出。

### 3.3 哑输出配置

集成测试创建内核时使用哑音频和哑视频输出参数，好处：

- 不需要真实声卡，可以在没有音频设备的环境运行。
- 不会在测试期间发出声音。
- 不创建视频窗口，测试不受显示环境影响。

这个配置由内核构造参数控制，不是编译期开关。

## 4. 异步测试的处理

播放器的操作都是异步的，测试必须处理等待。规定：

- **禁止用固定时长 `sleep` 碰运气。**
- 使用明确的等待条件：轮询目标状态直到满足或超时。
- 每个等待必须有超时上限，超时视为测试失败。
- 超时数值定义为具名常量，不散落魔法数字。
- 假内核测试应该完全同步，不需要等待。只有真实内核的集成测试才需要。

## 5. 构建与运行命令

```powershell
# 配置（首次或选项变化时）
cmake -S . -B cmake-build-debug -G Ninja ^
      -DCMAKE_BUILD_TYPE=Debug ^
      -DCMAKE_PREFIX_PATH="C:/Qt/Qt5.14.2/5.14.2/msvc2017_64" ^
      -DMEDIAHUB_VLC_ROOT="<本机 libVLC SDK 目录>"

# 构建
cmake --build cmake-build-debug

# 运行全部测试
ctest --test-dir cmake-build-debug --output-on-failure

# 只运行某一组
ctest --test-dir cmake-build-debug -R playlist --output-on-failure
```

以上命令需要在能找到 `cl.exe` 和 `ninja.exe` 的开发者终端中执行，或通过
Qt Creator 的构建配置执行。具体环境准备见
[依赖接入与部署说明.md](../交付/依赖接入与部署说明.md)。
