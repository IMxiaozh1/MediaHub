# MediaHub 阶段 4 测试

> 状态：已完成（2026-08-03）。
>
> 测试范围：真实 `VlcPlayerEngine`、libVLC 句柄 RAII、事件映射、哑输出本地音频、
> 中文空格路径、失败路径、事件线程、播放中析构和阶段 1 至阶段 3 全量回归。

## 1. 实现边界

阶段 4 实际完成以下内容：

- 使用 PImpl 实现 `VlcPlayerEngine`，公共头文件不包含任何 libVLC 或 Windows 类型。
- 集中构造 libVLC 初始化参数；测试通过选项启用 `adummy` 和 `vdummy` 输出。
- 用三个带自定义删除器的 `std::unique_ptr` 管理实例、媒体和播放器句柄。
- 实现打开、播放、暂停、停止、定位、音量、静音、视频句柄和线程安全快照。
- 把 libVLC 状态、时间、时长、可定位、自然结束和失败映射为核心事件。
- 位置事件在内核层按约 200 毫秒节流，用户主动定位和关键边界事件立即发送。
- 监听器解除会等待已进入的外部回调完成，析构会等待已进入的 libVLC 回调完成。
- 固定执行“断开事件、停止、等待、释放播放器、释放媒体、释放实例”的顺序。
- 增加 `mediahub_vlc_tests`，构建后自动部署 libVLC DLL 与完整插件目录。

本阶段没有把真实内核接入 Qt 窗口，没有播放控件，也没有启用网络输入。网络来源在
内核层直接返回明确失败，不发起网络访问。

## 3. 依赖与线程边界

```text
mediahub_vlc_tests
        │
        v
mediahub_engine_vlc ──> mediahub_core
        │
        v
MediaHub::LibVLC ──> C:\SDK\vlc-3.0.21（仅本机构建输入）
```

边界检查结果：

- `include/mediahub/core/` 和 `src/core/` 没有 Qt、libVLC 或 Windows 头文件。
- `include/mediahub/engine_vlc/` 只暴露 PImpl 与标准 C++ 类型，没有 libVLC 头文件。
- `src/engine_vlc/` 没有 Qt 头文件。
- `apps/gui/` 没有 libVLC 调用，`mediahub_gui_support` 仍不链接 libVLC。
- 只有私有 `vlc_handles.h` 的三个删除器调用对应的 `libvlc_*_release`。

`Playing` 状态回调记录的线程 ID 与测试调用线程不同，实际验证了 libVLC 事件来自
内部线程。监听接口改为 `noexcept`，异常不能越过 C 回调边界；回调规则明确禁止在
内核线程同步调用停止、释放或更换监听器。

## 4. 测试媒体

集成测试在运行时生成以下数据：

|---|---|
| 容器 | RIFF/WAVE |
| 编码 | PCM 16 位整数 |
| 声道 | 单声道 |

| 清理 | 测试对象析构时删除唯一目录，并尝试移除空父目录 |

WAV 头和静音数据由 C++ 测试代码直接写入，不下载、不复制、不提交任何音频素材。
测试不依赖固定盘符、执行顺序、真实声卡或可见窗口。

## 7. 首轮失败与修复记录

阶段 4 第一次编译正式内核时没有源码错误，但 MSVC 报告 C++20 已弃用
`std::filesystem::u8path`。这条警告没有被忽略：实现改为从 `std::u8string` 构造
`std::filesystem::path`，再次编译后警告消失。

正确开发环境下，8 个真实内核集成场景首次执行即全部通过；Debug 和 Release 最终
全量回归也没有测试失败、跳过或超时。本节没有把编译警告伪装成无问题。

## 8. 人工验收边界

本阶段使用 `adummy` 和 `vdummy`，因此自动化验证的是解封装、解码、时钟、状态、
事件和释放链路，不声称验证了真实扬声器音质、视频画面或音画同步。真实声卡输出和
用户可操作播放链路从阶段 5 开始接入，最终在阶段 11 人工验收。

## 9. 已知问题

- `MediaHub.exe` 仍是空窗口，真实内核尚未由 GUI 构造，这是阶段边界。
- libVLC 的通用失败事件无法可靠区分损坏文件和不支持格式，细化错误映射留到阶段 9。
- 位置节流已经实现，拖动进度条和 GUI 卡顿验证留到阶段 7。
- 视频输出方法已经透传不透明句柄，真实画面验证留到阶段 6。

## 10. 阶段结论

阶段 4 实现验收通过：

- 真实 libVLC 内核完整实现 `PlayerEngine`，公共边界没有泄漏具体库类型。
- 运行时生成的中文空格路径 WAV 能完成播放、暂停、定位、继续、停止和自然结束。
- 自动化使用哑输出，不依赖真实声卡、显示器或有版权媒体。
- 事件线程假设得到实际验证，监听解绑和析构等待具有明确同步与超时边界。
- 重复播放中析构没有崩溃、超时或残留测试进程。
- Debug、Release 和旧阶段全部回归通过。

可以进入阶段 5，把事件安全投递到 Qt 主线程并建立 GUI 的本地音频控制链路。
