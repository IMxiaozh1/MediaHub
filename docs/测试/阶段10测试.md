# MediaHub 阶段 10 测试

> 状态：已完成（2026-08-03）。核心边界、Presenter、PlaylistModel 和运行时测试数据
> 工具的覆盖补强通过。
>
> 测试范围：状态机与播放列表边界、媒体名称推导、六类错误日志映射、非法及迟到
> 事件、视图模型数据角色，以及运行时 WAV/错误媒体的生成和清理。

## 1. 实现边界

阶段 10 只补强自动化测试和测试基础设施，不改变播放器业务行为：

- 提取 `tests/support/generated_media.h/.cpp`，统一生成静音 PCM/WAV 和错误媒体。
- 生成器使用系统临时目录、中文空格文件名和唯一子目录，析构时只清理自身目录。
- libVLC 集成测试复用统一生成器，不再内嵌重复的文件写入和清理逻辑。
- 补齐空列表、单项列表、选择项前后移除和媒体名称推导边界。
- 补齐 `PlaylistModel` 的显示/无障碍角色、当前项标记和模型重置信号测试。
- 补齐 `PlayerPresenter` 对非法状态、关闭后迟到事件和全部错误分类日志值的测试。

本阶段不修改界面样式、不新增播放功能、不引入媒体素材，也不以自动化代替真实音画
验收；真实媒体、DPI 和稳定性验收留到阶段 11。

### 2.2 Qt GUI

`mediahub_gui_tests` 当前内部 25 个 Qt Test，用例新增覆盖：

- `PlaylistModel` 只在显示和无障碍文本角色返回内容，无效索引和其他角色为空。
- 当前项使用明确标记；核心选择改变并刷新后只发出一次模型重置信号。
- 播放中收到非法 `Idle` 状态不会改变界面，也不会发出已应用状态信号。
- Presenter 关闭后忽略新媒体、状态和错误事件，不继续向内核提交命令。
- 六种 `PlaybackErrorKind` 均映射为稳定日志值，用户提示仍只显示中文消息。

原有 GUI 测试继续覆盖控件状态、线程桥接、进度、音量、列表、视频占位、全屏、
错误恢复、日志脱敏和关闭顺序。不使用整窗口像素截图比较。

### 2.3 libVLC 集成

- 9 个 libVLC 集成用例全部复用运行时媒体生成器。
- 静音输出不依赖真实音频设备或显示设备。
- 所有等待都使用条件变量谓词和超时上限；源码扫描未发现固定 `sleep`/`qWait`。
- 测试不读取个人媒体、不依赖固定盘符，也不提交任何音视频文件。

## 3. 验证命令与实际结果

命令在 VS 2022 x64 开发者环境中执行：

```powershell
cmake --build cmake-build-debug
ctest --test-dir cmake-build-debug --output-on-failure

cmake --build cmake-build-release
ctest --test-dir cmake-build-release --output-on-failure

cmake --build cmake-build-core-debug
ctest --test-dir cmake-build-core-debug --output-on-failure

cmake --build cmake-build-no-tests
ctest --test-dir cmake-build-no-tests -N
```

实际结果：

- Debug 全量 CTest `38/38` 通过；最终回归总耗时约 11.74 秒。
- Release 全量 CTest `38/38` 通过；最终回归总耗时约 9.63 秒。
- `MEDIAHUB_CORE_ONLY=ON` CTest `27/27` 通过；最终回归总耗时约 3.10 秒。
- `MEDIAHUB_BUILD_TESTS=OFF` 构建成功，CTest 确认为 0 个测试。
- GUI Qt Test 内部 `25/25` 通过。
- `git diff --check`、100 字符行、固定等待和依赖边界扫描通过。
