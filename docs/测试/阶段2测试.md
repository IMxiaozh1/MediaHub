# MediaHub 阶段 2 测试

> 状态：已完成（2026-08-03）。
>
> 测试范围：C++20/Qt 5.14.2 最小工程骨架、全部基础 CMake 目标、GoogleTest、
> Qt Test、CTest、Qt 运行库部署，以及 Debug/Release 空窗口生命周期。

## 1. 实现边界

阶段 2 实际完成以下内容：

- 建立 `mediahub_core` 空静态库，不依赖 Qt 和 libVLC。
- 建立 `mediahub_engine_vlc` 静态库骨架，只验证 libVLC 头文件接入和依赖方向。
- 建立 `mediahub_gui_support` 静态库，封装阶段 2 最小 `MainWindow`。
- 建立正式 GUI 目标 `mediahub_gui`，输出 `MediaHub.exe`。
- 固定接入 GoogleTest 1.17.0，并建立 `mediahub_tests`。
- 接入 Qt 5.14.2 Test，并建立 `mediahub_gui_tests`。
- 使用 `windeployqt` 为程序和 GUI 测试部署实际 Qt 运行库。
- 显式部署 Qt offscreen 平台插件，使 GUI 测试不依赖可见桌面。
- 增加 `MEDIAHUB_BUILD_TESTS`，允许在不构建测试依赖时生成程序。

本阶段没有定义 `PlayerEngine` 接口，没有状态机、播放列表、播放控制、音视频输出或
网络功能。`MediaHub.exe` 只显示标题为 `MediaHub`、初始大小为 960×600 的空窗口。

## 6. 验证命令与最终结果

Debug：

```powershell

      -DCMAKE_BUILD_TYPE=Debug `
      -DCMAKE_PREFIX_PATH="C:/Qt/Qt5.14.2/5.14.2/msvc2017_64" `
      -DMEDIAHUB_VLC_ROOT="C:/SDK/vlc-3.0.21"

ctest --test-dir cmake-build-debug --output-on-failure
```

Release：

```powershell

      -DMEDIAHUB_VLC_ROOT="C:/SDK/vlc-3.0.21"
cmake --build cmake-build-release
ctest --test-dir cmake-build-release --output-on-failure
```

不构建测试：

```powershell
cmake -S . -B cmake-build-no-tests -G Ninja `
      -DCMAKE_BUILD_TYPE=Debug `
      -DCMAKE_PREFIX_PATH="C:/Qt/Qt5.14.2/5.14.2/msvc2017_64" `
      -DMEDIAHUB_VLC_ROOT="C:/SDK/vlc-3.0.21" `

ctest --test-dir cmake-build-no-tests -N
```

最终结果：

- Debug 和 Release 均成功生成 3 个基础静态库、`MediaHub.exe`、
  `MediaHubVlcProbe.exe`、`mediahub_tests.exe` 和 `mediahub_gui_tests.exe`。
- Debug 最终 CTest 为 3/3 通过，总耗时 0.57 秒。
- Release 最终 CTest 为 3/3 通过，总耗时 0.53 秒。
- GoogleTest 直接运行 1 个测试套件中的 1 个测试，通过数为 1，耗时 0 毫秒。
- Qt Test 进程返回 `0`，其内部两个测试函数均由 CTest 入口执行。
- 无测试配置成功构建程序，`ctest -N` 报告 `Total Tests: 0`。
- 检查的 16 个 Debug/Release 目标与平台插件产物全部存在。
- 最终没有失败、跳过或残留进程。

## 7. 首轮失败与修复记录

阶段测试过程中出现过以下失败，均在最终回归前修复：

1. Debug 首轮编译失败：`vlc.h` 不直接提供 `LIBVLC_VERSION_MAJOR`，同时 MSVC
   不接受指向自动存储数组的局部 `constexpr std::span`。改为包含
   `vlc/libvlc_version.h`，并把测试数组改为静态存储后编译通过。
2. GUI 测试首次运行没有结束。原因是 `windeployqt` 只自动部署 Windows 可见平台
   插件，没有复制测试指定的 `qoffscreen`。终止该次测试进程后，为
   `mediahub_gui_tests` 增加配置相关的 offscreen 插件复制，最终 Debug/Release
   GUI 测试均在 0.2 秒内完成。
3. 一次并行回归把“残留进程检查”和 CTest 同时启动，检查瞬间看到两个仍在正常
   执行的测试进程。改为等待 CTest 完成后再检查，相关进程数为 0；这属于验收
   命令时序问题，不是程序退出缺陷。

这些失败没有被写成通过；第 6 节只记录修复后的最终回归结果。
