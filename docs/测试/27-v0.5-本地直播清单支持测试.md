## 1. 问题与根因

VLC 桌面版打开本地 IPTV M3U8 后会解析子项并展示频道，但 MediaHub 的本地文件入口
只把路径作为单个媒体交给 `libvlc_media_new_path()`。远程 M3U/M3U8 已有独立下载和
核心解析链路，本地文件却没有进入该链路，因此既不会展开频道，也无法从列表选择直播。

用户提供的 8 个仓库外真实清单均为标准 IPTV 频道清单：首行是 `#EXTM3U`，每个
`#EXTINF` 后紧跟唯一的 HTTP/HTTPS 直播地址，不含 HLS 媒体控制标签。项目自己的核心
解析器验证结果如下：

| 样本 | 接受 | 跳过 | 重复 | 问题 |
|---|---:|---:|---:|---:|
| 完整清单及状态版 | 377 / 377 | 0 / 0 | 0 / 0 | 0 / 0 |
| 央视频道及状态版 | 195 / 195 | 0 / 0 | 0 / 0 | 0 / 0 |
| 付费频道及状态版 | 10 / 10 | 0 / 0 | 0 / 0 | 0 / 0 |
| 卫视频道及状态版 | 172 / 172 | 0 / 0 | 0 / 0 | 0 / 0 |

真实清单只在仓库外读取，没有复制或提交其中内容。

## 2. 实现策略

- 单独选择、拖入或通过命令行传入本地 `.m3u/.m3u8` 时，在线程池读取文件并复用
  `LivePlaylistService` 和纯核心 `parseM3u()`，不阻塞 GUI 主线程。
- 本地清单沿用 10 秒、2 MiB、5000 项、有效 UTF-8、协议白名单和重复地址限制；读取
  失败只报告稳定类别，不向日志写入完整本地路径。
- 本地清单文件本身按路径去重并保留在本地列表，便于切换其他 URL 清单后再次双击
  恢复；解析出的频道原子替换直播列表，不污染远程清单 URL 和历史记录。
- `.m3u8` 仍有语义歧义：检测到 HLS 主清单或媒体清单控制标签时，不展开为 IPTV
  频道，而是回退到原来的本地媒体播放链路。
- 修复前已经持久化在本地列表中的 `.m3u/.m3u8` 也会在双击、右键播放、最近播放或
  列表导航命中时重新进入清单解析，不要求用户先删除旧条目再重新选择文件。
- 一次选择中混入普通媒体和清单，或同时选择多个清单时，明确提示清单必须单独载入，
  避免异步请求互相覆盖或产生不明确的合并语义。
- `.m3u/.m3u8` 已加入文件选择器默认媒体筛选；普通 MP3、MP4、多选、远程清单和
  单路网络 HLS 行为保持不变。

## 3. 自动化证据

`LivePlaylistServiceTest::loadsLocalPlaylistFilesAndReportsFailures` 覆盖：

1. 带中文频道名、额外注释和未知 `response-time` 属性的本地 IPTV 清单完整解析。
2. 单路 HLS 媒体清单返回稳定分类，由 Presenter 决定回退播放。
3. 不存在或不可读文件返回 `LocalFileUnreadable`，不伪装成网络错误。

`MainWindowTest::expandsLocalIptvPlaylistAndFallsBackForLocalHlsManifest` 覆盖：

1. 本地 `.m3u8` 不直接发送播放命令，而是切换到直播列表并请求解析。
2. 解析结果保持频道名称和顺序，且完整本地路径不进入结构化日志。
3. 单路本地 HLS 回退为一个本地媒体项并发送 Open，不重复进入清单解析。
4. 普通媒体与清单混合多选被拒绝，不产生部分追加或错误播放。
5. 本地清单文件保留在本地列表，重复打开不会重复添加。

`MainWindowTest::reparsesLegacyLocalPlaylistItemsOnActivation` 使用旧版持久化快照恢复本地
M3U8 条目，确认双击后不向播放内核发送 Open，而是解析清单并切换到直播列表。
