# MediaHub 阶段 1 测试

> 状态：已完成（2026-08-03）。
>
> 测试范围：VLC 3.0.21 win64 SDK 的下载校验、结构检查、CMake 接入，以及
> libVLC 实例在 Debug 和 Release 中的创建、版本读取与释放。

## 1. 实现边界

阶段 1 实际完成以下内容：

- 从 VideoLAN 官方站点下载 `vlc-3.0.21-win64.7z` 和官方 SHA-256 文件。
- 把 SDK 解压到源码目录外的 `C:\SDK\vlc-3.0.21`。
- 使用缓存变量 `MEDIAHUB_VLC_ROOT` 接收本机 SDK 路径，不在源码中硬编码路径。
- 配置时检查头文件、两个导入库、两个运行库和插件目录是否完整。
- 建立 `MediaHub::LibVLC` 接入目标和 `MediaHubVlcProbe.exe` 验证程序。
- 构建后把两个 libVLC DLL 和完整插件目录部署到探针所在目录。
- 用 CTest 自动运行探针并检查输出的版本号。

本阶段没有创建 Qt 窗口，没有建立正式播放内核接口，也没有实现打开文件、解码、
音视频输出、播放控制或网络功能。当前探针不是最终的 `MediaHub.exe`。

## 6. 验证命令与实际结果

以下配置和构建命令在 VS 2022 x64 开发者环境中执行。

Debug：

```powershell
cmake -S . -B cmake-build-debug -G Ninja `
      -DCMAKE_BUILD_TYPE=Debug `
      -DCMAKE_PREFIX_PATH="C:/Qt/Qt5.14.2/5.14.2/msvc2017_64" `
      -DMEDIAHUB_VLC_ROOT="C:/SDK/vlc-3.0.21"
cmake --build cmake-build-debug
.\cmake-build-debug\MediaHubVlcProbe.exe
ctest --test-dir cmake-build-debug --output-on-failure
```

Release：

```powershell
cmake -S . -B cmake-build-release -G Ninja `
      -DCMAKE_BUILD_TYPE=Release `
      -DCMAKE_PREFIX_PATH="C:/Qt/Qt5.14.2/5.14.2/msvc2017_64" `
      -DMEDIAHUB_VLC_ROOT="C:/SDK/vlc-3.0.21"
cmake --build cmake-build-release
.\cmake-build-release\MediaHubVlcProbe.exe
ctest --test-dir cmake-build-release --output-on-failure
```

失败路径：

```powershell
cmake -S . -B cmake-build-validation-missing -G Ninja
cmake -S . -B cmake-build-validation-invalid -G Ninja `
      -DMEDIAHUB_VLC_ROOT="C:/SDK/not-present"
```

实际结果：

- Debug 和 Release 均成功生成 `MediaHubVlcProbe.exe`。
- 两种配置直接运行都输出 `libVLC version: 3.0.21 Vetinari`，退出码均为 `0`。
- Debug 最终 CTest 为 1/1 通过，总耗时 0.46 秒。
- Release 最终 CTest 为 1/1 通过，总耗时 0.44 秒。
- 两种构建目录都部署了 `libvlc.dll`、`libvlccore.dll` 和 367 个插件文件。
- 两次直接运行结束后，`MediaHubVlcProbe` 残留进程数均为 0。
- 缺少变量和错误目录两种配置都返回非零退出码，并显示预期的英文诊断。
- 没有跳过项。

## 8. 已知问题

- 阶段 1 只有依赖探针，没有最终播放器程序，这是计划内边界。
- VLC 官方发行包包含大量不同许可证的插件；对外发布前仍需逐项确认或裁剪，阶段
  12 再做发布合规复核。
- 阶段完成后已配置 Gitee SSH 远程仓库；按最新协作约定，本阶段测试和文档通过后
  自动创建本地提交，但不自动推送。

## 9. 阶段结论

阶段 1 实现验收通过：

- 官方压缩包来源、大小和 SHA-256 均已记录，校验一致。
- libVLC SDK 的编译与运行内容完整。
- Debug 和 Release 都能链接、初始化、读取版本并正常释放 libVLC。
- CMake 能拒绝缺失或错误的 SDK 配置，项目源码不包含本机绝对路径。
- CTest 能重复验证最小运行链路，构建后没有残留进程。

可以进入阶段 2，前提是继续保持“只建立工程骨架、不提前实现播放业务”的范围。
