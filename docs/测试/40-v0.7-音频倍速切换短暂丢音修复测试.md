# v0.7 音频倍速切换短暂丢音修复测试

## 1. 问题

用户反馈播放本地音乐时从 `1.0×` 切换到 `2.0×`，切换瞬间会丢失约一秒音频，随后才恢复为正常的两倍速；该问题此前修复过又再次出现。

## 2. 修复范围

- 纯音频切换倍率时保留原位置重建时钟，避免 `scaletempo` 刷新后时间线漂移；本地音频主
  播放器和波形分析播放器统一设置为 `:file-caching=30`，缩短刷新后重新建立输入队列的
  等待窗口。
- 低缓存配置避免 `set_rate` 后仍等待默认约 1 秒的文件缓存，消除可听见的空洞；视频仍不执行音频式 Seek。
- 本地视频仍保留原有 `:file-caching=30` 和“不因切速 Seek”的行为；网络媒体逻辑不变。

## 3. 自动化回归

| 用例 | 验证内容 | 结果 |
|---|---|---|
| 倍速长空档回归 | 运行时生成 8 秒音频，播放后切换到 `2.0×`；波形事件间隔不超过 500ms | 通过 |
| 音频媒体选项 | 主/分析播放器均提交 `:no-video`，并各提交一次 `:file-caching=30` | 通过 |
| `integration.VlcPlayerEngineTest.*` | libVLC 集成测试全量回归 | `23/23` 通过 |

验证命令：

```powershell
ctest --test-dir cmake-build-debug -R "integration\\.(VlcEventMappingTest|VlcPlayerEngineTest)" --output-on-failure
```

## 4. 人工门禁

用户使用本轮 Debug 构建播放真实本地 MP3，确认 `1.0× -> 2.0×` 无约一秒丢音，并同意更新
正式包、提交和推送。恢复 `1.0×` 已由自动化内核回归覆盖；正式 Release 包随后以 `test.mp3`
完成 5 秒隔离播放和正常关闭。
