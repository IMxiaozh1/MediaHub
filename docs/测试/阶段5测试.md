# MediaHub 阶段 5 测试

> 状态：已完成（2026-08-03）。
>
> 测试范围：正式主窗口、`PlayerPresenter`、`EngineEventBridge`、真实内核组装、
> GUI 主线程投递、基本播放控制、关闭顺序与阶段 1 至阶段 4 全量回归。

## 1. 实现边界

阶段 5 实际完成以下内容：

- 建立带文件菜单、打开按钮、播放、暂停、停止、媒体名称、状态和错误提示的主窗口。
- `MainWindow` 只收集输入和渲染 `PlayerViewState`，不判断播放操作是否合法。
- `PlayerPresenter` 持有核心接口引用，集中驱动状态机和全部控件启用规则。
- 打开本地文件后等待 `Opening` 事件，再排队发起播放，避免失败路径重复请求播放。
- `EngineEventBridge` 实现 `PlayerEventListener`，转发状态、位置、时长、结束和错误。
- 桥接信号与 presenter 强制使用 `Qt::QueuedConnection`，同线程回调也不会同步重入。
- 在 `main.cpp` 构造真实 `VlcPlayerEngine` 并完成组装，具体内核没有进入 GUI 支持库。
- 关闭窗口时先停用桥接、断开监听，再请求停止；迟到事件不会访问正在销毁的控件。
- 正式 `MediaHub.exe` 构建后同时部署 Qt 与 libVLC 运行时。

本阶段没有建立视频输出控件、进度条、音量、播放列表、拖放或命令行文件入口。
视频画面从阶段 6 接入，进度与音量从阶段 7 接入，网络输入仍留到 v0.2。

## 3. 线程与依赖边界

```text
libVLC 事件线程
        │ PlayerEventListener 值类型回调
        v
EngineEventBridge::on*（只检查关闭标记并发出信号）
        │ Qt::QueuedConnection
        v
GUI 主线程：PlayerPresenter → PlaybackStateMachine → MainWindow
```

五类自定义值类型在桥接构造时注册到 Qt 元类型系统。自动化从 `std::thread` 发出
内核事件，最终记录的 presenter 处理线程与 `QApplication` 主线程相同。

依赖关系保持为：

```text
mediahub_gui ──> mediahub_engine_vlc ──> libVLC
      │
      └──> mediahub_gui_support ──> mediahub_core + Qt5::Widgets
```

`mediahub_gui_support` 不链接 libVLC；除 `main.cpp` 外的 GUI 文件不包含或引用具体
内核类型。核心层仍可在完全不查找 Qt 和 libVLC 的模式下独立构建。

## 5. 构建、回归与应用生命周期

Debug：

```powershell
cmake --build cmake-build-debug
ctest --test-dir cmake-build-debug --output-on-failure
```

Release 使用 `cmake-build-release` 执行相同命令。核心独立回归使用
`cmake-build-core-debug`，无测试构建使用 `cmake-build-no-tests`。

最终结果：

- Debug 全量 CTest 为 23/23 通过，最终总耗时 5.70 秒。
- Release 全量 CTest 为 23/23 通过，最终总耗时 5.60 秒。
- Qt Test 内部 11/11 通过，0 失败、0 跳过、0 Qt 警告，耗时 264 毫秒。
- `MEDIAHUB_CORE_ONLY=ON` 为 13/13 通过，最终总耗时 0.32 秒，不查找 Qt 或
  libVLC。
- `MEDIAHUB_BUILD_TESTS=OFF` 成功构建正式 GUI，CTest 报告 `Total Tests: 0`。
- Debug 与 Release 编译没有项目源码警告。
- Release `MediaHub.exe` 取得非零原生窗口句柄，窗口处于响应状态，标题为
  `MediaHub`；正常关闭后返回 `0`。
- 正式 GUI 输出目录包含 libVLC 两个 DLL 与完整 `plugins/` 目录。
- 测试和应用退出后没有 MediaHub、探针或测试程序残留进程。

应用生命周期脚本轮询“句柄非零且窗口响应”的明确谓词，最多等待 5 秒；关闭时发送
正常窗口关闭消息并设置 5 秒退出上限，没有强制终止进程。

## 6. 首轮问题与修复记录

第一次从普通 PowerShell 触发增量构建时，MSVC 因开发环境未加载而找不到
`type_traits`、`chrono` 等标准库头文件。代码没有因此修改；改用项目文档规定的
VS 2022 `VsDevCmd.bat` 初始化 x64 环境后，源码一次编译通过且没有编译器警告。

展开 Qt Test 完整日志后发现 Qt 5 不支持样式表中的 `letter-spacing`，并且离屏
插件没有自动找到字体目录。实现删除不受支持属性，CTest 在 Windows 上为离屏测试
设置系统字体目录；再次执行后 11/11 通过且没有 `QWARN`、`QDEBUG` 或失败记录。
