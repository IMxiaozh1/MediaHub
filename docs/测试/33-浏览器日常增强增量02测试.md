# 浏览器日常增强增量 02 测试

> 范围：阶段二“Bing 首页、主动新标签、标准快捷键、网页内查找和标签右键菜单”。
>
> 状态：阶段二生产实现、BrowserPage、非 Runtime 自动化和构建矩阵已通过；真实
> Runtime 仍受当前环境阻塞，原生内容区交互、DPI 和退出进程人工验收仍未完成。

## 1. 验证目标

1. 首次打开网页页只导航一次 Bing，主动新标签默认打开 Bing；网站弹窗、历史、收藏和
   复制标签保留各自来源地址。
2. `Ctrl+T`、`Ctrl+W`、`Ctrl+Tab`、`Ctrl+Shift+Tab` 在 Qt 控件和 WebView2 原生内容区
   焦点下语义一致，关闭或切换期间的迟到动作不会命中其他标签。
3. 关闭最后一个标签时复用存活 Controller 打开 Bing，不关闭主窗口、不产生假标签；
   清除网页数据后仍停留在 `about:blank`。
4. `Ctrl+F` 只查找当前标签，支持前后跳转、结果计数和 `Esc` 关闭；查找能力缺失时安全
   降级，不注入脚本。
5. 标签右键菜单按稳定 `tabId` 操作目标标签，批量关闭、复制、静音和创建失败边界可预测。
6. 完整 URL、标题、查找词、剪贴板内容、Profile 路径和网页凭据不进入日志或测试证据。

至少执行：

```text
cmake --build cmake-build-debug
ctest --test-dir cmake-build-debug -R "gui.browser_page|gui.stage10_coverage" --output-on-failure
ctest --test-dir cmake-build-debug -R "webview2" --output-on-failure
```

本轮已实际尝试 `integration.webview2.initialization`，Runtime 定向程序结果为
`42 passed, 10 failed`。十项失败均发生在 Controller 未进入 Ready，最终固定失败为
`invalid_initialization_input`，HRESULT `-2147024809`。该结果必须记录为当前
环境/Runtime 阻塞，Probe 能发现 Runtime 不等于 Controller、查找或媒体场景已通过，
也不能沿用阶段一或 v0.6 旧证据替代本次结果。

2026-08-14 使用本轮最新 Debug 构建再次执行完整 WebView2 测试程序，结果为
`48 passed, 9 failed, 0 skipped`。本次 Controller 已能启动并通过非 Runtime/初始化契约，
但环回页面行为从第一个资料场景开始出现 `error=1`：持久化和清除、共享标签/弹窗、权限、
下载、上传及重定向场景未完成。该结果证明当前机器的 Runtime/渲染环境仍不足以作为
本轮真实网页功能通过证据，不覆盖 `45/45` 非 Runtime 通过结果，也不宣称产品行为已在
真实网页中验证。

用户在普通 Windows PowerShell 使用修复临时 Profile 清理后的重建 Debug
程序复跑完整套件，最终为 `57 passed, 0 failed, 0 skipped, 0 blacklisted`，
耗时 12027 ms。Profile、环回重定向、共享标签/弹窗、权限、下载和受控媒体页
全部取得真实 Runtime 通过证据。

排除真实 Controller 初始化项后，Debug CTest `90/90` 通过（最新全目标使用 `--parallel 1`），Release CTest
`90/90` 通过（使用 `--parallel 1`）。Debug 并行 4 曾因 PDB 文件锁失败，Release 并行构建曾因 `windeployqt` 部署 DLL 文件锁失败，
改用 `--parallel 1` 后成功。core-only `52/52` 通过（1.19 秒）；同时关闭
`BUILD_TESTING` 和 `MEDIAHUB_BUILD_TESTS` 的 Release 构建成功，`ctest -N` 为 0。
架构扫描、敏感信息扫描、UI 定向 `3/3` 和 `git diff --check` 通过，后者仅有 LF/CRLF 提示。
