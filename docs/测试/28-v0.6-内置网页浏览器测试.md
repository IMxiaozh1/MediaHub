# MediaHub v0.6 内置网页浏览器测试

> 状态：实施中，已完成 SDK、Runtime 探针、浏览器抽象、地址策略和真实后端初始化验证。
>
> 测试范围：第三展示模式、WebView2 导航、持久登录资料、安全策略、网页媒体、
> 全屏、生命周期、构建隔离和本地交付。

## 1. 测试原则

1. GUI 主流程使用 `FakeBrowserBackend`，不依赖 Edge Runtime、公共网络或真实账号。
2. 真实 WebView2 集成测试只访问 `127.0.0.1` 受控 HTTP 服务，Profile 使用运行时
   临时目录并由 RAII 清理。
3. 公共网站登录、视频画面、声音、DRM 和网站兼容性只做人工验收，不伪装为自动化。
4. 测试和日志不得包含账号、密码、Cookie、令牌、真实浏览记录或个人 Profile 路径。
5. 不提交有版权音视频。受控网页使用脚本生成的静态内容或运行时生成的无版权媒体。
6. 异步测试等待明确事件并设超时上限，禁止固定时长 `sleep` 或无条件 `qWait`。

## 2. 计划自动化场景

### 2.1 模式与原生播放协调

- 第三个“网页”入口存在，往返后本地/直播列表的条目、当前项和滚动位置不变。
- 进入网页时，Playing、Opening 和 Buffering 分别只产生一次暂停请求。
- 已暂停、已停止、播放结束或空闲时进入网页不产生多余内核命令。
- 离开网页不会自动继续 libVLC；网页后端收到静音和挂起请求。
- 返回网页恢复浏览器后端，但不发送脚本或模拟网页播放点击。
- 网页模式下原生进度、倍速、跳转、播放模式和全屏控件不可误操作。

### 2.2 地址栏与导航

- 空白输入不导航，无协议域名规范化为 HTTPS。
- 合法 HTTP/HTTPS 地址保持主机、端口、路径、查询和片段供当前页面展示。
- 用户明确选择的 `file:` 可以只读打开，网页后台发起的本地文件扩大访问被拒绝。
- 地址栏 `javascript:`、`data:` 和 WebView2 不支持的内部页被拒绝，但网站自身脚本、
  Data URL 子资源和 `blob:` 媒体正常工作。
- 外部应用协议展示目标并确认；取消时不启动应用，确认时只路由一次。
- 后退、前进、刷新/停止、主页命令准确路由到假后端。
- `Ctrl+L`、`Alt+左/右`、`Ctrl+R` 和 `F5` 只在正确窗口范围内生效。
- 导航状态变化会更新地址栏、标题、载入提示和按钮启用状态。
- 旧导航的迟到成功或失败事件不能覆盖当前页面状态。

### 2.3 初始化与错误

- WebView2 初始化成功后移除覆盖层并允许导航。
- Runtime 缺失、Profile 不可用、COM 模式错误和 Controller 创建失败分别显示稳定
  中文提示，主窗口和原生播放器仍可使用。
- 初始化中切换页面或关闭窗口不会重复创建后端，也不会访问已销毁控件。
- resize 和 DPI 连续变化只向后端提交有效的最新客户区尺寸。
- TLS 证书错误可以返回安全页或仅对当前会话继续，关闭后临时例外消失。
- 错误日志只有类别、HRESULT 数值和请求代次，不含完整 URL 或本地路径。

### 2.4 用户资料与清除

- 主页面与登录弹窗使用同一 Profile 标识。
- 正常重建浏览器后端时继续使用相同 MediaHub 用户数据目录。
- 测试 Profile 中设置的 Cookie 和 LocalStorage 在重建后仍可读取。
- Edge 个人资料目录从不作为 MediaHub Profile 输入。
- 密码自动保存关闭，MediaHub 配置快照中没有账号、密码、Cookie 或令牌字段。
- 取消“清除网页数据”不会调用后端；确认后只调用一次 Profile 清除命令。
- 清除成功后 Cookie、LocalStorage、IndexedDB 和缓存不可继续使用，并回到内部空白页。
- 清除失败显示可重试错误，不递归删除 Profile 目录。

### 2.5 弹窗、权限与下载

- 登录弹窗请求取得共享 Profile 的子浏览器，关闭后主页面继续存在。
- 同时最多创建 3 个子窗口，第 4 个请求被拒绝并显示说明。
- 主窗口关闭后不再接受新弹窗，现有子窗口先于主 Controller 释放。
- 摄像头、麦克风、位置、通知、屏幕捕获和剪贴板读取都显示真实来源和权限类型。
- “允许一次”“对本站记住”“拒绝”和关闭提示框分别准确回复原权限请求。
- 已记住权限只作用于对应来源，撤销或清除网页数据后重新询问。
- 下载可取消或选择目标，进度、完成和失败状态准确；同名目标不能静默覆盖。
- 文件上传只把系统选择器中当次明确选择的文件交给网页，取消时网页得不到路径。
- 权限、下载和弹窗日志不包含目标完整地址或网页内容。

### 2.6 网页全屏与快捷键隔离

- 网页全屏进入时隐藏 MediaHub 页头、侧栏和网页工具栏，只保留网页内容。
- `Esc` 先退出网页全屏，不触发现有 libVLC 全屏、停止或播放快捷键。
- 网页退出全屏后恢复此前模式、窗口状态和响应式尺寸。
- 网页输入框获得焦点时，空格和方向键由网页处理，不触发原生播放快捷键。
- 网页页以外的快捷键行为保持 v0.5 语义。

### 2.7 生命周期与关闭顺序

- 关闭后端前先清空事件监听器并递增请求代次。
- 事件令牌、弹窗、主 Controller、Environment 和 COM 生命周期按设计顺序释放。
- 关闭后到达的初始化、导航、全屏和清除数据回调全部丢弃。
- 浏览器关闭不会等待 WebView2 子进程，不阻塞 Qt 主线程。
- 有界检查确认 MediaHub 进程退出；测试不得结束系统 Edge 或其他程序的 WebView2
  进程。

## 3. 真实 WebView2 集成测试

计划新增独立的 Windows 集成测试目标，使用本机 Evergreen Runtime 和临时 Profile。
受控 HTTP 服务提供以下页面：

1. 静态标题、链接和重定向，用于导航、前进和后退。
2. 设置与读取 Cookie、LocalStorage、IndexedDB 的页面，用于重建和清除验证。
3. 调用 `window.open()` 的页面，用于共享 Profile 和弹窗生命周期。
4. 请求敏感权限、下载和上传的页面，用于确认每种用户决定和文件边界。
5. 运行时生成的短无版权媒体页面，用于确认 HTML5 video 事件和网页全屏事件。
6. 本机自签名 HTTPS 页面，用于确认返回安全页和当前会话临时例外。

集成测试满足以下限制：

- 服务只监听 `127.0.0.1` 随机端口，不访问公网。
- 每个等待都绑定导航、DOM 或 WebView2 完成事件并有明确超时。
- Profile 只位于测试临时目录，测试开始和结束时不扫描用户浏览器目录。
- 声音和画面效果不作为自动化结论；自动化只确认事件、状态和资源释放。
- Runtime 缺失时该目标应给出明确环境结果；完整交付回归不得静默跳过。

## 6. 网站兼容性记录规则

测试结果按能力而不是网站品牌作普遍承诺：

- “通过”只说明该次环境、Runtime、网站和账号组合可用。
- 网站拒绝 WebView2、DRM 不可用或地区限制时，记录为兼容性限制，不绕过限制。
- 网站自身宕机、账号风控或网络不稳定不归类为 MediaHub 自动化失败，但必须复核主
  窗口仍响应、错误可恢复且没有敏感日志。
- 不在仓库记录真实账号、付费状态、私人页面、完整访问地址或版权内容截图。

Task 6 先新增独立 `mediahub_webview2_tests`，首次修正测试目标 Qt Widgets 链接后，

实现后新增隔离的 `mediahub_browser_webview2` 静态目标；公开头仅暴露 PImpl，COM 与
WebView2 SDK 类型只存在于适配器实现。环境和 Controller 在 GUI STA 异步创建，所有
完成处理器检查生命周期令牌、生命周期序号和请求代次；导航用 WebView2 navigationId
保存代次，旧导航取消回调不会覆盖新导航。事件订阅由 RAII 撤销，关闭顺序为撤销事件、
关闭 Controller、释放 WebView/Controller/Environment 和 COM 引用，不等待子进程。

本阶段启用网页脚本和普通上下文菜单，关闭 DevTools、密码保存和常规自动填充；没有
Host Object、文档启动脚本或脚本注入。生产组合根使用
`AppLocalDataLocation/WebView2/Profile-v1`，日志只记录稳定事件名和 HRESULT，不记录
完整 URL 或 Profile 路径。使用指定 VS `vcvars64.bat` 环境构建
`mediahub_webview2_tests mediahub_gui` 成功；最终
`ctest --test-dir cmake-build-debug -R "webview2" --output-on-failure` 为 `2/2`
通过，Runtime 探针 0.02 秒、真实初始化 7.16 秒，总用时 7.22 秒。GUI 定向回归
`gui.stage10_coverage|gui.browser_page` 为 `2/2` 通过，总用时 31.99 秒。权限、下载、
弹窗和环回站点持久数据验证仍按 Task 7 至 Task 9 保持未完成。提交前组合复验覆盖
Runtime 探针、真实初始化和两项 GUI 回归，为 `4/4` 通过，总用时 39.65 秒。

Task 6 规格复核发现：仅保留 `answer*` 空实现不能阻止 WebView2 对未订阅敏感事件采用
默认行为。修复先增加结构门禁测试，要求权限、下载、证书错误、外部 URI 和新窗口五类
处理器都在 ready 前注册；RED 稳定失败于 `registerPermissionRequested()` 缺失，定向
结果为 `2` 项通过、`1` 项失败。实现随后对基础 PermissionRequested 立即设置 DENY，
通过 `ICoreWebView2_4` 取消并接管 DownloadStarting，通过 `ICoreWebView2_14` 取消
证书错误，通过 `ICoreWebView2_18` 取消外部 URI，并接管拒绝 NewWindowRequested。
任一版本接口查询或事件注册失败都会终止初始化、撤销已有订阅并关闭 Controller，不能
进入 ready。五类订阅全部由 `EventRegistration` 管理，并在 Controller Close 前于创建
COM 对象的 GUI STA 撤销；对应函数已补充调用线程和回调线程约束。

GREEN 阶段结构测试通过，真实 Evergreen Runtime 初始化同时证明 `_4`、`_14`、`_18`
及全部事件注册可用；测试程序内部 `4/4` 通过（6.717 秒、无 warning）。最终组合 CTest
覆盖 Runtime 探针、真实初始化、安全门禁和两项 GUI 回归，为 `4/4` 通过，总用时
36.87 秒。Task 6 不执行可能在 RED 阶段写入用户下载目录的端到端下载测试；受控环回
站点、下载目标和系统副作用验证仍由 Task 7 与 Task 9 完成，此处不据结构测试宣称这些
端到端场景已经通过。

Task 6 提交后的代码质量复核又发现两个异步关联缺陷和一项测试假绿。挂起实现原先在
`TrySuspend` 未完成时立即执行恢复，后到的挂起完成可能把已重新激活的网页挂起；现在
使用独立纯状态协调器维护 desired、actual、in-flight 和 request serial。恢复请求会在
挂起完成前保持静音，确认确实挂起后只发一次纠正 `Resume`，且仅在 `Resume` 成功后
解除强制静音；HRESULT 失败、`BOOL` 为 false、重复请求、旧 serial 和生命周期失效均
