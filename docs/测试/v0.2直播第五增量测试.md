# MediaHub v0.2 直播第五增量测试

> 状态：纯核心 M3U 与频道模型实现、自动化和构建矩阵全部通过（2026-08-06）。
>
> 范围：`LiveChannel` / `LiveChannelLibrary`、UTF-8 M3U 解析与序列化、结构化
> 诊断、重复统计、往返一致性及既有功能回归。本增量没有可见页面变化，无需人工验收。

## 1. 实现边界

- 新增纯 C++ 频道和频道库值类型，不依赖 Qt、libVLC、文件系统或网络。
- 解析器接受 UTF-8 BOM、CRLF/LF、中文、普通注释及第一版支持的六个元数据字段。
- 缺少分类的频道规范化为“未分类”；频道顺序保持与来源文件一致。
- 地址继续复用 `validateNetworkUrl`，不探测直播是否在线。
- 完全相同的地址只接受第一次出现；重复数量与其他跳过数量分开统计。
- 诊断只携带行号和错误类别，不复制完整直播 URL，避免后续日志或提示意外泄漏凭据。
- 序列化发现空名称、非法或重复地址、字段换行注入时显式失败并返回空内容，调用方
  不会拿到可误写入磁盘的半成品。

## 2. 新增自动化覆盖

新增 17 个 GoogleTest 场景：

| 类别 | 覆盖内容 |
|---|---|
| 正常解析 | 中文、频道顺序、分类、`tvg-id`、`tvg-name`、`tvg-logo`、`x-tvg-url` |
| 文本兼容 | UTF-8 BOM、CRLF/LF、空行、普通注释、缺省分类 |
| 元数据边界 | 名称和属性中的逗号、引号与反斜杠转义 |
| 错误恢复 | 缺文件头、孤立地址、损坏 `#EXTINF`、缺名称、缺地址、非法协议 |
| 重复规则 | 相同地址跳过并单独统计；相同名称但不同地址继续保留 |
| 安全生成 | 空库、稳定字段顺序、非法模型拒绝、换行注入拒绝 |
| 往返一致性 | “模型 -> 生成 -> 再解析”保持全部支持字段和频道顺序 |

新增测试自身不读取外部 M3U，不使用真实频道地址，也不访问网络。

## 4. GUI 测试隔离修复

第一次 Debug 全量回归为 `66/67`：既有歌词校准测试把 `QSettings` 写入真实用户配置
目录，受限环境无法持久化后，重新加载得到默认值。测试套件现使用 `QTemporaryDir`
重定向 `QSettings::IniFormat` 的用户范围路径，不再读取、写入或污染真实 MediaHub
歌词校准。修复后 GUI 套件 `60/60`，Debug 和 Release 全量回归均通过；产品运行时
设置路径未改变。

## 5. 结论与下一步

第五增量满足规划中的纯核心通过条件，可以作为后续本地文件服务和页面模型的稳定
输入边界。下一增量只实现默认 `channels.m3u`、分类/频道页面以及添加、编辑、删除、
排序和原子保存；频道选择播放、外部导入/重新加载/导出仍分别留在后续增量。
