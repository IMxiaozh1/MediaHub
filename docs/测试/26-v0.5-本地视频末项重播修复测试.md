# MediaHub v0.5 本地视频末项重播修复测试

> 日期：2026-08-11。
>
> 状态：实现、Debug/Release 自动化、最终 Release 构建和真实视频人工验收全部通过。

## 1. 问题与根因

顺序播放到本地列表最后一个视频并自然结束后，点击播放按钮时进度会重新移动，但视频
区域没有画面；再次双击列表项后画面才能恢复。

Presenter 已按设计重新打开当前媒体、创建新的原生视频子窗口，并执行
Open -> Play -> Seek(0)。缺失环节位于 libVLC 内核：VLC 3 在发出 `EndReached`
并进入 `Ended`、`Stopped` 或 `NothingSpecial` 后，旧视频输出 `vout` 仍可能保留。
旧实现根据终态跳过 `libvlc_media_player_stop()`，随后直接更换媒体和 HWND，因此时间线
能够重新运行，但新窗口没有恢复视频输出。再次双击时播放器尚在运行，旧路径会执行
Stop，所以画面反而能够恢复。

## 2. 修复策略

- 本地播放器只要仍绑定旧媒体，在更换媒体或视频 HWND 前就无条件显式 Stop，不再根据
  libVLC 的终态快照跳过清理。
- 保持现有重播顺序：创建新的非空原生子窗口，打开当前末项，收到打开确认后 Play，
  进入 Playing 后 Seek(0)。
- 继续在旧 HWND 已不被播放器引用后才通知 GUI 销毁，避免重新引入独立 VLC 窗口或
  失效句柄。

## 3. 自动化证据

新增 libVLC 集成用例
`StopsEndedLocalPlayerBeforeApplyingReplayVideoSurface`：修复前稳定证明旧播放器没有
Stop，重播 HWND 在旧 vout 收尾前被应用；修复后确认 Stop 先完成，再应用不同的重播
句柄，并释放旧句柄。

新增 GUI 用例 `replaysSequentialLastVideoOnFreshSurfaceAfterNaturalEnd`，覆盖：

1. 顺序播放定位到列表最后一个本地视频。
2. 自然结束后保持最后一项选中，不自动循环。
3. 点击播放创建与旧句柄不同的非空 HWND。
4. 命令顺序为 Open -> Play -> Seek(0)，视频展示状态重新激活。

真实像素输出无法由哑视频自动化可靠判断，因此画面恢复仍由人工验收确认，不虚构自动
化覆盖。
