# MediaHub v0.2 直播第六与第七增量测试

> 状态：实现和自动化已完成（2026-08-06），卡顿源连续切换修复已通过用户复验；
> 页面和真实直播音画继续人工验收；直播右键菜单（含停止、标记和会话内收藏）已通过
> 用户实机验收。
>
> 范围：远程 M3U/M3U8 清单文本读取、相对地址解析、本地/直播双列表、直播条目播放
> 接入、资源限制、失败保留、隐私边界和既有功能回归。

## 1. 实现边界

- `LivePlaylistService` 只读取用户提供的远程清单文本，不下载、缓存或保存 MP3、MP4
  及其他音视频文件。
- 清单 URL 只允许 HTTP/HTTPS；清单条目继续使用既有八种网络协议白名单。
- 请求从 GUI 主线程发起，Windows 版在线程池使用系统 WinHTTP 读取，不依赖当前 Qt
  5.14 未部署的 OpenSSL 1.1；设置 10 秒超时、5 次安全重定向、2 MiB 正文和 5000
  个有效条目上限，新请求取消旧请求并隔离迟到结果。
- Cookie 读取和保存均被禁用；HTTPS 不允许降级跳转到 HTTP，非 HTTP(S) 重定向被
  拒绝。
- 只接受有效 UTF-8；相对条目以最终响应 URL 补全，再交给纯核心解析器校验和去重。
- 普通 HLS 变体或媒体分片清单不会作为频道通讯录展示；HLS 控制标签按行首结构识别，
  不会因频道名称或元数据中的相似文本误判。
- 新清单成功后整体替换直播列表；任何读取或解析失败都保留上一次有效直播列表。
- 本地文件只进入本地列表；单直播 URL 和远程清单条目只进入直播列表。直播列表
  不提供分类、重命名、排序和删除。
- 直播右键菜单仅含“播放/暂停”、“停止”、“标记/取消标记”和“收藏/取消收藏”。
  停止只对当前可停止的直播源启用，其他条目置灰。标记状态只在本次会话内保存，条目
  显示“【不可用】”、浅红警示背景和加粗文字，悬停提示右键取消标记；同时置灰且不可
  选择或播放，标记当前源时停止播放。
- 收藏同样按直播源地址在会话内识别，以“★”前缀显示，不改变播放能力或顺序。
- 标记、取消标记、收藏与取消收藏只发送目标行数据变化，不重置直播列表模型，滚动
  位置保持不变。
- “定位正在播放”按当前播放源地址查找行，不依赖列表当前滚动或界面选中位置；连接、
  缓冲、播放和暂停时可用，停止、源缺失或当前源被标记时禁用。
- 右键单击只弹出菜单；右键双击被视图事件边界拦截，不得发送打开请求。
- `Ctrl+L` 识别 `.m3u`/`.m3u8`：`.m3u` 始终作为频道清单且失败时绝不新增为单路
  直播；有歧义的 `.m3u8` 仅在检测到普通 HLS 控制标签后回退到单路直播播放。

## 2. 自动化覆盖

核心 GoogleTest 新增 2 个相对地址场景，M3U 定向覆盖增至 19 个：

| 类别 | 覆盖内容 |
|---|---|
| 相对地址 | 调用方补全后通过既有协议校验；补全失败时结构化跳过 |
| 重复规则 | 两个相对地址补全为同一绝对地址后只保留第一次 |

独立 Qt Test 使用本机临时 HTTP 服务覆盖 Windows 产品读取路径，不访问公网，不写入
真实用户设置：

| 类别 | 覆盖内容 |
|---|---|
| 正常读取 | 最终重定向基址、中文名称、来源顺序、相对地址、重复和跳过统计 |
| 格式边界 | 非 M3U、空清单、非法 UTF-8、普通 HLS 媒体清单 |
| 资源边界 | 正文过大、条目过多、超时、HTTP 错误 |
| 重定向 | 次数上限、非 HTTP(S) 不安全目标 |
| 并发隔离 | 等待旧请求真正到达后发新请求，旧响应迟到也不能覆盖新结果 |

主窗口 Qt Test 新增页面和 Presenter 回归：

- 本地/直播列表始终分开，标签切换不发送停止或重新打开命令。
- 单直播 URL 只进入直播列表；本地列表保留扩展多选和右键操作，直播列表为只读单选。
- 切到本地列表后刷新当前直播，仍重开实际播放的直播地址，不误用本地选中项。
- 远程清单按来源顺序原子替换；分类不显示；失败时旧直播列表保持不变。
- 双击直播条目生成带原名称的 `NetworkStream`，复用既有网络播放链路。
- 直播右键单击不发送打开请求；右键双击不播放；菜单固定为四个操作，播放/暂停、
  停止、标记和收藏按目标源状态动态切换或启用。
- 标记项提供独立数据角色，移除启用和可选标志；右键播放动作禁用，直接触发双击
  也不会重新打开标记源；显示前缀、前景、背景、粗体和悬停提示角色均有断言，取消
  标记后恢复。
- 清单播放期间刷新为不同条目时按源身份判断右键状态，不因相同行号误显示“暂停”。
- 收藏角色和“★”显示前缀支持往返切换，收藏不发送打开、停止等内核命令。
- 40 项长列表在中部标记或收藏后会在同步和延迟刷新后恢复原滚动值；从列表顶部点击
  “定位正在播放”可跳转并选中第 40 项当前源。标记当前播放源后定位按钮立即禁用，
  不等待停止事件。
- 带凭据和查询参数的清单 URL 不进入状态文案和日志。
- `Ctrl+L` 清单 URL 不发送播放命令而是展开列表；`.m3u` 失败不回退，单路 HLS
  `.m3u8` 检测后才回退为直接播放。

首次人工验收发现，卡顿直播连续切换时会出现无法由 MediaHub 主窗口关闭的独立视频
窗口。第一次修正删除旧播放器的空 HWND 并保留原嵌入句柄，自动化通过但真实复验
仍能弹窗；第二次为每个旧播放器创建不可见的专用 HWND，先迁移输出并关闭音视频轨，
确认后才让新播放器绑定主画面。句柄观察回归验证了 A→B→C 连续两次“专用回收
句柄→主画面句柄”的顺序，且全程没有提交空句柄，但真实复验仍会弹窗。

第二次复验时的原生窗口检查确认，弹窗是父窗口和所有者均为空的顶层
`VLC video main`，内部包含 `VLC video output`；此时专用隐藏回收窗口已经销毁，说明
弹窗属于当前替换播放器而非旧播放器。Qt 视频宿主 HWND 同时具备 libVLC 要求的
`WS_CLIPCHILDREN` 样式。高概率原因因此收敛到每次直播切换都创建新的 libVLC
实例：后创建实例的 vout 会回退到自建顶层窗口。

第三次修正保留旧播放器隐藏 HWND 回收机制，但直播刷新和直播间切换只替换播放器并
复用当前主实例；仅在直播切回本地媒体时创建新实例。实例创建观察器确认 A→B→C
主播放与音频分析共维持 2 个实例，直播切本地生成 WAV 达到 3 个实例。用户复验仍
发现独立窗口：旧画面继续冻结在 MediaHub 内，最后才显示播放结束；新源则在独立
窗口播放。

第三次失败现场的原生窗口枚举同时观察到两套可见 vout：旧 `VLC video main` 仍是
MediaHub 视频宿主的子窗口，新 `VLC video main` 已成为父窗口和所有者均为空的桌面
顶层窗口。证据表明，对正在输出的旧播放器调用 `set_hwnd` 只改变后续输出目标，不能
迁移已经创建的 vout；在旧 vout 完全退出前启动新播放器才是窗口冲突的直接原因。

第四次修正删除无效的隐藏 HWND 迁移，改为在现有内核控制线程上关闭旧播放器音视频
轨、同步等待 `stop` 返回并释放最后一个播放器引用，之后才把新播放器绑定到 MediaHub
主画面。等待不会占用 GUI 主线程；每次打开带递增请求号，旧 vout 停止期间如果又选择
第三个源，已被取代的第二个源不会进入 `Opening`，只继续最后一次请求。新增停止门闩
回归可稳定卡住旧回收：修改前会在门闩放行前错误打开新源，修改后必须等待释放并跳过
中间源。直播切本地的实例隔离、波形和进度回归继续通过。
