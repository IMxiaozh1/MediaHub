# MediaHub v0.8 Qt 6.8 迁移规划

> 状态：已完成；源码、测试、文档、双远端推送和唯一 Qt6 正式包均已收口。
>
> 日期：2026-08-24。

## 1. 目标

将 MediaHub 从历史 Qt 5.14.2 工具链迁移到 Qt 6.8.3 `msvc2022_64`。Qt SDK 只作为
开发机外部依赖，项目文件继续保留在 `C:\Users\adminstrator\MediaHub`，源码不写入
`C:\Qt6.8`，也不把 Qt SDK 放入仓库。

迁移正式定义为 v0.8。它不新增播放功能，不改变播放内核、WebView2 边界或 Windows
x64 平台范围；当前源码采用 Qt6-only 策略，不维护 Qt5/Qt6 双版本分支。

## 2. 范围

- CMake：`find_package(Qt6 6.8 ...)`、Qt6 target 链接、Qt6 `windeployqt` 定位和 MSVC
  异常模型选项。
- 源码：`qsizetype` 容器索引、Qt6 网络重定向策略、UTF-16 缓冲、事件和鼠标事件 API。
- 测试：所有 Qt Test、Widgets、Network target 与 Qt6 API 构造方式。
- 部署：Qt6 DLL、插件、TLS 后端白名单，拒绝 Qt5 DLL 和 Qt6 Debug DLL。
- 本机状态：Qt6 播放状态使用独立配置，首次运行幂等导入旧版列表、历史、主题和直播源
  备忘，避免 Qt5/Qt6 并行退出时互相覆盖。
- 界面密度：固定 Qt5 时期的 12px Windows 正文字体基线，直播列表不随窗口断点放大，
  并收紧列表项行高和内边距。
- 文档：当前构建命令、依赖版本、许可证、结构图、测试和交付说明。

历史阶段文档中的 Qt5 版本、失败记录和原始交付证据保留，不机械改写为 Qt6 结果。

## 3. 约束与决策

| 项目 | 决策 |
|---|---|
| Qt 版本 | Qt 6.8.3 |
| MediaHub 版本 | 0.8.0 |
| 编译器 | MSVC 19.44，Visual Studio 2022 x64 |
| CMake 入口 | `CMAKE_PREFIX_PATH` 指向 Qt SDK，不硬编码到源码 |
| Qt 模块 | Core 间接使用，Widgets、Network、Concurrent、Test、Svg 按目标接入 |
| 浏览器 | 继续使用固定 WebView2 SDK，不迁移到 Qt WebEngine |
| 播放内核 | 继续使用外部 libVLC 3.0.21 |
| 兼容策略 | Qt6-only；Qt5 仅作为历史记录，不再作为构建依赖 |
| 状态迁移 | 从旧 `MediaHub` 配置一次性导入到 `MediaHubQt6`；直播源按地址合并，Qt6 优先 |

## 4. 完成条件

1. Qt6 Debug/Release 全目标编译无警告。
2. 全量 CTest、Core-only 和无测试构建通过。
3. 发布包包含 Qt6 运行库和插件，不包含 Qt5、Debug、测试或构建文件。
4. 隔离环境能从包内加载 Qt6/libVLC 并正常播放、关闭。
5. WebView2 真实 Runtime 初始化通过，100%/125%/150% GUI 回归通过。
6. 旧版直播源备忘完整进入 Qt6 帮助窗口，且重复启动不会覆盖 Qt6 已有备注或恢复已删除项。
7. 真实视频跨网页页切换不被 Qt6 迁移破坏；可用直播源完成声音和画面人工确认后，
   才能替换旧正式包并提交。
8. Qt6 下主窗口和直播列表保持 12px 正文字体，四档窗口断点的直播列表单行不超过
   30px，实机可见项目数量恢复到接近 Qt5 的水平。

## 5. 不在本次范围

- 不把项目目录移动到 Qt SDK 目录。
- 不迁移到 Qt Quick/QML。
- 不新增移动端、Linux 或 macOS 支持。
- 不更换 libVLC、WebView2 或 MSVC 工具链。
- 不重写历史 Qt5 阶段测试证据。
