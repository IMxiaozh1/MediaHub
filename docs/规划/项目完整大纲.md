## 1. 项目概览

### 1.1 项目名称

`MediaHub`

### 1.2 项目定位

MediaHub 是一个使用 C++20 和 Qt 5.14.2 开发的 Windows 桌面媒体播放器。第一版
播放本地音频和视频文件；第二版支持直接输入直播地址观看网络直播；第三版把播放
内核从第三方库替换为自研 FFmpeg 实现。

### 1.3 核心原则

- 分层：界面、控制逻辑、播放内核和渲染输出各自独立，可以单独替换。
- 可替换：播放内核藏在一个抽象接口之后，换内核不改界面。
- 可解释：模块、数据流、线程边界、错误和测试都能由开发者独立说明。
- 可演进：先用成熟库跑通完整产品形态，再逐步替换核心难点。
- 小步交付：每个增量都能构建、验证和审查。
- 安全：不修改、不删除用户的媒体文件，只做读取和播放。

## 2. 项目成功后的样子

v0.1 完成后，用户可以在 Windows 上双击 `MediaHub.exe`，然后：

1. 通过菜单或拖放打开本地音视频文件。
2. 在播放列表中看到已加入的媒体。
3. 点击播放，听到声音，视频文件同时看到画面。
4. 暂停、继续、停止、拖动进度、调节音量。
5. 切换上一首和下一首，选择顺序、列表循环或单曲循环。
6. 遇到无法播放的文件时看到明确原因，程序继续可用。
7. 关闭窗口后进程干净退出。

项目交付的不只是一个可执行文件，还包括自动化测试、构建说明、设计文档、依赖
部署说明和清晰的 Git 历史。

v0.2 完成后，用户还可以在地址栏粘贴一个直播地址并直接观看。
v0.3 完成后，播放内核可以在第三方实现和自研实现之间切换，用于对照验证。

## 4. 用户流程

### 4.1 正常播放流程

```text
启动程序
  → 初始化播放内核
  → 用户选择本地文件
  → 加入播放列表
  → 打开媒体
  → 输出音频与画面
  → 用户控制播放
  → 当前项结束
  → 按播放模式决定下一步
```

### 4.2 打开失败流程

```text
用户选择文件
  → 加入播放列表
  → 内核打开失败
  → 记录失败原因
  → 界面显示可读提示
  → 程序保持可用，其他项不受影响
```

### 4.3 退出流程

```text
用户关闭窗口
  → 请求内核停止播放
  → 等待内核释放媒体与渲染资源
  → 释放播放内核实例
  → 进程退出，返回 0
```

播放中关闭窗口不得强制终止线程，也不得让进程残留。

## 6. 技术架构

### 6.1 分层

```text
        Qt GUI 应用层（主窗口、控制栏、播放列表视图、视频输出控件）
                              │
                              │ 只依赖抽象接口
                              ▼
              核心层（播放状态机、播放列表、媒体项、PlayerEngine 抽象）
                              ▲
                              │ 实现抽象接口
                              │
        ┌─────────────────────┴─────────────────────┐
        │                                           │
   libVLC 内核实现（v0.1）              自研 FFmpeg 内核实现（v0.3）
        │                                           │
        ▼                                           ▼
     libVLC                              FFmpeg + 音频输出 + 渲染
```

关键点：核心层定义接口，内核实现层依赖核心层，GUI 依赖核心层。GUI 不知道
libVLC 的存在，具体内核只在 `main.cpp` 这一个位置被创建并注入。

### 6.2 依赖规则

- `mediahub_core` 不得依赖 Qt、libVLC 或任何界面代码。
- `mediahub_engine_vlc` 可以依赖 `mediahub_core` 和 libVLC，不得依赖 Qt 和 GUI。
- `mediahub_gui_support` 可以依赖 `mediahub_core` 和 Qt，不得依赖 libVLC。
- 只有 `mediahub_gui` 的 `main.cpp` 同时知道具体内核和主窗口，负责组装。
- Qt 类型不得进入 `mediahub_core` 的公共头文件。
- libVLC 类型不得进入 `mediahub_core` 的公共头文件。
- 新增第三方依赖前必须单独讨论其必要性、许可证和部署成本。

这条“GUI 不认识 libVLC”的规则是 v0.3 能够顺利替换内核的前提，不得为了图方便
在窗口代码里直接调用内核 API。

### 6.3 CMake 目标

| 目标 | 类型 | 作用 |
|---|---|---|
| `mediahub_core` | 静态库 | 播放内核抽象、媒体项、状态机和播放列表 |
| `mediahub_engine_vlc` | 静态库 | 基于 libVLC 的内核实现 |
| `mediahub_gui_support` | 静态库 | 主窗口、播放控制器、视图模型和 Qt 适配 |
| `mediahub_gui` | GUI 可执行程序 | 创建 Qt 应用、组装内核与主窗口 |
| `mediahub_tests` | 测试程序 | 核心与内核实现的 GoogleTest 测试 |
| `mediahub_gui_tests` | 测试程序 | 主窗口、控制器和视图模型的 Qt Test |
| `mediahub_logging` | 静态库 | 结构化日志（阶段 9 引入） |

可执行文件名为 `MediaHub.exe`。详细目录见
[项目结构.md](../设计/项目结构.md)。

## 7. 核心数据流

```text
用户输入（菜单 / 拖放 / 命令行参数）
  ↓
媒体项（来源字符串 + 来源类型 + 显示名称）
  ↓
播放列表（顺序 + 当前索引 + 播放模式）
  ↓
播放控制器（校验状态转换，决定是否调用内核）
  ↓
PlayerEngine 抽象接口
  ↓
libVLC 内核实现
  ↓
┌─────────────┬──────────────────┐
│ 音频输出设备 │ 视频输出窗口句柄 │
└─────────────┴──────────────────┘
       │
       │ 内核在自己的线程上产生事件
       ▼
事件线程适配（跨线程投递到 GUI 主线程）
       ↓
播放状态机
       ↓
界面刷新（按钮状态、进度、时间、状态文字、失败提示）
```

重要约束：

- 事件从内核线程回到 GUI 线程必须经过显式的跨线程投递，不得直接操作控件。
- 播放状态机是界面状态的唯一来源，控件不各自维护一份状态。
- 界面只读取状态，不重新判断业务规则。
- 进度这类高频事件必须节流，不得每次回调都刷新界面。

## 8. 候选领域对象

以下只是设计讨论中的概念，接口阶段再确定正式名称和字段：

| 概念 | 可能包含的信息 |
|---|---|
| 媒体项 | 来源字符串、来源类型、显示名称 |
| 播放状态 | 空闲、打开中、缓冲中、播放中、已暂停、已停止、结束、失败 |
| 播放位置 | 当前毫秒、总时长毫秒、是否可定位 |
| 播放失败 | 失败类别、内核原始信息、面向用户的可读说明 |
| 播放列表 | 媒体项序列、当前索引、播放模式 |
| 内核事件 | 状态变化、位置变化、时长确定、播放结束、发生错误 |

设计时优先使用值语义；抽象接口只在确实需要替换实现的位置使用。

## 9. C++20 与 Qt 能力映射

| 能力 | 使用位置 |
|---|---|
| RAII | libVLC 实例、媒体对象、播放器对象的自动释放 |
| `std::unique_ptr` 与自定义删除器 | 包装 libVLC 的 C 句柄 |
| 纯虚接口 | `PlayerEngine` 的可替换边界 |
| `enum class` | 播放状态、来源类型、失败类别、播放模式 |
| `std::optional` | 尚未确定的时长等可能缺失的值 |
| `std::chrono` | 播放位置与时长，不用裸整数表达时间 |
| `std::string_view` | 只读字符串参数 |
| 原子变量与互斥量 | 内核回调线程与 GUI 线程之间的共享状态 |
| Qt 队列连接 | 跨线程事件投递的实现手段 |
| Qt Model/View | 播放列表的只读展示 |

不为了覆盖语法清单而强行使用 Concepts、模板元编程或复杂继承。

## 11. 测试策略

### 11.1 单元测试

重点验证：

- 播放状态机的合法与非法转换。
- 播放列表的顺序、边界和三种播放模式。
- 媒体来源类型识别。
- 错误类别到可读提示的映射。
- 时间格式化与边界值。

这些测试使用假内核，不依赖 libVLC、Qt 和音频设备。

### 11.2 集成测试

重点验证：

- 真实 libVLC 打开、播放、定位和释放的完整链路。
- 打开失败与损坏文件的错误路径。
- 内核对象释放后的资源回收。
- 中文与空格路径。

集成测试使用 libVLC 的哑音频与哑视频输出模式，不需要真实声卡。

### 11.3 GUI 测试

- 控制器状态与控件启用状态的对应关系。
- 跨线程事件投递后界面状态正确更新。
- 播放列表视图模型的数据角色。
- 窗口关闭时内核确定性释放。

### 11.4 测试数据

- 音频测试文件在运行时生成，采用可用代码直接构造的简单格式。
- 测试结束后由 RAII 自动清理。
- 不使用固定盘符和个人路径。
- 不在仓库中提交任何有版权的音视频素材。

无法用生成数据覆盖的格式，通过人工验收记录在阶段测试文档中，并明确说明这是
人工验证而非自动化验证。

## 12. 非功能要求

### 安全

- 只读取用户媒体文件，不修改、移动、删除或重命名。
- 不联网（v0.1）。
- 日志不记录完整文件路径。

### 可维护

- 播放内核藏在抽象接口之后，替换内核不改界面。
- 函数和类型遵守 [代码规范.md](../设计/代码规范.md)。
- 每次功能变更同步测试和相关文档。

### 性能

- 界面主线程不执行解码、文件读取和网络操作。
- 高频位置事件节流后再刷新界面。
- 播放列表视图模型不为每个单元格复制业务对象。

### 可移植

- v0.1 只正式支持 Windows x64。
- 核心层使用标准 C++20，不引入平台专属类型。
- Windows 专属能力（原生窗口句柄）集中封装在 GUI 层。

## 13. 主要风险

| 风险 | 应对 |
|---|---|
| 范围不断扩大 | 坚持 MVP 边界，新功能单独评审 |
| 界面直接调用内核 API | 强制依赖规则，GUI 目标不链接 libVLC |
| 内核回调线程操作控件导致崩溃 | 统一的跨线程事件投递适配层，单独测试 |
| 关闭窗口时内核未释放导致进程残留 | 明确释放顺序，阶段 11 专项验收 |
| 进度事件过密造成界面卡顿 | 节流后刷新，阶段 7 验证 |
| 测试依赖真实声卡与显示设备 | 使用哑音频与哑视频输出模式 |
| 测试需要有版权媒体素材 | 运行时生成简单媒体，人工验收单独记录 |
| libVLC 部署缺插件导致换机不可用 | 阶段 12 在隔离目录验证 |
| LGPL 合规问题 | 动态链接、保留许可证文本，阶段 12 复核 |
| v0.3 换内核时发现抽象泄漏 | v0.1 就用假内核证明接口可替换 |
| 代码由 AI 一次性生成 | 强制小步审查，开发者能解释后才继续 |

## 14. 协作与审查方式

每个阶段遵循：

1. 先说明当前小目标、设计和验收方法。
2. 双方确认后再写代码。
3. 单次尽量只改 1～3 个文件。
4. 完成后展示 diff、构建结果和测试结果。
5. 由项目所有者阅读、提问或修改。
6. 阶段测试和文档通过后自动提交；远程无冲突且认证可用时自动推送并进入下一阶段。
7. 推送失败时保留本地提交并记录原因，禁止强制覆盖远端历史。

如果实现暴露出设计问题，先回到文档修正规则，再继续编码。
