# v0.7 本地与直播界面重构

> 建立日期：2026-08-17
>
> 状态：已完成（本地自用）

## 1. 目标与边界

重构“本地”和“直播”两个原生播放页面，使其具备成熟桌面音视频软件常见的紧凑层级、
连续播放舞台和稳定控制区。设计可参考 Spotify、Apple Music、VLC、PotPlayer 等产品的
信息组织方式，但不复制商标、Logo、私有素材或逐像素外观。

本阶段只改变 Qt 界面的布局、主题、辅助窗口和音频/歌词画布呈现，并增加播放器外壳的
个性化主题设置。播放状态机、libVLC 内核、播放列表模型、歌词查询、直播清单服务、浏览器
后端和线程边界保持不变。网页页继续使用现有 Edge 风格 Chrome、地址栏和统一侧栏，不参与
本轮视觉重构。

## 2. 当前问题

1. 顶部同时出现模式分段、英文眉题、营销式大标题、副标题和徽章，信息重复且像展示模板。
2. 本地音频使用大面积浅绿渐变、光晕和同心圆，波形与标题重复占据媒体舞台。
3. 媒体舞台、播放列表、当前媒体和控制区分别使用圆角卡片，页面被切割成仪表盘。
4. 本地/直播列表标签与顶部模式导航表达相同层级，用户需要识别两套切换入口。
5. 直播页混用英文信号源文案、橙色控制台视觉和多层边框，不像常规播放器频道栏。
6. 播放进度标题、状态胶囊和全宽主按钮占用空间，却没有提高高频操作效率。
7. 歌词页沿用浅色渐变、胶囊标签和多层半透明面板，与视频/直播的深色播放环境割裂。
8. 播放列表和直播频道工具的文字在不同窗口尺寸下保持同一字号，大窗口中阅读性不足。
9. 在本地或直播页调整窗口后切回网页页，WebView2 仍短暂使用旧边界并显示黑区。
10. 快捷键和直播源备忘窗口仍使用英文眉题、渐变背景、胶囊计数和大面积彩色按钮，与新
    播放器外壳不一致。
11. 软件缺少用户可控的主题入口，无法选择强调色或使用本机图片作为播放器背景。

## 3. 目标布局

```text
┌────────────────────────────────────────────────────────────────────┐
│ MediaHub  [本地] [直播] [网页]                          [主题]     │
├────────────────────────────────────────────────────────────────────┤
│ 本地媒体 / 直播                                                    │
├───────────────────────────────────────────────┬────────────────────┤
│                                               │ 播放列表 / 频道     │
│                媒体舞台                       │ [添加媒体]          │
│          视频 / 波形 / 歌词                    │ 搜索、清单、列表     │
│                                               │                    │
├──────────────────────────┬────────────────────┴────────────────────┤
│ 正在播放 / 状态           │ 进度、播放控制、音量、倍速和播放模式   │
└──────────────────────────┴─────────────────────────────────────────┘
```

列表收起后媒体舞台获得完整宽度。全屏时继续隐藏模式导航、页面标题、当前媒体摘要和列表，
只保留视频画面与必要播放控制，不改变既有全屏语义。

## 4. 视觉与交互规格

### 4.1 播放器外壳

- 原生播放页统一使用中性石墨黑表面，不再按音频/视频切换整页明暗主题。
- 顶部模式入口左对齐，按钮保持固定点击区域；选中状态使用细边或低面积强调，不使用大块
  彩色胶囊。
- 页面标题只说明当前位置和用途，移除英文眉题、营销文案和 MUSIC/VIDEO/LIVE 徽章。
- 圆角限制在输入框、按钮和媒体舞台的必要边界，主体分区主要依靠间距、细分隔线和表面
  明度建立层级。

### 4.2 本地播放页

- 媒体舞台占据主要空间；视频保持黑色画布，音频使用从底部向上生长的单向连续波峰，
  不使用上下镜像，也不重复绘制媒体名称。
- 播放列表右侧固定为紧凑队列，“添加媒体”进入列表标题行，取消底部全宽绿色按钮。
- 播放列表纵向和横向滚动条都使用深灰滑块与列表同色轨道，不显示系统默认白底。
- 本地/直播列表标签不再作为可见的第二套导航；顶部模式入口是用户可见的唯一页面切换。
- 当前媒体摘要与传输控制合并为底部播放坞，播放坞高度和按钮位置不随媒体类型跳动。
- 歌词页使用同一深色舞台，当前歌词高亮，其余歌词保持低对比，不使用渐变卡片和胶囊来源。

### 4.3 直播播放页

- 延续同一播放器结构，右侧列表标题改为“直播频道”，使用克制的红色表示直播和连接状态。
- 清单 URL、历史、载入、定位和搜索仍在频道栏内，但去除“控制台”式英文文案和装饰边框。
- 当前频道选中项使用窄强调线和低面积背景，标记、收藏、刷新、失败状态语义保持不变。
- 视频未开始时显示简洁占位信息，不绘制网格或大面积橙色光晕。

### 4.4 网页页边界

- `BrowserPage`、`BrowserChrome`、`BrowserSidePanel` 和浏览器辅助对话框的结构、颜色、尺寸
  与响应式规则保持现状。
- 只允许调整播放器外层模式导航，使其与新外壳在高度和对齐上协调；网页内容区不得继承
  本地或直播主题属性。
- 网页页重新激活时必须先把 WebView2 边界同步到当前浏览器宿主尺寸，再恢复可见性；该修复
  只处理旧尺寸黑区，不改变网页页内部 UI、导航、标签或下载行为。

### 4.5 个性化主题与辅助窗口

- 顶部右侧提供常规尺寸“主题”按钮，不使用悬浮大入口或营销式图标。
- 主题设置提供默认、海蓝、青绿、暖橙和珊瑚五种强调色；改变强调色只影响播放器外壳的
  选中、焦点、进度和主要操作，不改写网页页内部颜色。
- 用户可选择本机 PNG、JPG、BMP 或 WebP 图片作为背景；程序只读取文件，不复制、修改或
  上传图片，配置只在本机保存完整路径。
- 自定义背景提供横向“模糊度”和“透明度”滑杆，范围均为 0 至 100，拖动时即时预览；
  透明度 0 表示隐藏背景，100 表示完整显示。
- “取消”恢复打开窗口前的主题，“应用”后持久化；同时提供移除背景和恢复默认入口。
- 快捷键、直播源备忘及其保存、关闭、校验确认框统一使用石墨灰平面窗口、中文标题、细
  分隔线和常规尺寸按钮；不改变快捷键内容、直播源编辑、保存和校验行为。

### 4.6 响应式与可访问性

- 760×640 最小窗口到 1920×1080 最大化布局均不得出现文字裁切、控制重叠或列表越界。
- 播放列表宽度在合理范围内随窗口变化；列表标题、列表项和直播频道工具按四档受控放大，
  其余播放器字体保持稳定，避免大窗口难以阅读或整体界面无节制膨胀。
- 100%、125%、150% DPI 下图标、输入框和按钮使用稳定逻辑尺寸。
- 所有图标按钮继续保留中文 tooltip、accessible name、键盘快捷键和明确禁用状态。

## 6. 完成门禁

- 本地和直播页不再出现英文营销眉题、模式徽章、大面积浅绿渐变或仪表盘式卡片堆叠。
- 页面切换、播放、暂停、停止、拖动、音量、倍速、歌词、列表和直播清单行为全部回归通过。
- 网页页 Chrome、侧栏、会话、下载和 WebView2 布局不因本轮改动发生视觉或行为回归。
- 在本地或直播页调整窗口后切回网页页，WebView2 立即使用当前尺寸且不出现旧边界黑区。
- 五种强调色可选择；本机背景图片、0 至 100 模糊度和透明度可即时预览并跨进程恢复。
- 快捷键和直播源备忘窗口不再出现英文眉题、渐变背景、胶囊计数或夸张彩色按钮。
- Debug 全量 CTest 通过，必要的 Release 回归和 `git diff --check` 通过。
- 普通窗口、最大化、100%/125%/150% DPI 无裁切、重叠和明显布局跳动。
- 用户确认本地与直播页达到常规桌面媒体播放器的克制、紧凑和易用水平。

## 7. 明确不做

- 不修改播放器内核、线程回调、网络协议、歌词数据源或媒体播放列表格式；只扩展本机界面
  状态以保存主题设置。
- 不重构网页页内部 UI，不改变 WebView2 生命周期、标签页或下载行为；只修复激活时的边界同步。
- 不新增第三方 UI 框架、字体、图标包或媒体素材。
- 不把用户背景图复制进软件目录，不上传图片，也不把背景应用到网页内容区。
- 不复制其他软件的商标、Logo、专有图标和逐像素外观。
