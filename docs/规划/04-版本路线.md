# MediaHub 版本路线

> 状态：v0.1 至 v0.7 均已按本地自用版本完成。
>
> 分类：规划。
> 本文档记录各版本边界。详细增量与验收结果见对应版本规划和测试文档。

## 1. 为什么先写这份文档

项目先交付可独立验收的本地播放器，再以独立版本增加 URL 直播能力，随后以 v0.3
重构三种播放场景的界面，并在 v0.4、v0.5 增加状态恢复和日常使用能力。v0.6 已增加
基于 WebView2 的独立网页浏览模式；v0.7 在不改网页页内部 UI 的前提下，完成本地、
直播、主题和辅助窗口的成熟桌面播放器风格收口。

提前记录范围有两个作用：

1. 记录 v0.1 为直播能力预留了哪些空间，避免把后来的设计误写成第一版范围。
2. 遇到“顺手加一下”的诱惑时，有明确依据拒绝。

## 2. v0.1 需要为后续预留的空间

只预留以下三点，不做更多提前设计：

| 预留项 | 原因 |
|---|---|
| 媒体项区分“本地文件”和“网络流”两种来源类型 | v0.2 需要按来源类型改变超时和缓冲策略 |
| 播放状态包含“缓冲中” | 本地播放几乎用不到，但状态机提前留位比后期改枚举便宜 |
| `PlayerEngine` 是纯虚接口，GUI 不链接 libVLC | 隔离界面与真实播放能力，便于独立测试 |

除此之外，v0.1 不为直播编写任何代码，也不预留配置项和空函数。

## 3. v0.2：URL 直播播放

### 3.1 版本目标

在保留本地播放能力的基础上，用户可以输入一个直播地址或远程清单 URL 并直接观看。

### 3.2 已完成范围

- 地址输入栏与“打开网络地址”菜单。
- 地址合法性的基本检查与来源类型识别。
- 支持 libVLC 能够处理的常见直播协议。
- 读取用户提供的远程 M3U/M3U8 清单，并与本地播放列表分开显示。
- 缓冲状态显示与缓冲进度。
- 打开超时与用户可中断的连接过程。
- 直播失败提示和用户主动刷新；不自动判断卡顿或重连。
- 直播与点播的界面差异处理：直播不显示总时长，禁用进度拖动。
- 最近播放地址的会话内记录。
- 网络失败原因的可读提示。

### 3.3 明确不包含

- 直播源搜索和内置源库。
- 需要登录、鉴权、签名或特定客户端标识的私有源。
- 录制、缓存到本地和回看。
- 弹幕、聊天和互动功能。
- 多路同时播放和画中画。
- 自适应码率的手动切换界面。
- 任何绕过访问限制或版权保护的能力。

### 3.4 已知难点

| 难点 | 说明 |
|---|---|
| 打开过程可能长时间无响应 | 必须异步打开并允许用户取消，不能阻塞主线程 |
| 直播没有总时长 | 状态机和界面都要能处理“时长未知”，不能假设时长总是有效 |
| 断流与网络抖动 | 协议行为差异导致自动判断不可靠，最终由用户通过按钮或 `F5` 主动刷新 |
| 地址有效性无法预先判断 | 只做基本格式检查，真正的可用性只能由打开结果决定 |
| 内核参数需要针对网络调整 | 缓存时长、超时等参数集中管理，不散落在业务代码里 |

### 3.5 合规边界

MediaHub 只负责播放用户自己提供的地址。项目不内置任何直播源列表，不提供源
搜索能力，也不实现任何绕过访问控制的手段。用户需要自行确保其播放的内容来源
合法。这一条写入 README，不因为实现方便而放宽。

## 4. v0.3：三场景界面重构

### 4.1 版本目标

在不改变 v0.2 播放、列表和快捷键行为的前提下，为本地音频、本地视频和直播建立
三种可辨识的界面模式，并补齐响应式与缩放回归。

### 4.2 已完成范围

- 本地音频采用浅色绿色音乐界面、真实 PCM 波形和统一歌词主题。
- 本地视频采用深色影院画布，保持 libVLC 原生活动画面输出。
- 直播采用紧凑深色工具侧栏，集中展示远程清单地址、操作、状态和频道列表。
- 三种模式复用原控件、对象名、快捷键、模型和 Presenter 路由。
- 覆盖默认、较大、最小窗口、全屏和 100%/125%/150% 模拟缩放。

用户已确认本地/直播列表切换、响应式字号和真实直播播放中的窗口缩放，v0.3
按本地自用版本完成。

### 4.3 明确不包含

- 新的媒体格式、播放内核或媒体处理链路。
- 用户自定义换肤、主题编辑或第三方品牌资源。
- 直播源搜索、内置源、录制、弹幕或频道持久化。

## 5. v0.4：状态持久化与快捷键

v0.4 恢复本地列表、最后直播清单 URL 和成功清单历史，增加可取消清单载入、直播源
备忘、快捷键帮助以及全屏和静音快捷键。启动恢复只展示，不自动播放或请求网络。

详细范围见 [v0.4 规划](09-v0.4-状态持久化与快捷键.md)，完成结论见
[v0.4.0 版本完成说明](../交付/07-v0.4.0-版本完成说明.md)。

## 6. v0.5：日常使用增强

v0.5 为用户已经载入的直播清单增加本地即时搜索，并让收藏跨重启保留；本地媒体增加
最多 20 项最近播放和安全断点续播。不可用标记仍不持久化，启动仍不自动播放、定位或
访问网络。

详细范围见 [v0.5 规划](10-v0.5-日常使用增强.md)，完成结论见
[v0.5.0 版本完成说明](../交付/08-v0.5.0-版本完成说明.md)。

## 7. v0.6：内置网页浏览器

v0.6 增加独立“网页”展示模式，使用 Microsoft Edge WebView2 Runtime 浏览用户输入
的 HTTP/HTTPS 网站。最终版本支持基础导航、多标签、会话恢复、资料侧栏、网页
视频/直播、网页全屏、并发下载和“清除网页数据”。

网页媒体不经过 libVLC；MediaHub 不读取账号密码，也不与 Edge 个人资料共享。下载、
上传、敏感设备权限、外部协议和自签名站点只在用户明确确认后允许；浏览器扩展、Edge
同步以及绕过 DRM 和访问限制不在范围。进入网页模式时暂停当前原生媒体；离开网页时
只隐藏 Controller，后台网页和下载继续运行，原生媒体不自动恢复播放。

详细范围见 [v0.6 规划](11-v0.6-内置网页浏览器.md)，集成边界见
[WebView2 设计](../设计/05-v0.6-WebView2集成设计.md)，最终测试和交付见
[v0.6 测试](../测试/28-v0.6-内置网页浏览器测试.md)与
[v0.6 交付说明](../交付/09-v0.6.0-内置网页浏览器交付说明.md)。

## 8. v0.7：本地与直播界面及主题重构

v0.7 统一本地与直播页的播放器外壳，增加深浅模式、完整配色预设、自定义 RGB 和本机
背景图片；波形、歌词、列表、悬浮面板和帮助子窗口同步适配。网页页内部 Chrome、侧栏、
标签和下载行为保持 v0.6 设计，只修复跨页缩放后的 WebView2 边界同步。

详细范围见 [v0.7 规划](14-v0.7-本地与直播界面重构.md)，验证与交付见
[v0.7 测试](../测试/37-v0.7-本地与直播界面重构测试.md)与
[v0.7 交付说明](../交付/10-v0.7.0-本地与直播界面重构交付说明.md)。

## 9. 未分配版本的候选

以下能力目前没有版本归属，只作为候选记录：

- 字幕加载与显示。
- 多音轨与多视频轨切换。
- 逐帧步进。
- 视频截图。
- 媒体库与目录扫描；v0.5 的轻量最近播放不扩展为媒体库数据库。
- 音效处理与均衡器。
- 快捷键自定义与配置持久化。
- Qt 6 升级。
- 硬件加速解码。

任何一项要开发时，先建立新的版本规划文档，再拆阶段，不直接开始编码。

## 10. 版本号约定

- v0.1.0：本地播放，libVLC 内核。
- v0.2.0：增加 URL 直播。
- v0.3.0：重构本地音频、本地视频和直播界面，不改变功能语义。
- v0.4.0：恢复本地列表与直播清单 URL，增加历史、取消和快捷键帮助。
- v0.5.0：直播清单搜索与收藏持久化，本地最近播放和安全断点续播。
- v0.6.0：基于 WebView2 的内置网页浏览、持久登录和网页媒体播放。
- v0.7.0：本地与直播播放器界面、个性化主题和辅助窗口重构。
