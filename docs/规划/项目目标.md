# MediaHub 项目目标

> 状态：v0.1 开发中，阶段 4 已完成。
>
> 分类：规划。
> 本文档回答“为什么做、为谁做、第一版做到什么算完成”。
> 版本演进路线以 [项目完整大纲.md](项目完整大纲.md) 和
> [后续版本路线.md](后续版本路线.md) 为准。

## 1. 一句话目标

使用 C++20 和 Qt 5.14.2 开发一个 Windows 桌面媒体播放器：第一版播放本地音频和
视频文件，后续版本支持直接输入直播地址观看网络直播，并最终把播放内核从第三方
库替换为自研实现。

## 2. 项目价值

### 对使用者

- 打开本地音乐和视频文件即可播放，不需要安装体积庞大的通用播放器。
- 后续版本粘贴一个直播地址就能观看，不必在浏览器和多个客户端之间切换。
- 播放失败时能看到明确原因，而不是无反应或者闪退。

### 对开发者

- 完整经历需求、架构、编码、测试和交付过程。
- 练习 C++20 的资源管理、类型设计、接口抽象和错误处理。
- 理解播放器的分层结构：界面、控制逻辑、播放内核和渲染输出各自的职责。
- 掌握“第三方回调线程”与“GUI 主线程”之间的边界处理，这是播放器最容易出错的地方。
- 通过可替换的播放内核接口，亲手完成一次“先接现成库、后自研实现”的架构演进。
- 最终能够独立解释每项设计，而不只是让程序运行。

## 3. 目标用户与场景

第一版面向在 Windows 上播放本地媒体文件的个人用户。

典型流程：

1. 用户启动程序。
2. 用户通过菜单或拖放选择一个或多个本地音视频文件。
3. 程序识别文件并加入播放列表。
4. 用户点击播放，程序输出声音，视频文件同时输出画面。
5. 用户可以暂停、继续、停止、拖动进度、调节音量和切换曲目。
6. 文件无法播放时，程序显示原因并继续保持可用状态。

第二版增加：用户在地址栏粘贴一个直播地址，点击播放即可观看。

## 4. 第一版 MVP

第一版只做一个可测试的 Qt Widgets 桌面程序，包含：

- 打开本地音频和视频文件。
- 播放、暂停、继续、停止。
- 视频画面输出与基本窗口适配。
- 播放进度显示与拖动定位。
- 音量调节与静音。
- 播放列表与上一首、下一首。
- 播放失败的明确提示。
- 对播放状态机和核心逻辑提供自动化测试。

支持的具体容器格式、界面细节和内核参数在详细设计阶段确定。

## 5. 第一版明确不做

- 不支持网络直播地址，也不支持任何网络流媒体协议。
- 不做音频可视化、频谱、均衡器和音效处理。
- 不做字幕加载、字幕搜索和多音轨切换。
- 不做视频截图、录制、转码和格式转换。
- 不做媒体库、扫描目录、封面刮削和播放历史数据库。
- 不做换肤、主题系统、动画和自定义控件绘制。
- 不做倍速播放、逐帧播放和 AB 循环。
- 不做自动更新和安装程序。
- 不做移动端、Linux 和 macOS 适配。
- 不复制任何公司代码、图片、模型或业务数据。
- 不在仓库中提交任何有版权的音视频素材。

## 6. 验收标准

MVP 同时满足以下条件才算完成：

- 使用当前约定的 C++20 与 Qt 5.14.2 工具链完成 Debug 和 Release 构建。
- 能够播放常见本地音频文件并正确输出声音。
- 能够播放常见本地视频文件并正确输出画面和声音。
- 暂停、继续、停止、进度拖动和音量调节的行为稳定且可重复。
- 播放列表能够切换曲目，播放完成后按既定规则继续或停止。
- 打开损坏文件或不支持的文件时，程序显示原因且不崩溃、不卡死。
- 关闭窗口时播放内核和后台线程被确定性释放，不留下僵尸进程。
- 播放状态机可以脱离界面和真实播放内核单独测试。
- 自动化测试全部通过。
- 测试媒体在运行时生成，不依赖个人目录或有版权的素材。
- 项目文档能够说明构建、运行、测试和关键设计取舍。

## 7. 后续方向

MVP 完成后按独立版本推进，不提前混入第一版基线：

1. v0.2 增加 URL 直播播放、缓冲状态和断流处理。
2. v0.3 增加自研 FFmpeg 播放内核，并与现有内核并存对照。
3. 字幕、倍速、截图、媒体库等能力仍是更后续的候选。

每项能力都要单独讨论范围、设计和验收，再决定是否进入某个版本。
