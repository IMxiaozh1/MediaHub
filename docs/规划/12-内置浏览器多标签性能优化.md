# 内置浏览器多标签性能优化

> 建立日期：2026-08-14
>
> 状态：已完成并通过最终人工验收

## 1. 背景与目标

用户实测发现，网页标签较多时，点击单标签静音或打开历史、收藏等辅助窗口
会出现明显卡顿。本增量目标是降低 MediaHub 宿主的 GUI 主线程工作量、同步磁盘
I/O 和无效控件刷新，使多标签下的点击反馈保持即时。

本增量不承诺 WebView2 页面本身零 CPU 或零内存消耗。用户要求后台视频和直播继续
播放，因此不得为省资源自动挂起、静音、销毁或重新导航后台 Controller。

## 2. 已确认的性能风险

1. 单标签静音会进入统一声音展示刷新；即使声音窗口隐藏，也可能清空并重建列表。
2. 历史和收藏窗口每次显示或输入搜索文字时，会重新读取 QSettings 并逐行创建控件。
3. 历史记录按完整数组重写并立即 `sync()`，频繁导航可以在 GUI 主线程产生同步 I/O。
4. 标签状态变化存在多个全量 O(n) 刷新入口，且可能在一次用户操作内重复执行。
5. DPAPI 会话快照必须保留，但不应进入静音、切换或搜索输入等高频热路径。
6. `QListWidgetItem` 的重复创建、文本拼接、排序和重绘会随历史、收藏和标签数量增长。
7. 切换 `tabsClosable` 后再恢复会让整个标签栏重建关闭按钮，不能位于常用操作热路径。
8. 网页模式拖动主窗口时，密集 `Move` 事件若逐次同步调用 WebView2 COM 接口，会阻塞
   GUI 主线程并造成窗口位置明显落后于鼠标。

## 3. 实施范围

### 3.1 状态刷新

- 单标签静音只更新目标标签、当前静音按钮和可听数量，不刷新无关标签。
- 声音、历史、收藏、标签搜索和分组窗口隐藏时不重建列表；只标记数据已过期。
- 可见窗口优先对单行做就地更新；只在结构改变或筛选条件改变时全量刷新。
- 同一事件循环内的多次全量刷新合并为一次队列任务。
- 标签关闭按钮只更新新增、删除、固定状态变化涉及的标签，不再关闭后重新开启
  `tabsClosable`。
- 下载高频进度事件按约 100 至 250 毫秒合并界面刷新，完成、失败和取消等终态立即显示；
  后端下载与写盘节奏不变。

### 3.2 历史与收藏

- 首次读取后在浏览器资料模型中维护有界缓存，不在每次窗口显示和每个搜索字符上读取磁盘。
- 历史、收藏、声音和标签搜索优先改为 `QAbstractListModel`/`QListView`；单项变化发出
  精确 `dataChanged()`，结构变化才重置模型。
- 搜索输入使用短延迟合并，快速输入不重建多次列表。
- 列表批量变更时关闭中间重绘，恢复后只触发一次布局和绘制。
- 重复打开未变更的窗口复用现有模型和控件，不再清空重建。
- 历史持久化使用延迟合并写入；正常退出、清空或用户显式修改时必须刷盘。

### 3.3 会话与 WebView2 资源

- 会话保存由定时检查改为脏标记加延迟检查点；无状态变化时不重复加密和写文件。
- 窗口关闭时保留同步最终检查点，不丢失标签、分组、静音、固定和缩放状态。
- 不修改后台 Controller 存活、可见性、音频和挂起语义，不影响视频/直播连续播放。
- 不以定时轮询页面 DOM、标题或媒体状态换取性能数据。

### 3.4 主线程与内存约束

- GUI 主线程只接收已准备好的轻量状态变更，不在点击处理函数中执行 `sync()`、DPAPI
  加密或完整数组重写。
- 持久化定时器使用单次延迟合并；应用关闭时执行一次有界最终刷盘，失败时保留明确错误。
- 不复制 WebView2 页面数据，不缓存完整网页内容，只缓存有上限的宿主元数据和图标。
- 所有性能计数器只放在测试替身或 Debug 诊断入口，Release 不增加常驻轮询和日志噪声。

### 3.5 窗口移动诊断边界

- 已验证活动 Controller 边界更新、物理像素模式、父窗口位置通知合并、Qt 客户区冻结和
  WebView2 Composition Controller 候选均不能改善用户实机持续拖动。
- 用户确认本地、直播和网页三个页面均可复现，WebView2 原生子窗口树不是唯一根因。
- 上述无收益候选均已回退；当前源码继续使用既有窗口式 Controller，不修改 Windows
  原生窗口移动语义。
- 后续诊断不得通过隐藏、挂起、静音、销毁或重新导航网页来换取表面流畅，也不得影响
  播放、网络、下载和 WebView2 子进程语义。

## 4. 可量化验收门禁

1. 100 个假后端标签下，单标签静音只产生一个后端静音命令；辅助窗口隐藏时列表重建为 0。
2. 500 条历史下，连续两次打开未变更的历史窗口，第二次 QSettings 读取和列表重建为 0。
3. 快速输入多个搜索字符时，只对最终查询执行一次完整筛选和列表更新。
4. 标签未改变时，周期检查点不调用 DPAPI 会话保存；正常关闭仍能恢复最后状态。
5. Debug/Release 浏览器定向回归、真实 WebView2 Runtime、core-only 和无测试构建不回归。
6. 普通 Windows 人工验收：打开多个真实网页后，静音、声音、历史、收藏和标签搜索窗口无可感知停顿。
7. 下载持续更新时，UI 刷新频率受控且终态不延迟；下载速度、完整性和断点继续不回归。
8. 普通 Windows 下持续拖动本地、直播和网页三个页面时，窗口位置均不再明显落后于鼠标，
   且不得改变后台播放、下载、窗口吸附和多屏移动语义。

## 5. 实施顺序

1. 以假后端和可计数数据存储补充红灯测试，锁定无效调用次数。
2. 建立资料缓存和轻量列表模型，先移除 QSettings/DPAPI 的 GUI 热路径调用。
3. 优化声音、标签搜索和分组窗口的可见性门禁与就地更新。
4. 增加历史/收藏搜索合并、批量 UI 更新和标签关闭按钮的局部更新。
5. 引入历史延迟写入和会话脏检查点，完成关闭与崩溃边界回归。
6. 运行构建矩阵、真实 Runtime 与普通 Windows 人工性能复验。

## 6. 与网页页 UI 重构的关系

Edge 风格 UI 重构见 `docs/规划/13-内置浏览器Edge风格UI重构.md`。性能阶段先稳定缓存、
模型和脏标记接口，UI 阶段再让历史、收藏、下载、声音等侧边面板复用这些模型，避免先
针对旧对话框优化后又重复改写。两阶段可以在同一开发周期连续执行，但必须分别提交、
分别回归。

## 7. 明确不做

- 不为降低资源占用自动暂停或睡眠正在播放的网页。
- 不结束、合并或共享多标签 Controller，每标签导航与 Profile 语义保持不变。
- 不通过降低画面质量、帧率或声音质量伪造宿主性能改善。
- 不增加第三方性能库或改动 WebView2 Runtime 文件。
