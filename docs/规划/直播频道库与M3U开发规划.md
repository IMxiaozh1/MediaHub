# MediaHub 直播频道库与 M3U 开发规划

> 状态：规划已并入项目路线，尚未开始实现频道库。
>
> 当前前置工作：v0.2 直播连接第二增量已经完成，先完成断流恢复、会话历史和
> 单 URL 完整回归，再进入纯核心 M3U。频道库开发不得破坏现有本地媒体与单 URL
> 直播能力。

## 1. 目标

MediaHub 在现有“输入单个直播 URL 并播放”的基础上，增加用户自己维护的直播频道库：

1. 用户可以在软件页面添加、编辑和删除直播频道。
2. 用户可以为频道设置分类，并按分类浏览和选择频道。
3. 页面修改会安全写入 MediaHub 管理的本地 M3U 文件。
4. 用户可以用文本编辑器修改本地 M3U，再让 MediaHub 重新加载。
5. 用户可以导入其他本地 M3U，并把频道合并到自己的频道库。
6. 用户选择频道后，复用现有 `NetworkStream` 和 libVLC 播放链路。
7. 后续可以增加远程 M3U 订阅、Logo、EPG、收藏和排序。

公开版本只提供频道管理和播放能力，不内置、搜索、抓取或托管第三方直播源。用户需要
自行提供并确认直播地址及内容来源合法。

## 2. MediaHub、M3U 与直播源各自负责什么

| 部分 | 职责 | 不负责 |
|---|---|---|
| MediaHub | 管理频道、解析和保存 M3U、显示分类、把选中地址交给 libVLC | 产生直播内容、绕过登录或版权保护 |
| M3U | 用文本保存频道名称、分类、Logo、EPG 标识和直播地址 | 保存视频数据、保证地址在线、提供解码能力 |
| 直播源提供方 | 通过 HTTP、RTSP、RTMP、UDP、RTP 或 SRT 等协议提供实际音视频流 | 管理 MediaHub 的本地频道列表 |

M3U 可以理解为“频道通讯录”。它可以告诉 MediaHub 某个频道叫什么、属于哪个分类、
播放地址是什么，但真正的画面和声音仍由对应直播地址提供。

## 3. 当前能力与缺口

MediaHub 当前已经具备：

- 从“文件 -> 打开网络地址”输入单个直播 URL。
- 校验 `http`、`https`、`rtsp`、`rtmp`、`rtmps`、`udp`、`rtp` 和 `srt` 地址。
- 将合法地址创建为 `NetworkStream`，交给 libVLC 异步打开。
- 对网络媒体隐藏未知总时长并禁用不可用的进度定位。
- 对列表名称和日志中的 URL 用户信息、查询参数及片段进行隐私保护。
- 显示缓冲百分比，支持 15 秒打开超时和连接期间立即取消。
- 使用专用内核命令线程和网络播放器热替换，避免慢连接停止或切换卡住界面。

频道库仍缺少：

- M3U 解析和生成。
- 持久化的直播频道数据模型。
- 添加、编辑和删除频道的页面。
- 分类列表和频道列表。
- 本地 M3U 导入、重新加载和导出。
- 从频道列表选择频道并接入现有播放链路。

`C:\Users\adminstrator\m3u` 中的第三方仓库只可作为格式观察和本地测试参考，不接入
MediaHub 源码，不执行其中的 Shell/Docker 脚本，也不把其中的直播地址放进公开版本。

## 4. MediaHub 支持的 M3U 子集

第一版使用 UTF-8 文本，文件头为 `#EXTM3U`。一个频道由 `#EXTINF` 元数据行和紧随
其后的直播地址组成：

```m3u
#EXTM3U x-tvg-url="https://example.test/epg.xml"

#EXTINF:-1 tvg-id="news01" tvg-name="我的新闻频道" tvg-logo="https://example.test/news.png" group-title="新闻",我的新闻频道
https://example.test/live/news.m3u8

#EXTINF:-1 group-title="摄像头",局域网摄像头
rtsp://192.0.2.10:554/live
```

第一版字段规则：

| 字段 | 是否必需 | 用途 |
|---|---|---|
| 频道显示名称 | 是 | `#EXTINF` 最后一个逗号后的文本 |
| 直播地址 | 是 | `#EXTINF` 后第一条非空、非注释行 |
| `group-title` | 否 | 频道分类；缺少时归入“未分类” |
| `tvg-id` | 否 | 后续匹配 EPG 的稳定频道标识 |
| `tvg-name` | 否 | EPG 或频道提供方使用的标准名称 |
| `tvg-logo` | 否 | 后续显示频道 Logo 的网络或本地位置 |
| `x-tvg-url` | 否 | 整个频道库使用的 EPG 地址 |

第一版解析器需要：

- 接受 CRLF 和 LF 换行，以及有无 UTF-8 BOM 的文件。
- 忽略空行和普通注释。
- 保持文件中的频道顺序。
- 对协议使用现有 `validateNetworkUrl` 规则。
- 跳过不完整或协议非法的条目，并向用户报告成功、重复和跳过数量。
- 允许相同名称使用不同地址；完全相同的地址在导入时默认视为重复。
- 不因为地址暂时离线而拒绝保存，联网探测只作为用户主动触发的“测试播放”。

M3U 还存在 `#EXTVLCOPT`、`#KODIPROP` 等非统一扩展。第一版不解释这些指令。导入
外部文件时只复制 MediaHub 支持的字段，不原地重写外部文件，避免破坏未知内容。

## 5. 本地频道库

### 5.1 默认位置

使用 Qt 的 `QStandardPaths::AppLocalDataLocation` 获取用户数据目录，在其中管理：

```text
MediaHub/
|-- channels.m3u
`-- channels.m3u.bak
```

Windows 上通常对应 `%LOCALAPPDATA%\MediaHub\`，但代码不得硬编码某台机器的绝对
路径。程序安装目录和源码仓库中都不保存用户的真实频道地址。

首次进入直播频道页面时，如果文件不存在，创建内容只有一行的空频道库：

```m3u
#EXTM3U
```

### 5.2 页面修改写回 M3U

用户在页面完成以下操作后立即保存：

- 添加频道：追加名称、分类、直播地址以及可选元数据。
- 编辑频道：更新对应 `#EXTINF` 和地址。
- 删除频道：移除对应条目。
- 修改分类：更新该频道的 `group-title`。
- 调整顺序：按照当前频道顺序重新生成 M3U。

保存必须使用 `QSaveFile` 或等价的临时文件加原子替换流程。写入完全成功前不得覆盖
原文件；每次成功替换前可保留一份 `channels.m3u.bak`。保存失败时页面展示错误，并
继续保留内存数据和上一次有效文件。

### 5.3 外部编辑后重新加载

用户可以使用记事本等工具直接编辑 `channels.m3u`。MediaHub 提供“重新加载”操作，
并可使用 `QFileSystemWatcher` 检测外部变化：

1. MediaHub 自己保存引起的文件事件直接吸收，不重复导入。
2. 检测到外部修改时提示用户重新加载，不静默覆盖当前页面状态。
3. 解析全部成功后一次性替换内存频道库。
4. 存在非法条目时展示条目位置和原因，由用户决定保留当前列表还是导入有效部分。

第一版采用“操作完成后立即保存”，不保留长期未保存编辑，从而减少外部修改冲突。

## 6. 导入、重新加载与导出

三个操作的语义必须明确区分：

| 操作 | 行为 | 是否修改来源文件 |
|---|---|---|
| 导入 M3U | 读取外部文件，把有效频道合并进默认 `channels.m3u` | 否 |
| 重新加载 | 重新读取 MediaHub 当前管理的 `channels.m3u` | 否 |
| 导出 M3U | 把当前频道库另存为用户选择的新文件 | 新建或经确认后替换目标 |

导入时的第一版合并规则：

- 保持当前频道原有顺序，新增频道按照来源文件顺序追加。
- 完全相同的直播地址默认跳过，并在结果中统计。
- 相同名称但地址不同的频道保留，由用户之后自行编辑或删除。
- 缺少分类的频道放入“未分类”。
- 导入完成并成功保存后才刷新页面；保存失败不得留下半次导入结果。

后续可以增加“新建频道库”和“打开指定 M3U 作为当前频道库”，但第一版只管理一个
默认频道库，减少文件绑定、未知标签回写和多文件冲突问题。

## 7. 页面与交互

直播页面建议分为分类、频道和现有播放区域：

```text
+----------------+----------------------+------------------------+
| 分类           | 频道                 | 播放区域               |
|                |                      |                        |
| 全部           | CCTV-1               | 当前直播画面           |
| 央视           | CCTV-2               |                        |
| 卫视           | 湖南卫视             |                        |
| 体育           | 体育直播             |                        |
| 未分类         | 临时频道             |                        |
+----------------+----------------------+------------------------+
| 添加  编辑  删除  导入 M3U  重新加载  导出 M3U               |
+----------------------------------------------------------------+
```

添加或编辑对话框第一版包含：

- 频道名称：必填。
- 分类：可以选择已有分类，也可以输入新分类；空值保存为“未分类”。
- 直播地址：必填，使用现有网络 URL 校验。
- Logo 地址：可选，第一版可以只保存而不下载。
- EPG ID：可选，第一版可以只保存而不解析节目单。
- “测试播放”：可选操作，不影响用户保存暂时离线的频道。

频道库与现有播放列表是两种不同数据：

- 直播频道库是长期保存的数据，来源为 `channels.m3u`。
- 现有播放列表是本次播放会话中的媒体队列。
- 用户选择频道时，将 `LiveChannel` 转换为 `NetworkStream` 再交给 Presenter。
- 频道切换不得在现有播放列表中无限追加重复项目。

空频道库、读取失败、保存失败、无效地址、网络打开中、用户取消和播放失败都要有明确
中文状态，不能让用户通过界面是否卡住来猜测结果。

## 8. 核心数据与模块边界

建议在纯核心层增加不依赖 Qt 和 libVLC 的类型：

```cpp
struct LiveChannel {
  std::string name;
  std::string category;
  std::string streamUrl;
  std::string logoUrl;
  std::string epgId;
  std::string epgName;
};

struct LiveChannelLibrary {
  std::string epgUrl;
  std::vector<LiveChannel> channels;
};
```

模块职责建议如下：

| 模块 | 所在层 | 职责 |
|---|---|---|
| `LiveChannel` / `LiveChannelLibrary` | `mediahub_core` | 保存纯业务数据 |
| M3U 解析器与序列化器 | `mediahub_core` | UTF-8 文本与频道库互相转换 |
| 本地频道库服务 | GUI 支持层 | 使用 Qt 读写、原子保存和监视文件 |
| 频道列表模型 | GUI 支持层 | 分类过滤、显示和选择频道 |
| Presenter | GUI 支持层 | 校验用户操作并复用现有播放链路 |
| libVLC 内核 | `mediahub_engine_vlc` | 只负责播放选中的网络媒体 |

必须继续遵守现有架构约束：核心层不依赖 Qt 和 libVLC，GUI 支持层不调用 libVLC，
内核事件通过 `EngineEventBridge` 回到 GUI 主线程。

数据流如下：

```text
channels.m3u
    |
    v
纯核心 M3U 解析器
    |
    v
LiveChannelLibrary
    |
    v
分类和频道模型
    |
    v
用户选择 LiveChannel
    |
    v
MediaItem(NetworkStream)
    |
    v
现有 Presenter -> PlayerEngine -> libVLC
```

## 9. 远程 M3U 订阅

远程订阅不是第一版必需功能。它表示用户保存一个网络上的 M3U 地址，MediaHub 可以
手动或定期重新下载最新列表：

```text
订阅 URL -> 下载 M3U -> 本地缓存 -> 解析分类 -> 显示频道
```

订阅频道默认只读，因为 MediaHub 通常没有权限修改远程文件，而且下次刷新会覆盖
本地修改。页面应分开显示：

```text
直播
|-- 我的频道       可添加、编辑、删除，保存到 channels.m3u
`-- 订阅频道       可刷新、停用、删除订阅，频道默认只读
```

用户需要修改订阅频道时，使用“复制到我的频道”，再编辑本地副本。

远程订阅阶段需要额外实现：

- 只允许 `http` 和 `https` 订阅地址。
- 异步下载、连接和读取超时、用户取消及有限重定向。
- 文件大小和频道数量上限，避免异常订阅耗尽内存。
- `ETag` 或 `Last-Modified` 条件刷新，以及最后成功更新时间。
- 下载失败时保留并使用最后一次有效缓存。
- 订阅 URL 的凭据和查询参数不得进入日志。
- 手动刷新优先；自动刷新频率由用户选择，失败不影响正在播放的频道。

## 10. 安全、隐私与发布边界

- 公开版本首次启动时频道库为空，不附带真实第三方直播地址。
- 测试使用运行时生成的 M3U 和本机可控测试流，不提交有版权的音视频或真实订阅。
- 完整直播 URL 可能包含用户名、密码、Cookie 或临时 Token，不得写入日志和错误信息。
- M3U 是普通文本，保存在其中的凭据对本机其他用户可见；保存前需要向用户说明。
- 第一版不支持自定义请求头、Cookie、Referer、DRM、登录、签名生成或访问限制绕过。
- Logo 和 EPG 下载必须异步并有缓存、超时和大小限制；第一版可以只保存字段。
- 删除和覆盖用户选择的文件前必须明确目标并确认；自动保存只作用于 MediaHub 管理的
  `channels.m3u`。
- 直播地址能播放不代表具有传播或商业使用权，责任边界需要在软件说明中明确。

## 11. 分阶段开发顺序

### 阶段 A：完成当前单 URL 直播能力（进行中）

1. 已完成缓冲百分比、打开超时、用户取消和中文错误映射。
2. 已验证连接期间窗口不冻结，停止操作立即返回，取消后可重新播放正常直播。
3. 待实现有限次数、带退避的断流重连和会话内最近地址。
4. 待回归直播与本地 MP3/MP4 切换、音量、进度、全屏和安全关闭。

通过后再开始频道库，避免把连接故障与列表故障混在同一次增量中。

### 阶段 B：纯核心 M3U 与频道模型（未开始）

1. 增加 `LiveChannel` 和 `LiveChannelLibrary`。
2. 实现 M3U 解析和序列化。
3. 覆盖中文、分类、可选字段、BOM、不同换行、非法条目和重复地址。
4. 增加“解析 -> 生成 -> 再解析”往返一致性测试。

### 阶段 C：本地频道库与页面管理（未开始）

1. 创建默认 `channels.m3u`。
2. 增加直播页面、分类列表和频道列表。
3. 实现添加、编辑、删除和立即安全保存。
4. 重启 MediaHub 后频道、分类和顺序保持一致。

### 阶段 D：选择频道播放（未开始）

1. 将选中频道转换为 `NetworkStream`。
2. 复用现有连接、取消、停止和错误处理。
3. 快速切换频道时取消旧连接，旧媒体迟到事件不得覆盖当前频道。
4. 不向现有播放列表无限追加重复频道。

### 阶段 E：导入、重新加载和导出（未开始）

1. 导入外部本地 M3U，并显示成功、重复和跳过数量。
2. 支持手动重新加载默认频道库。
3. 检测外部编辑并提示重新加载。
4. 导出当前频道库，不修改导入来源文件。

### 阶段 F：远程订阅（第一版频道库完成后再排期）

1. 添加、刷新、停用和删除订阅。
2. 使用本地缓存并在失败时安全降级。
3. 订阅频道只读，支持复制到“我的频道”。
4. 后续再增加自动刷新。

### 阶段 G：后续增强（未排期）

- Logo 下载和缓存。
- XMLTV EPG 节目单与当前/下一节目。
- 收藏、搜索、排序和最近观看。
- 分类重命名和批量移动频道。
- 多频道库和本地/订阅聚合视图。

## 12. 第一版频道库通过条件

1. 没有频道时显示空状态，用户可以从页面添加第一个频道。
2. 添加、编辑和删除后，`channels.m3u` 立即、安全且符合格式地更新。
3. 关闭并重开 MediaHub 后，频道名称、分类、地址和顺序保持一致。
4. 用户用文本编辑器修改 `channels.m3u` 后，可以重新加载并看到变化。
5. 导入外部 M3U 不修改来源文件，重复和非法条目有明确统计。
6. 分类依据 `group-title` 生成，缺少分类的频道进入“未分类”。
7. 点击频道只向内核提交对应的 `NetworkStream`，能够显示连接、播放和失败状态。
8. 快速切换、停止或关闭程序不会让旧直播继续连接或留下进程。
9. 保存失败不会损坏上一次有效 M3U，也不会静默丢失用户操作。
10. 日志、列表名称和错误提示不泄漏完整 URL 中的凭据、查询参数和片段。
11. 现有本地媒体、歌词、播放列表、音量、倍速、进度和全屏行为无回归。

## 13. 第一版明确不做

- 不内置任何第三方频道或订阅地址。
- 不抓取、搜索、测速或破解直播源。
- 不搭建直播服务器，不转码、转发或录制直播内容。
- 不实现登录、DRM、签名计算、自定义 Cookie 或访问限制绕过。
- 不要求第一版显示 Logo、EPG、收藏或自动刷新远程订阅。
- 不把第三方 M3U 仓库及其脚本作为 MediaHub 运行时依赖。

第一版的核心成果是：用户能维护自己的本地 M3U 频道库，按分类选择频道，并通过
MediaHub 已有的网络播放能力稳定观看直播。
