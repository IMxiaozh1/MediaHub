# 内置浏览器 Edge 风格 UI 重构

> 建立日期：2026-08-14
>
> 状态：已完成并通过最终人工验收

## 1. 目标与边界

网页页改为用户熟悉的桌面浏览器结构：紧凑标签栏、独立导航栏、地址栏、右侧工具区和
统一侧边面板。目标是达到 Edge/Fluent 一类浏览器的清晰层级、信息密度和操作习惯，
不是逐像素复制 Edge，也不使用微软商标、Logo 或私有素材。

本阶段只重构 MediaHub 宿主界面和交互呈现。WebView2 Profile、导航、安全请求、下载、
会话恢复和后台连续播放语义保持不变；地址栏仍沿用现有网址解析规则，不在本阶段擅自
增加搜索引擎查询。

## 2. 当前问题

1. 标签栏、地址工具栏和信息/设置栏三层常驻，网页内容高度被明显挤占。
2. 后退、主页、历史、权限、声音等大量文字按钮并排，视觉密度不像常规浏览器。
3. 标题和状态重复占用独立一行；标题已经存在于标签页，加载状态也应靠近导航控件。
4. 历史、收藏、标签搜索、声音和分组分别弹出独立窗口，位置、尺寸和关闭方式不统一。
5. 下载中心插在网页内容上方，出现时会让页面整体跳动。
6. 紧凑模式把按钮缩成“历、藏、权”等文字，辨识度和专业感不足。

## 3. 目标布局

```text
┌────────────────────────────────────────────────────────────────────┐
│ [站点图标 标题 ×] [站点图标 标题 ×]  [+]              [标签搜索] │
├────────────────────────────────────────────────────────────────────┤
│ [←][→][↻][⌂] [站点控制 | 地址................ | ☆] [声音][下载][⋯]│
├───────────────────────────────────────────────┬────────────────────┤
│                                               │ 历史 / 收藏 / 下载 │
│                 WebView2 网页内容             │ 声音 / 标签 / 分组 │
│                                               │       侧边面板     │
└───────────────────────────────────────────────┴────────────────────┘
```

右侧面板关闭时网页占满宽度。面板打开时使用布局分栏并重新设置 WebView2 bounds，不把普通
Qt 浮层直接盖在原生 WebView2 子窗口上，避免 Windows 原生子窗口 Z 序造成遮挡和闪烁。

## 4. 交互与视觉规格

### 4.1 标签栏

- 标签栏高度约 38 逻辑像素，导航栏高度约 44 逻辑像素，关闭查找栏和侧边面板后不再
  占用额外常驻 Chrome 高度。
- 活跃标签与导航栏表面连成一体；非活跃标签保持低对比背景，文本超长时省略。
- 网站图标固定尺寸显示；关闭按钮只在当前标签或鼠标悬停时出现。
- 固定标签为仅图标宽度，分组使用克制的颜色标记和折叠入口，不铺大面积彩色背景。
- 正在出声或用户静音直接显示在对应标签上，点击图标只切换该标签静音。
- `+`、标签搜索和关闭都使用熟悉图标，固定点击区域，状态变化不改变行高或标签高度。

### 4.2 导航栏与地址栏

- 后退、前进、刷新/停止、主页改为 32×32 的图标按钮；不可用状态降低对比度。
- 地址栏占据剩余宽度，左侧站点控制按钮打开当前 origin 的权限信息，右侧星标用于
  收藏或编辑当前页；加载、错误和安全状态不再占独立信息行。
- 右侧保留声音、下载和“更多”入口。下载按钮显示轻量活动标记，不用宽文本改变布局。
- 历史、收藏、标签、分组、缩放、启动设置、网站权限和清除网页数据进入“更多”菜单；
  高频的历史、收藏、下载可以由用户当前操作直接打开对应侧边面板。
- 增加 `Ctrl+H` 打开历史、`Ctrl+Shift+O` 打开收藏、`Ctrl+J` 打开下载，以及 `F6`
  在浏览器 Chrome 和网页内容间循环焦点；既有快捷键全部保留。
- 所有非常用图标提供中文 tooltip 和 accessible name；菜单命令使用图标加文字。

### 4.3 侧边面板

- 建立一个可复用 `BrowserSidePanel`，同一时间只显示一个页面，统一标题、搜索、关闭、
  空状态、列表和底部动作区。
- 历史、收藏、下载、声音标签、标签搜索和分组管理迁入右侧面板；编辑收藏、导入确认、
  清除数据和危险权限操作仍使用聚焦明确的小型确认对话框。
- 宽窗口面板建议 360 至 420 逻辑像素；800×600 下使用约 320 像素并隐藏低频工具按钮，
  不允许文字、按钮或 WebView2 内容发生重叠。
- 面板开关不播放装饰动画，保持点击响应直接；列表复用性能阶段建立的数据模型和缓存。

### 4.4 页内查找、状态和错误

- 页内查找采用地址栏下方靠右的紧凑行，包含输入、结果、上一个、下一个和关闭；真实
  Runtime 验证原生窗口层级后再决定是否使用浮动 Tool 窗口。
- 成功提示使用短时状态提示，不保留常驻状态行；加载中由刷新按钮切换为停止图标。
- 初始化失败、页面失败和进程崩溃继续使用网页内容区域中的明确错误页，不用 toast
  代替可恢复错误。

### 4.5 主题、图标与响应式

- 网页 Chrome 使用独立的中性浏览器主题，不再继承本地音频、视频或直播展示模式；
  `QPalette` 提供表面和文字基色，MediaHub 强调色只用于焦点与选中状态。
- 建立 `BrowserIconProvider`，复用项目现有 `QPainter` 矢量图标模式绘制常见浏览器图标并
  缓存 `QIcon`；不复制 Edge 图标文件，也不新增第三方依赖。
- 控件使用 6 至 8 像素圆角，地址栏可使用完整胶囊轮廓；标签、工具按钮和徽标尺寸固定，
  禁止内容变化导致布局跳动。
- 100%、125%、150% DPI 使用逻辑尺寸和高 DPI 图标缓存；不按视口宽度缩放字体。
- 小于 900 像素时隐藏主页等低频按钮并收入菜单，不再把文字缩成单个汉字。
- 宽度断点只调整可见命令和 overflow，不逐个 unpolish/polish 子控件，也不随窗口宽度
  放大字体。

## 5. 代码结构

1. `BrowserPage` 保留状态协调、后端命令和 WebView2 生命周期，不继续承担全部控件构造。
2. 提取 `BrowserChrome` 管理标签栏、导航栏、地址栏和命令入口，只发出语义信号。
3. 提取 `BrowserSidePanel` 及历史、收藏、下载、声音、标签和分组页面；共享标题栏和关闭逻辑。
4. 标签栏保留稳定标签 ID，局部更新图标、声音、固定和关闭状态，不用全量重建。
5. 主题规则按组件拆分到现有 `ui_theme.cpp` 的明确区段；图标由单一提供器生成并缓存。
6. 不把 WebView2、Qt 或 libVLC 依赖引入 `mediahub_core`，不改变既有线程回调边界。

## 6. 实施顺序与提交边界

1. 先完成 `docs/规划/12-内置浏览器多标签性能优化.md` 中的资料模型、缓存和脏标记接口。
2. 为旧 UI 增加结构与快捷键回归，记录 800×600、1280×720、1920×1080 基线截图。
3. 提取 `BrowserChrome`，完成两层顶部结构并移除常驻信息栏。
4. 建立统一右侧面板，依次迁移历史/收藏、下载、声音、标签搜索和分组。
5. 完成 Fluent 图标、主题、DPI、键盘焦点和无障碍状态。
6. 运行假后端、Debug/Release、真实 WebView2 Runtime 和人工视觉/网页媒体回归。

性能实现与 UI 重构必须使用两个独立提交。若 UI 阶段发现功能行为变化，先补回归测试再
修复，不在视觉提交中顺带改变导航、安全或下载规则。

## 7. 完成门禁

- 顶部只保留标签栏和导航栏两层，关闭侧边面板后没有多余常驻状态行。
- 历史、收藏、下载、声音、标签搜索和分组使用同一右侧面板框架。
- 800×600 至 1920×1080、100%/125%/150% DPI 下无文字裁切、遮挡和布局跳动。
- 所有既有浏览器快捷键、会话、权限、下载、标签与后台播放回归通过。
- 普通 Windows 真实 Runtime 下 WebView2 不被 Qt 控件遮挡，面板开关和 resize 无闪烁。
- 用户确认整体观感达到常规 Edge 类桌面浏览器的紧凑、清晰和易用水平。

## 8. 实施结果

- 已提取 `BrowserChrome` 和 `BrowserIconProvider`，网页页现在只有标签栏、导航栏两层常驻
  Chrome；标题/状态不再占用常驻信息行，图标按钮提供固定点击区域、中文 tooltip 和
  accessible name。
- 已建立统一 `BrowserSidePanel`，历史、收藏、下载、声音、标签搜索和分组共用同一侧栏，
  关闭后 WebView2 恢复完整宽度；站点控制只显示当前 origin 的权限，更多菜单保留全量权限
  管理入口。
- 已补齐当前网页星标收藏/编辑、下载活动标记、标签出声状态、快捷键、独立主题、响应式断点
  和高 DPI 图标缓存。初始 WebView2 控制器先报告 `about:blank` 时，仍会沿真实 `onTabReady`
  路径导航到默认 Bing，避免首屏停留空白页。
- BEU-A01 至 BEU-A14 自动化通过；Debug/Release 全量 CTest 均为 `91/91`，core-only 为
  `52/52`，Release 无测试构建成功且 CTest 为 `0` 项；完整 WebView2 Runtime 为
  `57 passed, 0 failed, 0 skipped, 0 blacklisted`。
- Release 人工检查确认默认 Bing、两层顶部栏、历史/收藏/声音/下载侧栏、更多菜单、最大化
  布局和关闭侧栏后的全宽恢复正常。受控本机 HTTP 视频页中 `test.mp4` 持续播放时打开/关闭
  声音侧栏并启动下载，视频画面继续更新，下载中心显示任务并可取消；关闭程序后无本项目
  `MediaHub` 或其 WebView2 子进程残留。
- 规划 12 已完成原生宿主层级修复：WebView2 挂到既有原生祖先，Bounds 使用相对祖先的物理
  像素坐标。真实 Bing、统一侧栏与三页工具拖动复验均正常；用户最终持续拖动确认通过，
  本规划没有通过隐藏、挂起、静音、销毁或重新导航后台网页来掩盖性能问题。
- 网页 Chrome、标签、地址栏、历史、收藏、声音和下载等宿主界面统一改为浅色中性表面，
  活跃标签使用白底、深色粗体和蓝色强调线；侧栏标题条增加高对比底色、分隔边框和标题
  识别线，网页页外框与深色程序背景明确分离。
- “本地 / 直播 / 网页”改为居中的固定尺寸浅色分段控件，三个选中状态分别使用克制的
  绿、橙、蓝强调色。普通窗口和最大化工具实机检查无文字裁切或控件重叠。
- 最终候选 Debug/Release 完整 CTest 均为 `91/91`，core-only `52/52`，无测试 Release
  为 `0` 项；Release BrowserPage 与真实 WebView2 Runtime 定向复跑 `2/2` 通过。
  用户完成最终配色与持续拖动联合验收并确认无问题。
- 规划 13 组件提交为 `1e03a42 feat: 添加规划13浏览器界面组件`，最终浅色可读性修复提交为
  `fad899a fix: 提升网页界面可读性`。

## 9. 明确不做

- 不复制 Edge Logo、商标、私有图标或逐像素伪装成 Edge。
- 不在本阶段增加扩展、Edge 账号同步、密码管理器、垂直标签或搜索引擎切换。
- 不用隐藏、挂起、静音或销毁后台网页来换取 UI 流畅。
- 不增加新的第三方 UI 框架或图标依赖。
