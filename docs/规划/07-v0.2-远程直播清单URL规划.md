# MediaHub 远程直播清单 URL 开发规划

> 状态：实现、自动化、真实直播页面验收与 v0.2 本地自用交付均已完成。
>
> 当前前置：v0.2 单 URL 直播和第五增量纯核心 M3U 解析均已完成。

## 1. 用户目标

用户提供一个远程直播清单 URL，MediaHub 读取并解析其中的 M3U/M3U8 文本条目，以扁平
直播列表展示名称。用户在“本地播放列表”和“直播列表”之间明确切换，并从当前可见
列表选择媒体。

本版本不提供频道分类，也不要求用户逐个添加、编辑或删除频道。`group-title` 只作为
外部 M3U 的兼容字段由核心解析器保留，界面和排序均不使用它。

## 2. 三种地址的语义

| 地址类型 | 行为 |
|---|---|
| 本地媒体文件 | 加入本地播放列表，不进入直播列表 |
| 单个直播流 URL | 使用“打开网络地址”，作为单项加入直播列表并播放 |
| 远程直播清单 URL | “打开网络地址”自动识别并解析多个条目，成功后整体替换直播列表 |

远程清单首版只允许 `http` 和 `https`。清单中的播放地址继续使用现有白名单：
`http`、`https`、`rtsp`、`rtmp`、`rtmps`、`udp`、`rtp` 和 `srt`。

普通 HLS 媒体播放列表包含码率变体或媒体分片，不是可供用户选择的频道通讯录。
通过 `Ctrl+L` 输入时应自动回退为单路直播播放，不得把分片逐个列出；通过清单输入区
载入时则提示它属于单路 HLS。

## 3. 页面结构

播放列表侧栏改为两个明确入口：

```text
+--------------------------------------------------+
| [本地播放列表] [直播列表]                       |
+--------------------------------------------------+
| 本地：文件条目                                  |
|   或                                             |
| 直播：                                          |
| [清单 URL........................] [载入/刷新]   |
| 当前 URL 解析出的扁平直播条目                   |
+--------------------------------------------------+
```

交互规则：

1. 切换列表只改变当前看到和操作的列表，不自动停止正在播放的媒体。
2. 双击本地条目播放本地媒体；双击直播条目复用现有网络播放链路。
3. 上一项、下一项以用户当前选择的列表为准。
4. 本地条目保留已有多选、重命名、排序和移出能力。
5. 直播条目保持远程清单顺序，只允许选择和播放，不提供分类、重命名或重新排序。
6. 成功载入新 URL 后整体替换直播列表；读取或解析失败时保留上一次有效列表。
7. 直播侧显示载入中、成功数、重复数、跳过数、超时、过大和格式无效等中文状态。

## 4. 读取边界

- 调用线程：请求和取消从 GUI 主线程发起；Windows 版由 Qt 线程池中的 WinHTTP 工作
  任务读取，完成后投递回 GUI 主线程，不阻塞窗口。注入网络管理器时保留 Qt 测试路径。
- 新请求取消旧请求，并使用请求代次忽略迟到结果。
- 单次超时 10 秒，最多跟随 5 次不降低安全等级的重定向。
- 响应正文上限 2 MiB，解析后最多接受 5000 个直播条目。
- 只接受有效 UTF-8 文本；支持 BOM、CRLF/LF 和普通注释。
- 相对条目地址以最终响应 URL 为基准补全，再交给现有网络 URL 校验。
- 读取清单时不预先探测每个频道是否在线；真正可播放性仍由用户选择后交给 libVLC
  判断。
- 第一版只保留当前会话中的清单 URL 和结果，不做订阅持久化或定时自动刷新。

## 5. 隐私与安全

- 清单 URL 和条目 URL 可能包含用户信息、查询参数或临时 Token，不进入日志、状态
  文案或窗口标题。
- 日志只记录请求结果类别和条目数量；列表只显示 `#EXTINF` 名称或净化后的显示名。
- 远程响应不能修改本地文件、执行脚本、加载 Cookie、生成签名或绕过访问限制。
- 项目不内置、搜索、抓取或托管任何第三方直播清单；自动化只使用本机临时 HTTP
  服务和示例域名。
- 同一条目地址在一次清单内只保留第一次出现，重复和非法条目分别统计。

## 6. 数据与模块边界

```text
用户输入清单 URL
    |
    v
LivePlaylistService（Windows 原生异步读取、限制、取消）
    |
    v
纯核心 parseM3u（字段、诊断、重复）
    |
    v
扁平 LiveChannel 列表（忽略分类）
    |
    v
独立直播 PlaylistModel
    |
    v
用户选择 -> NetworkStream -> 现有 Presenter -> PlayerEngine
```

`mediahub_core` 继续不依赖 Qt/libVLC；清单读取服务、双列表视图和列表切换位于
`mediahub_gui_support`；只有播放内核处理最终选中的媒体地址。

## 7. 开发顺序

### 第六增量：远程清单读取与解析（已完成）

1. 为核心 M3U 解析增加可注入的相对地址解析边界。
2. 实现异步 `LivePlaylistService`，覆盖 URL 校验、取消、超时、重定向、正文上限和
   条目上限。
3. 使用最终响应 URL 补全相对条目；无效结果不覆盖上次成功数据。
4. 使用本机临时 HTTP 响应覆盖成功、错误、慢响应、过大和迟到结果。
5. Windows 产品路径使用系统 WinHTTP，避免依赖当前 Qt 5.14 未部署的 OpenSSL 1.1。

### 第七增量：双列表与播放接入（已完成）

1. 侧栏增加“本地播放列表 / 直播列表”切换和清单 URL 输入区。
2. Presenter 分开持有本地列表与直播列表；本地文件和网络条目不再混在同一模型。
3. 选择直播条目复用现有连接、缓冲、15 秒播放超时、停止和手动刷新。
4. 回归本地多选、排序、播放模式、上一项/下一项和直播快速切换。
5. `Ctrl+L` 自动探测 M3U/M3U8；频道清单展开，普通 HLS 自动回退为直接播放。

### 第八增量：完整回归与交付（已完成）

1. 自动化覆盖空清单、有效/重复/非法混合清单、相对地址和列表替换原子性。
2. 人工验证真实用户清单的名称、顺序、选择、音画、刷新及本地列表往返。
3. 完成 Debug/Release、Core-only、无测试构建、隐私扫描和阶段文档。

结果：全部构建矩阵、用户人工验收、隐私与模块边界扫描、Release 包结构和隔离运行
通过。v0.2 本地自用交付结果记录于 `docs/测试/21-v0.2-直播增量08测试.md` 和
`docs/交付/05-v0.2.0-最终交付清单.md`。

## 8. 明确不做

- 不显示、筛选或编辑频道分类。
- 不创建 `channels.m3u`，不提供逐频道添加、编辑、删除和本地频道库持久化。
- 不自动定时刷新，不保存带凭据的清单 URL，不做多订阅聚合。
- 不显示 Logo、EPG，不做收藏持久化、搜索或测速；仅保留会话内收藏标识。
- 不把 HLS 分片或码率变体伪装成频道清单。
- 不内置、抓取或推荐直播源。

## 9. 通过条件

1. 用户通过直播页或 `Ctrl+L` 输入有效远程 M3U/M3U8 URL 后，看到按来源顺序排列的
   扁平直播名称列表。
2. 本地和直播条目始终位于两个独立列表，切换视图不会互相追加或清空。
3. 选择任一直播条目可进入现有网络播放链路，停止、刷新和快速切换保持响应。
4. 新清单载入失败时，之前成功的直播列表继续可用。
5. 相对地址正确补全；非法、重复、过多和无名称条目有明确统计或错误。
6. 清单 URL 与条目私密部分不进入日志和状态文案。
7. 本地播放列表的添加、删除、排序、重命名、播放模式和媒体控制无回归。
