# MediaHub v0.6 内置网页浏览器

> 状态：基线规划已实现并随 v0.6 本地自用交付完成；后续多标签性能和 Edge 风格界面
> 分别由规划 12、规划 13 收口。
>
> 分类：规划。

> 演进说明：本文保留最初“切出网页时静音并挂起”的设计背景。日常增强后的当前语义为
> 仅隐藏网页并保持后台运行；进入网页仍暂停活动的原生媒体，离开网页不自动续播。
> 当前行为以 [06-内置浏览器选项卡与资料持久化设计.md](../设计/06-内置浏览器选项卡与资料持久化设计.md)
> 和最终测试为准。

## 1. 版本目标

v0.6 在不改变本地媒体、URL 直播和 M3U/M3U8 清单播放链路的前提下，增加独立的
“网页”展示模式。用户可以输入 HTTP/HTTPS 地址、浏览网站、登录自己的账号，并在
网站允许的范围内观看网页直播或视频。

网页媒体由 Microsoft Edge WebView2 运行时负责，不把网页中的地址提取后交给
libVLC，也不实现绕过登录、鉴权、地区限制或数字版权保护的能力。

## 2. 技术决策

### 2.1 采用 WebView2

v0.6 采用 Microsoft WebView2，而不是当前 Qt 5.14.2 随附的 Qt WebEngine：

| 维度 | Qt WebEngine 5.14.2 | WebView2 |
|---|---|---|
| 网页内核 | 随 Qt 固定，版本较旧 | 使用系统 Evergreen Edge Runtime |
| 现代网站兼容性 | 部分网站可能拒绝或功能缺失 | 更接近当前 Edge |
| 登录与站点存储 | 支持，但受旧内核影响 | 支持独立用户数据目录和持久会话 |
| 网页视频 | 编解码器和 DRM 风险较高 | 由 Edge Runtime、系统和网站共同决定 |
| 项目接入 | 本机 Qt 模块已存在 | 需要新增官方 WebView2 SDK |

本机已经检测到 Evergreen WebView2 Runtime，但这只是开发环境事实。正式程序必须在
启动时检测运行时是否可用，并在缺失时显示可操作的中文提示，不能假定所有电脑都已
安装。

### 2.2 依赖接入门槛

WebView2 SDK 是 v0.6 唯一计划新增的第三方依赖。实现开始前必须先完成独立依赖提交：

1. 从微软官方来源取得固定版本 SDK，记录下载地址、版本和 SHA-256。
2. 放入 `Third_Party/webview2/`，保留上游许可证和版本记录，不修改上游文件。
3. CMake 只让新的 WebView2 适配目标链接 SDK，核心库和 GUI 测试不直接依赖它。
4. Release 默认依赖 Evergreen Runtime，不把体积较大的 Fixed Version Runtime 提交
   到仓库或静默打包。
5. SDK 升级使用独立提交，并重新执行网页兼容性和发布目录检查。

具体 SDK 版本在依赖下载与校验时确定；规划文档不虚构尚未取得的版本或哈希。

## 3. 产品范围

### 3.1 第三个展示模式

1. 当前“本地列表”和“直播列表”之外增加“网页”入口，但网页不是第三种播放列表。
2. 网页模式使用中央区域展示浏览器，上方提供地址栏和浏览控制；本地/直播列表模型
   不因切换网页而改变。
3. 进入网页模式时，如果 libVLC 当前正在播放或缓冲，先请求暂停，避免网页媒体和
   原生媒体同时出声；离开网页模式不会自动恢复原生播放。
4. 离开网页模式时挂起并静音网页，返回时恢复页面本身，不自动替用户点击播放。
5. 网页模式隐藏原生进度、倍速、跳转、播放模式和全屏控制，网页视频使用网站自身
   控件和网页全屏。

### 3.2 浏览控制

首版提供以下能力：

- 地址输入、访问、后退、前进、刷新/停止和主页。
- 页面标题、载入状态和失败提示。
- `Ctrl+L` 聚焦并全选地址栏，`Alt+左/右` 后退或前进，`Ctrl+R` 或 `F5` 刷新。
- 用户省略协议时优先补为 `https://`；HTTP/HTTPS 正常访问，本地文件和外部协议经过
  用户明确选择或确认后允许。
- 页面要求打开登录弹窗时，创建共享同一用户资料的受控子窗口。
- 网页进入全屏后占满 MediaHub 内容区，按 `Esc` 可靠退出。
- 下载显示保存位置和进度，上传只读取用户在系统选择器中明确选择的文件。
- 摄像头、麦克风、位置、通知等权限按网站来源逐次询问，可允许或拒绝。

不把地址栏扩展为互联网搜索框。无法解析为合法站点地址的输入直接提示，不自动提交
给搜索引擎。

### 3.3 持久登录

“持久登录”只指网站会话在正常重启后能够继续使用：

1. WebView2 在 MediaHub 专用用户数据目录保存 Cookie、LocalStorage、IndexedDB、
   Service Worker 和必要缓存。
2. MediaHub 不读取、不记录、不序列化用户名、密码、Cookie 或登录令牌。
3. 内置网页与用户平时使用的 Edge 资料隔离，不共享 Edge 登录状态、收藏夹、扩展、
   密码或微软账号同步。
4. 默认关闭 WebView2 的密码自动保存；是否保持登录由网站 Cookie 和站点存储决定。
5. “清除网页数据”必须经过确认，并通过 WebView2 Profile API 清除 Cookie、缓存和
   网站存储；不在运行时直接删除仍被占用的资料目录。
6. 网站主动使会话过期、修改密码或要求二次验证时，MediaHub 不绕过重新登录。

## 4. 自用浏览能力与安全边界

v0.6 是用户本人控制的本地自用浏览器，不按公共终端或受限只读浏览器设计。正常网页
能力默认可用，但会影响本机文件、设备或其他应用的动作必须让用户当次知情：

1. 用户可访问任意 HTTP/HTTPS 网站，不建立网站白名单；网页正常重定向和自身
   JavaScript、子资源、`blob:` 媒体都由 Edge Runtime 正常处理。
2. `file:` 只在用户输入本地路径或通过文件选择器明确选择后允许；`mailto:`、`tel:`、
   `magnet:` 等外部协议显示目标应用并确认后交给 Windows。WebView2 不支持的
   `edge:`、`devtools:` 内部页不伪装为可用。
3. `javascript:` 和 `data:` 不作为地址栏顶层命令执行，避免粘贴内容直接取得当前
   登录页面权限；这不影响网站自己的 JavaScript。MediaHub 不向任意网页注入带本机
   权限的脚本或宿主对象。
4. TLS 证书错误显示主机、错误和风险；用户可仅对当前会话明确选择继续，程序不设置
   全局“忽略所有证书错误”，关闭后清除临时例外。
5. 摄像头、麦克风、位置、通知、屏幕捕获和剪贴板读取按来源弹出确认，可允许一次、
   对本站记住或拒绝；清除网页数据同时清除持久权限决定。
6. 下载允许用户选择保存位置、查看进度和取消；同名文件必须再次确认，不覆盖、修改、
   移动或删除已有文件。上传只允许读取用户在系统文件选择器中明确选中的文件。
7. 结构化日志仍只记录事件类别、错误码和必要的站点来源，不记录完整 URL、查询参数、
   用户数据目录、网页标题、表单内容、账号、Cookie 或令牌。自用不等于把凭据写日志。
8. 用户可以在本机自行截图和使用自己的账号；仓库测试、截图和文档仍不得提交账号、
   Cookie、令牌、私密网页内容或有版权媒体，避免 Git 历史永久保存这些数据。
9. MediaHub 不限制用户正常访问自己有权使用的网站，但不实现绕过登录、付费、DRM、
   地区或网站访问控制的功能；本地自用不会改变网站的技术限制和授权规则。

## 5. 网页视频能力边界

- 普通 HTML5 视频、直播和声音由 WebView2/Edge Runtime 播放，不经过 libVLC。
- 自动播放遵守网站和 Edge 的用户手势策略，不添加绕过自动播放限制的启动参数。
- H.264、AAC、MSE、EME 和硬件解码取决于 Edge Runtime、Windows、显卡驱动和网站。
- DRM、地区限制、网站反嵌入策略或服务方禁止 WebView2 时，允许明确提示“不受支持”，
  不承诺与完整 Edge 百分之百一致。
- 用户可以通过网站正常下载；MediaHub 不嗅探隐藏媒体地址、去广告、录制、投屏、
  修改网站脚本或绕过网站提供的下载规则。

## 6. 原 v0.6 基线的明确不包含

以下条目适用于 2026-08-11 的 v0.6 首版基线；2026-08-12 已确认的“内置浏览器选项卡、
历史与收藏夹”增量 supersede 其中的标签、历史收藏和密码自动保存限制。新的边界以
`docs/设计/06-内置浏览器选项卡与资料持久化设计.md` 为准。

- 扩展、开发者工具和 Edge 账号同步（多标签页、收藏夹、浏览历史已由后续增量加入）。
- MediaHub 自己的密码管理器或跨设备同步；WebView2 Profile 可按网站规则保存密码和
  自动填充资料，但 MediaHub 不读取这些资料。
- 多任务下载中心、断点续传、自动分类、打印、网页翻译和广告拦截；基础下载、上传
  文件选择和单任务进度属于 v0.6 范围。
- 无提示的全局设备授权；权限只能由用户按来源允许，并可随网页数据一起清除。
- 向远程网页暴露 MediaHub 宿主对象、播放内核或任意本地文件访问能力。
- 把网页直播加入现有直播列表，或把网页媒体转交给 libVLC。
- 绕过 DRM、登录、付费、地区、年龄或客户端限制。
- macOS、Linux 或非 Windows 浏览器实现；v0.6 仍是 Windows x64 本地自用版本。

## 7. 实施增量

### 增量 A：依赖与最小探针

- 固定并校验 WebView2 SDK，保留许可证和版本记录。
- 新增仅 WebView2 适配层使用的 CMake 目标和运行时检测。
- 用最小原生子窗口完成环境、Controller、WebView 创建和确定性释放。
- 证明 Core-only 和不含浏览器实现的 GUI 测试不需要 WebView2 SDK/Runtime。

### 增量 B：抽象接口与第三模式骨架

- 建立可替换浏览器接口、事件监听和假实现。
- 把中央媒体区域改为本地/直播共用播放页与网页页的栈式布局。
- 增加“网页”入口和地址工具栏；切换模式不修改两个播放列表。
- 覆盖进入网页时暂停原生媒体以及离开后不自动续播。

### 增量 C：导航与生命周期

- 实现地址规范化、导航、后退、前进、刷新/停止、主页和快捷键。
- 实现异步初始化、迟到回调隔离、窗口 resize、DPI 和关闭时序。
- 初始化失败、运行时缺失和页面失败都显示稳定中文类别。

### 增量 D：资料持久化与清除

- 使用专用用户数据目录恢复 Cookie 和站点存储。
- 禁用密码自动保存，增加带确认的“清除网页数据”。
- 使用临时资料目录自动化验证“重建后仍登录”和“清除后退出”。

### 增量 E：网页媒体、全屏与完整自用权限

- 接入网页全屏、受控登录弹窗、逐站点权限确认、基础下载/上传、外部协议和当前会话
  证书例外。
- 切出网页时挂起和静音，关闭主窗口时先关闭子窗口和 WebView2 Controller。
- 使用本机受控网页验证视频元素，不把公共网站稳定性冒充自动化覆盖。

### 增量 F：完整回归与本地交付

- 完成 Debug/Release、Core-only、无测试构建和三档缩放回归。
- 在隔离 Release 目录检查 WebView2 Loader、许可证和运行时缺失提示。
- 由用户使用自己的合法网站完成登录保持、真实直播/视频和全屏人工验收。
- 未经用户明确要求，不生成或替换仓库外已有 ZIP。

| W-06 | 内置网页资料不与 Edge 个人资料共享 |

## 9. 主要风险与应对

| 风险 | 应对 |
|---|---|
| 网站拒绝嵌入式 WebView | 如实提示并记录为网站兼容性限制，不伪装为播放器故障 |
| DRM 或编解码器不可用 | 使用真实环境人工验收，不承诺绕过或自行解密 |
| WebView2 异步回调晚于窗口销毁 | 使用请求代次和弱生命周期令牌，关闭后丢弃迟到回调 |
| WebView2 子进程或资料句柄残留 | 固定关闭顺序并增加有界退出检查，不结束系统 Edge 进程 |
| 登录资料泄漏到日志或测试 | 日志仅保留稳定类别，测试使用临时资料和本机受控网页 |
| 新依赖污染核心或 GUI 测试 | 单独适配目标和假浏览器注入，继续执行依赖边界扫描 |
| 页面隐藏后仍播放声音 | 切出时同时静音并请求挂起，人工验证直播和普通视频 |
| 恶意网站滥用设备权限 | 每次展示真实来源和权限类型，允许一次、记住或拒绝 |
| 下载覆盖文件或写错位置 | 使用系统保存窗口、同名确认、临时文件和完成后原子落盘 |

## 10. 版本完成条件

v0.6 只有在以下条件全部满足后才能标记完成并提交交付状态：

1. WebView2 SDK 来源、版本、哈希和许可证可核对，依赖提交独立。
2. 三条既有架构约束继续成立，Core-only 构建不需要 Qt、libVLC 或 WebView2。
3. W-01 至 W-18 均有自动化或人工证据，真实音画、登录和 DRM 不冒充自动化覆盖。
4. Debug/Release 全量、Core-only、无测试构建、三档缩放和发布目录检查全部通过。
5. 用户确认至少一个登录网站、一个网页视频/直播、一次权限请求和一次下载可用。
6. 测试文档、开发交接和后续完成说明同步更新；未完成或受阻时不得提交完成状态。
