# MediaHub 版本路线

> 状态：v0.1 与 v0.2 均已按本地自用交付封存，当前没有后续版本计划。
>
> 分类：规划。
> 本文档记录 v0.1 与 v0.2 的版本边界。v0.2 的增量拆分与验收结果见
> `v0.2直播播放.md`。

## 1. 为什么先写这份文档

项目先交付可独立验收的本地播放器，再以独立版本增加 URL 直播能力。两个版本均已
完成并封存。

提前记录范围有两个作用：

1. 记录 v0.1 为直播能力预留了哪些空间，避免把后来的设计误写成第一版范围。
2. 遇到“顺手加一下”的诱惑时，有明确依据拒绝。

## 2. v0.1 需要为后续预留的空间

只预留以下三点，不做更多提前设计：

| 预留项 | 原因 |
|---|---|
| 媒体项区分“本地文件”和“网络流”两种来源类型 | v0.2 需要按来源类型改变超时和缓冲策略 |
| 播放状态包含“缓冲中” | 本地播放几乎用不到，但状态机提前留位比后期改枚举便宜 |
| `PlayerEngine` 是纯虚接口，GUI 不链接 libVLC | 隔离界面与真实播放能力，便于独立测试 |

除此之外，v0.1 不为直播编写任何代码，也不预留配置项和空函数。

## 3. v0.2：URL 直播播放

### 3.1 版本目标

在保留本地播放能力的基础上，用户可以输入一个直播地址或远程清单 URL 并直接观看。

### 3.2 已完成范围

- 地址输入栏与“打开网络地址”菜单。
- 地址合法性的基本检查与来源类型识别。
- 支持 libVLC 能够处理的常见直播协议。
- 读取用户提供的远程 M3U/M3U8 清单，并与本地播放列表分开显示。
- 缓冲状态显示与缓冲进度。
- 打开超时与用户可中断的连接过程。
- 直播失败提示和用户主动刷新；不自动判断卡顿或重连。
- 直播与点播的界面差异处理：直播不显示总时长，禁用进度拖动。
- 最近播放地址的会话内记录。
- 网络失败原因的可读提示。

### 3.3 明确不包含

- 直播源搜索和内置源库。
- 需要登录、鉴权、签名或特定客户端标识的私有源。
- 录制、缓存到本地和回看。
- 弹幕、聊天和互动功能。
- 多路同时播放和画中画。
- 自适应码率的手动切换界面。
- 任何绕过访问限制或版权保护的能力。

### 3.4 已知难点

| 难点 | 说明 |
|---|---|
| 打开过程可能长时间无响应 | 必须异步打开并允许用户取消，不能阻塞主线程 |
| 直播没有总时长 | 状态机和界面都要能处理“时长未知”，不能假设时长总是有效 |
| 断流与网络抖动 | 协议行为差异导致自动判断不可靠，最终由用户通过按钮或 `F5` 主动刷新 |
| 地址有效性无法预先判断 | 只做基本格式检查，真正的可用性只能由打开结果决定 |
| 内核参数需要针对网络调整 | 缓存时长、超时等参数集中管理，不散落在业务代码里 |

### 3.5 合规边界

MediaHub 只负责播放用户自己提供的地址。项目不内置任何直播源列表，不提供源
搜索能力，也不实现任何绕过访问控制的手段。用户需要自行确保其播放的内容来源
合法。这一条写入 README，不因为实现方便而放宽。

## 4. 未分配版本的候选

以下能力目前没有版本归属，只作为候选记录：

- 字幕加载与显示。
- 多音轨与多视频轨切换。
- 逐帧步进。
- 视频截图。
- 媒体库、目录扫描与播放历史。
- 音效处理与均衡器。
- 快捷键自定义与配置持久化。
- Qt 6 升级。
- 硬件加速解码。

任何一项要开发时，先建立新的版本规划文档，再拆阶段，不直接开始编码。

## 5. 版本号约定

- v0.1.0：本地播放，libVLC 内核。
- v0.2.0：增加 URL 直播。

当前版本路线在 v0.2.0 结束。候选能力不自动获得版本号；只有用户重新明确目标、
范围和验收标准后，才建立新的版本规划。
