# MediaHub v0.2 URL 直播播放

> 状态：单 URL 直播四个增量已于 2026-08-06 封存；第五增量纯核心 M3U 与频道模型
> 已完成。用户已将后续目标调整为远程清单 URL、扁平直播列表和本地/直播双列表。
>
> 目标：保留全部本地播放能力，让用户输入自己提供的直播 URL 并观看。
> 单 URL 能力完成后，再按独立增量实现远程清单读取、本地/直播双列表和条目播放。

## 1. 范围边界

v0.2 的单 URL 阶段只提供通用 URL 播放能力；完成稳定性回归后，频道库阶段只管理
用户自己添加或导入的本地 M3U。程序不内置直播源、不搜索或抓取频道，不处理需要
登录、签名或特定客户端身份的私有源，也不提供录制、回看、弹幕、画中画和多路播放。
MediaHub 不绕过访问限制或版权保护，用户需要自行确认地址和内容来源合法。

首批协议白名单如下：

| 协议 | 常见用途 |
|---|---|
| `http`、`https` | HLS、DASH 或普通网络媒体 |
| `rtsp` | 摄像头和实时流 |
| `rtmp`、`rtmps` | RTMP 直播流 |
| `udp`、`rtp` | 组播、单播或本地监听流 |
| `srt` | SRT 实时流 |

## 2. 增量拆分

### 第一增量：地址输入与最小打开链路（已完成）

1. “文件”菜单增加“打开网络地址”，输入后先在纯核心层校验。
2. 只接受带白名单协议和有效目标的绝对 URL；拒绝空值、空白字符、无协议、本地
   路径、`file:` 和未知协议。
3. 合法地址作为 `NetworkStream` 媒体项加入现有播放列表，并复用 Presenter、状态机
   和视频输出。
4. libVLC 使用网络位置创建媒体描述；真正连接由 libVLC 播放线程异步完成，不在
   GUI 线程预请求或探测地址。
5. 没有已知总时长或不可定位时显示 `--:--`，主进度条保持禁用。

### 第二增量：连接过程（实现与自动化已完成）

- libVLC 缓冲事件会通过线程桥转为 `0..100` 百分比，网络媒体显示
  `正在缓冲 42%`；本地媒体保持原有文案。
- 网络打开使用 15 秒单次计时器。进入播放、失败、停止或切换媒体时
  关闭计时器；超时后停止内核并显示可重试的中文错误。
- 连接期间点击停止立即显示`已取消连接`；即使内核还没发出 `Opening`，
  也不需等待停止事件。取消或超时后的迟到事件不得覆盖当前界面。
- 网络打开失败统一映射为“无法连接网络媒体”，界面和日志不记录完整
  URL、凭据、查询参数或片段。
- libVLC 3 的停止和媒体切换可能等待网络读取；所有真实内核控制命令
  在专用工作线程串行执行。取消或切换网络媒体时立即替换播放器，旧播放器
  在后台独立回收，不阻塞 GUI 或后续打开命令。旧播放器回收时必须先迁移到该
  播放器独享的非空隐藏 HWND 并关闭音视频轨；迁移完成后，新播放器才能绑定主画面
  HWND。不得把活动播放器改绑空句柄，也不得让新旧播放器同时占用主画面，避免
  libVLC 3 创建脱离 MediaHub 主窗口的独立视频窗口。

### 第三增量：断流恢复与会话历史（已完成）

- 历史实现曾在失败、结束或活动停滞后按 1、2、4 秒最多自动重连 3 次，本机可控
  HTTP MPEG-TS 的断流恢复、次数耗尽和取消边界均已完成验收。
- 公网 HTTP-FLV 复验发现，libVLC 活动统计可能在画面和声音持续正常时冻结；即使
  延长确认窗口并加入播放位置兜底，也无法对所有协议可靠区分源站短暂停顿和真实断流。
- 最终产品策略取消自动重连、活动轮询和停滞看门狗。明确失败或结束后只显示
  “直播已断开，请点击刷新”，普通缓冲或画面停顿不会触发程序自动重开。
- 网络直播显示“刷新直播”按钮；用户可在任何直播状态点击，或按 `F5`，立即重开
  当前地址。刷新复用当前列表项，不新增播放列表记录或最近地址，本地媒体不响应。
- 记录本次会话最近使用的 10 个地址，去重并按最近优先排列；地址只供可编辑下拉框
  选择，不写入设置、文件或日志。
- 切换本地媒体、手动停止、移除当前项或关闭程序后，旧直播不得继续输出或覆盖
  当前媒体。直播刷新和直播间切换复用当前 libVLC 实例并替换播放器；切回本地媒体
  时创建新实例隔离旧直播。新播放器必须等旧 vout 完全停止并释放后才能绑定主画面；
  等待期间被后续点击取代的打开请求直接丢弃。两种路径都保留音量和静音状态。

### 第四增量：完整回归与交付（已完成）

- 已使用本机可控测试流完成真实画面、声音、停止、切换和全屏验收。
- 已使用公网 HLS/HTTP-FLV 完成直播语义、直播间切换和返回本地歌曲的兼容性复验；
  第三方地址只在人工输入中使用，不进入仓库。
- 已实现随时可用的手动刷新按钮与 `F5`，并删除自动重连状态、计时器和活动看门狗。
- 已完成 Debug/Release、核心独立构建和既有本地播放回归。
- 已更新版本号、README、交付说明和最终测试记录。

第四增量的前置门槛已经通过。频道库与连接稳定性保持为独立增量；第五增量已在纯
核心层完成，不改变现有播放链路。

## 3. URL 校验规则

- 输入会先去除首尾空白；规范化后的地址内部不得包含空白或控制字符。
- 地址必须使用 `协议://目标` 形式，协议匹配不区分大小写。
- HTTP、RTSP、RTMP 和 SRT 地址必须包含主机；UDP/RTP 允许 libVLC 使用的监听目标
  形式，例如 `udp://@:1234`。
- 格式校验只判断能否安全交给内核，不能证明地址在线或内容可播放。
- 地址片段不用于媒体显示名；查询参数和用户信息不得进入日志或列表名称。

## 4. 线程与隐私

- 对话框、Presenter 和控件更新只在 GUI 主线程运行。
- URL 校验位于 `mediahub_core`，不依赖 Qt、libVLC 或网络。
- `VlcPlayerEngine::open` 只创建媒体描述并提交请求；libVLC 事件仍通过
  `EngineEventBridge` 排队回到 GUI 主线程。
- 完整 URL 只在当前进程内交给 libVLC 和播放列表使用。结构化日志只记录经过净化的
  显示名，不记录完整 URL、用户信息、查询参数或片段。
- 后续最近地址只允许会话内保存；如果未来需要持久化，必须另行设计凭据和查询参数
  脱敏规则。

## 5. 第一增量通过条件

1. 合法白名单 URL 能加入列表并触发一次网络媒体打开及自动播放请求。
2. 非法或未知协议在请求内核前显示中文错误，且不改变当前播放项。
3. 网络媒体打开后总时长未知、不可定位时，时间显示为 `--:--` 且进度条不可操作。
4. VLC 内核不再拒绝 `NetworkStream`，创建网络媒体描述时不访问本地文件系统。
5. 网络列表名称和日志不包含 `user:password@`、查询字符串或片段。
6. 现有自动化测试、核心独立构建和本地文件打开行为无回归。

## 6. 第二增量通过条件

1. 网络媒体的缓冲百分比可见，值始终限制在 `0..100`。
2. 网络媒体 15 秒内未进入播放时停止内核、显示超时错误并允许重试。
3. 连接期间点击停止立即取消，不等待 libVLC 迟到事件。
4. 取消或超时后的迟到缓冲、播放、位置、结束和错误事件不改变当前界面。
5. 正常进入 `Playing`、切换媒体或移除正在连接的最后一项时，超时计时器
   必须关闭。
6. 网络连接失败使用可读中文错误，不泄漏完整 URL 或其私密部分。
7. Debug 全量 CTest、核心独立测试和既有本地媒体回归全部通过。

## 7. 单 URL 完成后的频道库执行步骤

第五增量已完成，其余事项按顺序执行。详细数据格式、界面、存储和验收边界见
`直播频道库与M3U开发规划.md`。

### 第五增量：纯核心 M3U 与频道模型（已完成）

1. 在不依赖 Qt 和 libVLC 的核心层增加 `LiveChannel` 和
   `LiveChannelLibrary`。
2. 实现 UTF-8 M3U 解析和序列化，支持 BOM、CRLF/LF、中文、`group-title`、
   `tvg-id`、`tvg-name`、`tvg-logo` 和 `x-tvg-url`。
3. 复用现有网络 URL 校验；非法或不完整条目可跳过并统计，完全相同地址按重复处理。
4. 覆盖“解析 -> 生成 -> 再解析”的往返一致性测试。

结果：新增 17 个 M3U 场景；Debug/Release 全量 CTest 均为 `67/67`，Core-only
CTest `50/50`，无测试构建成功且 CTest 为 0。解析诊断不携带完整 URL，序列化失败
不返回半成品。详细证据见 `docs/测试/v0.2直播第五增量测试.md`。

### 第六增量：远程直播清单读取与解析（实现与自动化已完成）

1. 用户输入 `http`/`https` 清单 URL，Windows 原生网络任务异步读取 UTF-8 M3U/M3U8
   文本，不依赖 Qt 5.14 未部署的 OpenSSL 1.1。
2. 设置 10 秒超时、5 次安全重定向、2 MiB 正文和 5000 个条目上限。
3. 相对条目以最终响应 URL 补全；非法、重复和跳过项使用核心结构化诊断。
4. 新清单失败时保留上一次成功列表，不用空结果覆盖。

### 第七增量：本地/直播双列表与播放接入（实现与自动化已完成）

1. 播放列表侧栏明确切换“本地播放列表”和“直播列表”，不显示频道分类。
2. 本地文件只进入本地列表；单直播 URL 和远程清单条目只进入直播列表。
3. 直播条目保持来源顺序，不提供逐项编辑、删除、分类或排序。
4. 直播右键菜单只提供“播放/暂停”、“停止”、“标记/取消标记”和
   “收藏/取消收藏”；停止只对当前可停止源启用。标记在会话内生效，条目显示
   “【不可用】”、浅红警示背景与加粗文字，并置灰且不可选择或播放；收藏同样只在
   会话内生效，以“★”前缀显示。
5. 右键单击只打开菜单，右键双击不得激活播放；选择直播条目继续复用现有连接、
   取消、停止、刷新、错误和迟到事件隔离。
6. 标记、取消标记、收藏和取消收藏只刷新目标行，不改变长列表当前滚动位置；直播页
   提供“定位正在播放”按钮，按当前播放源地址把对应行滚动到视图中央并选中。
7. `Ctrl+L` 自动识别 M3U/M3U8；频道清单展开，单路 HLS 自动回退为直接播放。

结果：远程清单读取和双列表已完成；独立视频窗口第四次修正后的 Debug/Release 全量
CTest `72/72`，Core-only `52/52`，无测试构建成功且 CTest 为 0。直播右键菜单和
会话内标记/收藏的最新 Debug/Release 全量回归仍为 `72/72`。实现只读取清单文本，不提供
MP3、MP4 或其他音视频下载。可见页面、真实直播音画与右键交互仍等待用户人工验收。
