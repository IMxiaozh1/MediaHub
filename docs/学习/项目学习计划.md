# MediaHub 学习计划

> 状态：适用于 MediaHub v0.1 规划阶段。随开发进展补充。
>
> 学习定位：自己掌握需求、架构、数据流和设计到核心代码的映射，由 AI 生成
> 具体实现，自己负责读懂、审查和验证。
>
> 建议周期：约 25 小时，可按自己的节奏拆分。

## 1. 这份计划解决什么问题

MediaHub 的代码、测试和文档主要由 AI 生成。学习这个项目不需要逐行背诵实现，
也不需要重新手写全部代码。真正需要获得的是：

1. 知道项目解决什么问题，边界在哪里。
2. 能画出数据从用户点击到声音输出的完整流向。
3. 能解释核心层、内核实现层、界面层为什么这样分。
4. **能说清楚线程边界在哪里，以及跨过它会发生什么。**
5. AI 修改代码后，能判断它影响了哪一层、是否破坏原有约束。
6. 能通过运行、断点、测试和 Git Diff 验证 AI 的结果。
7. 面对一个新需求，能先确定模块、数据结构和测试边界，再交给 AI 实现。

第 4 条是这个项目区别于普通 CRUD 项目的地方，也是播放器最容易出错的地方。
如果只学一件事，学这个。

## 2. 学什么，跳过什么

### 2.1 必须掌握

| 内容 | 要达到的程度 |
|---|---|
| 产品目标与边界 | 能说明程序做什么、不做什么 |
| 三层架构 | 能画出核心层、内核实现层、界面层的依赖方向 |
| 抽象接口的作用 | 能解释为什么 GUI 不能直接调用 libVLC |
| 播放状态机 | 能说出每个状态下哪些操作合法 |
| 线程模型 | 能指出线程切换点在哪一行代码 |
| 异步语义 | 能解释为什么 `play()` 返回后状态可能还不是播放中 |
| 资源释放顺序 | 能说出为什么必须先解除事件监听 |
| 错误分类与映射 | 能区分四类失败及其处理方式 |
| 测试与验证 | 能验证 AI 的修改，而不是只相信回答 |

### 2.2 理解用途即可

| 内容 | 只需要知道 |
|---|---|
| libVLC 的解码实现 | 它负责解封装、解码和输出，细节是黑盒 |
| Qt Model/View | 播放列表数据怎样被转换为只读界面 |
| Qt 信号槽的队列连接 | 它是跨线程投递的实现手段 |
| 原生窗口句柄 | 内核往这个句柄指向的窗口画画面 |
| CMake | 目标、依赖、构建选项和 Debug/Release 目录 |
| 部署 | Qt DLL、VLC 插件和 MSVC 运行库是交付依赖 |

### 2.3 第一轮可以跳过

- `Third_Party/` 中的第三方源码。
- libVLC 每个 API 的完整参数说明。
- Qt `.ui` 文件的 XML 内容。
- 所有 Qt 视图模型的样板代码。
- 音视频编解码的数学原理。
- `windeployqt` 的参数与 DLL 清单。

这些遇到问题时再按需学习，不要因为细节阻塞主线。

## 3. 学习顺序

### 第一部分：范围与架构（约 4 小时）

阅读顺序：

1. [项目目标.md](../规划/项目目标.md)
2. [第一版MVP.md](../规划/第一版MVP.md)
3. [播放内核选型.md](../设计/播放内核选型.md)
4. [项目结构.md](../设计/项目结构.md)

完成后应该能不看文档回答：

- 这个程序第一版做什么、不做什么？
- 为什么不用 Qt 自带的播放能力？
- 为什么先用 libVLC 而不是直接自己写解码？
- 哪个 CMake 目标可以链接 libVLC，哪些不可以？为什么？

### 第二部分：核心概念（约 5 小时）

阅读 [第一版实现.md](../设计/第一版实现.md) 第 2、3 节，以及阶段 3 完成后的
核心层代码。

完成后应该能：

- 画出播放状态机的状态转换图。
- 说明为什么总时长用 `optional` 而不是用 `0` 表示未知。
- 解释假内核存在的三个理由。
- 说明如果接口里出现了一个 Qt 类型会有什么后果。

**动手练习**：在纸上画状态转换图，然后对照代码检查有没有遗漏的转换。

### 第三部分：线程边界（约 6 小时，重点）

阅读 [第一版实现.md](../设计/第一版实现.md) 第 5 节，以及阶段 5 完成后的事件
桥接代码。

这部分要理解的核心问题：

1. libVLC 的事件回调发生在哪个线程？
2. 如果在回调里直接改一个按钮的文字，会发生什么？
3. 队列连接是怎么把执行搬到主线程的？
4. 为什么不能在回调里直接调用停止？
5. 关闭窗口时为什么要先停止事件转发？

**动手练习**：在事件桥接的回调里打印当前线程标识，在主线程的槽函数里也打印，
运行一次，亲眼看到两个不同的值。这个练习比读十遍文档有用。

**自测题**：如果有人把队列连接改成直接连接，程序会在什么时候崩溃？为什么不是
每次都崩？

最后这个问题的答案（时序相关的崩溃是间歇性的）是理解并发问题的关键。

### 第四部分：内核实现（约 4 小时）

阅读阶段 4 完成后的 `src/engine_vlc/` 代码。

重点看三处：

1. 句柄的 RAII 包装 —— C 库资源怎样交给 C++ 管理。
2. 释放顺序 —— 六个步骤，每一步为什么在那个位置。
3. 事件映射 —— 内核事件怎样变成项目状态。

不需要看懂每个 libVLC 参数的含义。

**自测题**：如果把“解除事件监听”从释放顺序的第 1 步挪到第 4 步，可能出什么
问题？

### 第五部分：界面与列表（约 3 小时）

阅读阶段 5 至阶段 8 完成后的 `apps/gui/` 代码。

重点：

- 控件启用状态表怎样从一处驱动所有按钮。
- 进度条拖动为什么需要暂停接受位置更新。
- 播放列表的核心逻辑为什么放在核心层而不是界面层。

### 第六部分：测试与验证（约 3 小时）

阅读 [测试策略与阶段模板.md](../测试/测试策略与阶段模板.md) 和实际测试代码。

重点理解：

- 假内核怎样让测试摆脱不确定性。
- 为什么禁止用固定 sleep 等待。
- 哪些东西自动化测试覆盖不到，为什么。

**动手练习**：故意改坏一处逻辑（比如把单曲循环的下一项算错），跑测试，看它是否
被抓住。如果没被抓住，说明测试有缺口。

## 4. 从设计问题映射到代码

| 设计问题 | 主要模块 | 关键技术 |
|---|---|---|
| 怎样换内核不改界面 | `PlayerEngine` 抽象接口 | 纯虚接口 + 依赖注入 |
| 怎样表达“时长未知” | `PlaybackPosition` | `std::optional` |
| 怎样防止非法操作 | `PlaybackController` | 状态机 + 转换表 |
| 怎样避免跨线程崩溃 | `EngineEventBridge` | Qt 队列连接 |
| 怎样管理 C 库资源 | 句柄包装 | `unique_ptr` + 自定义删除器 |
| 怎样避免界面卡顿 | 内核层节流 | 时间窗口过滤 |
| 怎样让测试不依赖声卡 | 哑输出参数 + 假内核 | 构造参数注入 |
| 怎样保证关闭无残留 | 释放顺序 | 显式顺序 + RAII |

学习时不要只记住类名，要能回答“这个设计解决了什么问题，不这样做会怎样”。

## 5. 掌握标准

能做到以下几点，说明这个项目学到位了：

1. 不看文档画出三层架构和依赖方向。
2. 指出代码中的线程切换点，并解释跨过它会发生什么。
3. 解释释放顺序中每一步的必要性。
4. 拿到一个新需求，先说出它属于哪一层、要改哪些文件、怎么测。
5. 看到 AI 的一段修改，能判断它有没有破坏依赖规则或线程约束。
6. 说清楚哪些功能没有自动化测试覆盖，以及为什么。

第 6 点尤其重要。知道自己的测试覆盖不到什么，比 CTest 全绿更有价值。
