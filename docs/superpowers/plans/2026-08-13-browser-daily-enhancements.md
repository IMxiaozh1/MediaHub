## 1. 总体范围

本增量包括以下能力：

1. 切换到本地或直播页面后，已经开始播放的网页视频、音频和直播继续运行。
2. 主动新建标签、`Ctrl+T`、`Ctrl+W`、`Ctrl+Shift+T` 和标准标签切换快捷键。
3. 首次进入网页页和普通新标签默认打开 `https://www.bing.com/`。
4. 历史、收藏、权限、证书、外部协议、清除资料和下载窗口统一适配网页主题。
5. 重启后按用户选择恢复上一组标签，或打开自定义主页/多个启动页。
6. 网站图标、标签搜索、标签分组、固定标签、手动/自动睡眠和批量操作。
7. 多任务下载中心。
8. 网页声音标签控制中心、每标签缩放和网站权限管理。
9. 网页内查找、标签崩溃恢复、标签右键菜单、收藏导入导出和统一媒体状态提示。

本增量不承诺绕过网站或 WebView2 的自动播放、DRM、后台检测和节流策略。MediaHub
保证自身不再因页面模式切换而主动静音或挂起网页；若网站脚本自行暂停，记录为网站
兼容性边界，不注入脚本强制播放全部媒体元素。

## 2. 不变的架构与安全边界

- `mediahub_core` 不增加 Qt、WebView2、COM、Windows 或 libVLC 依赖。
- `mediahub_gui_support` 仍不链接 libVLC；网页功能不调用播放器内核。
- 每个标签继续使用稳定 `tabId` 和独立 WebView2 Controller，共享同一专用 Profile。
- 普通导航和媒体播放可在后台继续；权限、下载目的地、证书、外部协议、屏幕捕获和
  全屏等交互请求只允许当前可见网页处理。MediaHub 位于本地/直播页面时按安全默认值
  立即拒绝或取消，不排队到用户稍后处理，也不突然弹出网页确认窗口。已经由用户确认
  目标并开始的下载可以继续。
- 不在日志、测试文档或仓库中记录完整 URL、查询参数、片段、Cookie、Token、密码、
  Profile 路径或下载完整路径。
- MediaHub 不自行保存或读取网页密码、Cookie 和表单内容；登录资料继续由 WebView2
  专用 Profile 管理。
- 会话恢复只恢复标签元数据和导航目标，不承诺恢复 DOM、表单内容、滚动位置、网页
  内存状态、媒体播放位置或未提交的权限请求。
- 清除网页数据后必须清除会话恢复记录、已关闭标签栈、站点权限、网站图标缓存和下载
  中心记录，避免刚清除的网页资料通过宿主元数据再次出现。

## 3. 数据模型与状态分离

在实现功能前先扩展浏览器专用模型，避免继续把全局开关塞入 `BrowserPage`：

- `BrowserTabRecord` 增加标签标题、显示地址、图标键、分组 ID、固定状态、用户静音
  状态、是否正在播放音频、媒体活动、活动下载数、是否睡眠、缩放比例和最后激活时间。
- 后端分别维护 `isHostVisible`、`isUserMuted`、`isPlayingAudio`、`hasActiveMedia`、
  `isSuspended`，不再以“页面隐藏”推导“静音并挂起”。
- `BrowserPage` 独立维护全局网页静音；有效静音固定为“全局静音或标签用户静音”，
  打开和解除全局静音都不得覆盖每标签选择。
- 新增浏览器会话模型，保存标签顺序、当前标签、分组、固定状态、静音、缩放和启动
  策略；不进入播放器 `AppStateSnapshot`。
- 已关闭标签使用有界栈，默认最多 20 条；只保存恢复所需元数据，不保留 Controller。
- 活跃下载由单个 `optional` 改为按稳定下载 ID 管理的集合；每项独立处理目的地、进度、
  取消、失败和结束状态。

## 4. 阶段一：后台连续播放与声音控制

### 4.1 页面模式切换

1. `BrowserPage::deactivate()` 只隐藏全部 WebView Controller，不调用 `TrySuspend`，也不
   修改用户静音状态。
2. `activate()` 只恢复当前 Controller 可见性和尺寸，不重新导航、不重建标签。
3. 切换网页标签只改变可见 Controller；其他标签继续运行，是否出声由各自用户静音
   状态决定。
4. 程序最小化不自动暂停网页。自动睡眠由后续独立策略控制，默认关闭。

### 4.2 声音标签控制中心

1. 使用 WebView2 音频状态事件维护每个标签的“正在出声”状态。
2. 标签显示声音/静音图标；点击图标只切换该标签静音，不激活标签。
3. 网页模式按钮在本地/直播页面显示后台网页出声数量。
4. 增加声音标签面板，列出正在出声或被静音的标签，支持切换、静音、取消静音和关闭。
5. 增加“全部网页静音/恢复用户状态”，全局静音只作为有效状态叠加，不覆盖每标签选择。
6. `BrowserPage` 向主窗口提供可听网页标签数量；主窗口与本地媒体、直播状态合成统一
   媒体状态提示，便于定位当前声音来源，但不跨模块直接控制播放内核。
7. 正在播放、正在出声或有活跃下载的标签不得进入手动或自动睡眠。

### 4.3 阶段验收

- 两个受控网页媒体标签开始播放后，切到本地、直播和其他标签，媒体时间继续推进。
- 页面模式切换不产生额外 Navigate、Controller 重建、挂起或用户静音状态变化。
- 单标签和全局静音可预测，切换模式后保持原状态。
- 统一媒体状态能区分本地、直播和网页声音来源，不显示完整网页地址。
- 后台网页的敏感请求不显示到本地/直播页面。
- 关闭含多个媒体标签的程序后无 `MediaHub.exe` 或 WebView2 子进程残留。

## 5. 阶段二：Bing 首页、主动新标签与标准快捷键

1. 默认首页统一为 `https://www.bing.com/`。
2. 没有可恢复会话时，首次进入网页页只导航一次 Bing。
3. 标签栏增加 `+` 按钮；主动新建标签和 `Ctrl+T` 打开 Bing 并切换过去。
4. “主页”按钮在当前标签打开用户配置的主页；未配置时打开 Bing。
5. `Ctrl+W` 关闭当前标签。只剩一个标签时复用存活 Controller 打开 Bing，不关闭主窗口。
6. `Ctrl+Tab`、`Ctrl+Shift+Tab` 循环切换标签；中键继续关闭指向的标签。
7. Qt 控件焦点与 WebView2 原生子窗口焦点走同一稳定动作枚举，避免快捷键只在地址栏生效。
8. 网站 `window.open`、`target=_blank`、历史和收藏的新标签仍打开请求地址，不替换为 Bing。
9. 默认标签上限为 20，可在设置中调整到 5 至 100；创建失败不留下假标签。
10. 清除网页数据完成后停留在 `about:blank`，不立即访问 Bing；用户下一次主动新建标签
    才访问首页。
11. 增加网页内查找，`Ctrl+F` 打开当前标签的查找条，支持上一个、下一个、结果计数和
    `Esc` 关闭；查询只传给当前 WebView2 查找能力，不写入历史、设置或日志。
12. 增加标签右键菜单，提供复制地址、复制标题、复制标签、重新加载、关闭、关闭其他、
    关闭右侧、静音和移动到分组；固定、出声和活动下载标签继续受批量操作保护规则约束。

## 6. 阶段三：浏览器资料窗口与网站权限管理

### 6.1 统一网页主题

1. 增加独立 `themeMode=web`，采用深石墨背景、绿色状态强调、清晰边框和紧凑卡片布局。
2. 统一历史、收藏、收藏编辑、清除资料、权限、证书、外部协议和下载相关窗口。
3. 懒创建窗口在创建时显式继承网页主题，不能只依赖主窗口启动时的一次主题刷新。
4. 所有窗口提供标题区、说明区、内容区、空状态和底部操作区。
5. 在 800x600 与 Windows 100%/125%/150% DPI 下不得裁切关键按钮或输入框。

### 6.2 历史和收藏增强

1. 历史显示标题、域名、规范化 URL 和访问时间，支持搜索、删除选中和确认后清空。
2. 收藏显示标题、域名、备注和 URL，支持搜索、新增、编辑、删除和拖动排序。
3. 保留左键当前标签、`Ctrl+左键`/中键新标签语义。
4. 空记录显示正式空状态；危险操作使用警示色，不复用主要绿色按钮。
5. 收藏支持标准浏览器书签 HTML 的导入和导出。导入先解析到临时模型，执行协议过滤、
   地址规范化、去重和数量限制后再原子替换；导出不包含 Cookie、备注以外的宿主状态、
   会话恢复地址或历史记录。

### 6.3 网站权限管理

1. 增加按来源管理的相机、麦克风、通知和其他可记忆权限列表。
2. 允许撤销“本次会话允许”“始终拒绝”等宿主记录；屏幕捕获永不提供永久允许。
3. 来源只保存规范化 origin，不保存路径、查询、片段或请求内容。
4. 清除网页数据同时清除宿主权限记录和 WebView2 Profile 权限状态。

## 7. 阶段四：关闭标签恢复、会话恢复与启动页

### 7.1 `Ctrl+Shift+T` 恢复关闭标签

1. 普通关闭、批量关闭和网站自请求关闭进入有界已关闭标签栈。
2. 恢复原地址、标题提示、分组、固定状态、静音和缩放；分配新的稳定 `tabId`。
3. 清除网页数据、关闭内部空白标签或创建失败不进入恢复栈。
4. 连续按 `Ctrl+Shift+T` 按最近关闭顺序恢复；恢复失败不丢弃后续记录。

### 7.2 重启后恢复整组网页会话

1. 启动策略提供三种互斥选择：打开 Bing、恢复上次会话、打开指定启动页。
2. 默认保持“打开 Bing”，只有用户主动启用才恢复上次会话。
3. 会话保存标签顺序、当前标签、分组、固定、静音、缩放和导航目标，不保存网页内容。
4. 为兼顾精确恢复和 URL 隐私，完整恢复地址使用 Windows DPAPI 加密后写入浏览器专用
   会话文件；索引和日志不包含明文 URL。解密失败时丢弃该会话并安全打开 Bing。
5. 保存前拒绝非 HTTP(S)、用户信息地址、内部清除页和危险协议；不把会话内容写进测试
   文档或错误日志。
6. 正常退出和有界周期检查点更新会话；恢复时先建立标签模型，再异步创建 Controller，
   不阻塞 GUI 主线程。
7. 恢复会话不绕过网站自动播放策略，也不声称恢复媒体进度或表单状态。

### 7.3 自定义主页和多个启动页

1. “主页地址”和“启动行为”分别配置，避免主页按钮与启动会话耦合。
2. 主页只允许一个 HTTP(S) 地址，默认 Bing。
3. 指定启动页支持有序多个地址、添加当前页、添加当前全部标签、排序和删除。
4. 地址输入统一走现有安全规范化；拒绝用户名密码、危险协议和无效地址。
5. 恢复会话与多启动页互斥；设置界面明确显示实际启动行为。

## 8. 阶段五：网站图标、缩放、标签搜索与资源管理

### 8.1 网站图标 FavIcon

1. 优先使用 WebView2 提供的 Favicon API，不由 MediaHub 对网页图标 URL 发起额外网络请求。
2. 图标按规范化 origin 缓存，限制像素、格式、单项大小和总缓存数量。
3. API 不可用、读取失败或图像损坏时使用内置通用图标，不影响导航。
4. 清除网页数据时清除图标缓存；日志只记录固定失败事件，不记录来源地址。

### 8.2 每标签缩放

1. 支持 `Ctrl++`、`Ctrl+-`、`Ctrl+0`，范围 25% 至 500%，常用档位优先。
2. 缩放属于标签状态，切换标签时恢复；可选择按 origin 记忆默认缩放。
3. 工具栏显示当前比例，并提供点击菜单；Qt 与原生 WebView 焦点行为一致。

### 8.3 标签快速搜索和批量操作

1. 增加标签搜索面板，按标题和域名筛选，不检索网页正文。
2. 支持快速切换到正在出声、固定、睡眠或指定分组的标签。
3. 支持关闭其他标签、关闭右侧、批量静音、批量睡眠和移动到分组。
4. 固定标签、活跃下载标签和正在出声标签默认不参与危险批量操作，用户必须显式选择。

### 8.4 标签分组与固定

1. 分组保存稳定 ID、名称、颜色和折叠状态；折叠只隐藏标签栏项目，不暂停网页。
2. 标签拖入、移出和组内排序不改变 `tabId` 或 Controller。
3. 固定标签位于标签栏左侧，默认不显示关闭按钮，不参与“关闭其他标签”。
4. `Ctrl+W` 关闭固定标签前显示轻量确认，避免误关长期直播或控制台页面。

### 8.5 睡眠标签

1. 原计划支持手动睡眠和可选自动睡眠，但本轮因 Runtime 媒体信号不足而不启用；自动睡眠
   默认关闭。
2. 若后续 Runtime 提供可靠信号，自动睡眠时间可选 15、30、60 分钟；手动和自动入口共用
   资格判断，只对长期未激活且
   无声音、无媒体播放、无下载、无未决请求、非固定的后台标签调用 `TrySuspend`。
3. 正在播放、正在出声或有活动下载的标签绝不睡眠，这是后台连续播放需求的硬门禁。
4. 选择睡眠标签时异步 Resume，恢复完成前显示明确状态，不重新 Navigate。
5. `TrySuspend` 失败不强制静音、不伪造睡眠成功；状态与日志记录固定错误类别。
6. Runtime 无法可靠报告静音视频等媒体活动时，不启用该 Runtime 的睡眠功能，不使用
   标题、网址或超时猜测媒体是否停止。

### 8.6 标签崩溃恢复

1. 监听每标签 WebView2 进程失败事件，区分渲染进程退出、浏览器进程退出和宿主关闭；
   事件只携带稳定标签 ID、代次和固定失败类别。
2. 单标签渲染失败显示独立恢复页，保留标签标题提示、分组、固定、静音和缩放；用户点击
   “重新加载”后使用 WebView2 `Reload` 恢复当前网页实例，不在宿主中重放或记录完整地址。
3. 不自动无限重启；同一标签短时间连续失败进入有界退避，并允许关闭标签或复制安全地址。
4. 浏览器进程整体退出时统一标记受影响标签，本轮不在失效 Environment/Profile
   上伪造局部恢复，而是明确提示重启 MediaHub 后使用已保存会话恢复。
5. 崩溃恢复不保存 DOM、表单、媒体位置或未决安全请求，恢复地址继续遵守会话加密和日志
   脱敏规则。

## 9. 阶段六：多任务下载中心

1. 把单任务下载组件升级为下载中心，支持多个并发和等待用户选择目标的任务。
2. 每项显示安全文件名、来源 origin、进度、速度、剩余大小、状态和失败原因类别。
3. 支持取消单项、重试可重试失败、清除已完成和取消全部；不能自动覆盖已有文件。
   目标二次校验或下载事务启动失败必须经 `onDownloadUpdated` 投递 `Failed` 终态，不能
   把任务留在“等待下载开始”。
4. 目标必须由系统保存窗口确认；不自动打开可执行文件，不在日志中记录完整目标路径。
5. 下载可在网页页隐藏时继续；目标选择、覆盖确认等系统交互只能由用户当前操作触发。
6. 当前阶段下载列表只保留本次应用会话；若以后持久化，只保存文件名、状态和 DPAPI
   加密目标，不在本轮扩大范围。
7. 退出时若有活动下载，显示非阻塞确认：取消下载并退出，或返回应用；不让关闭流程
   无限等待 WebView2。

## 10. 主要文件范围

- `apps/gui/browser_page.*`：标签模型、快捷键、声音面板、网页查找、右键菜单、搜索、
  分组和浏览器窗口。
- `apps/gui/browser_backend.h`、`apps/gui/browser_types.h`：稳定后端能力和事件语义。
- `apps/gui/browser_data_store.*`：主页、启动策略、权限、缩放、分组、收藏导入导出等
  非敏感设置。
- 新增浏览器会话存储：DPAPI 加密的会话地址与有界关闭标签栈。
- `apps/gui/browser_download_widget.*`：演进为多任务下载中心，必要时按职责拆分文件。
- `apps/gui/ui_theme.*`、`apps/gui/main_window.*`：网页主题与统一媒体状态提示。
- `src/browser_webview2/webview2_browser_backend.cpp`、`webview2_tab_controller.*`：音频状态、
  网页查找、Favicon、缩放、睡眠、崩溃恢复和多下载事件。
- `src/browser_webview2/webview2_accelerator.h`：全部原生内容区快捷键映射。
- `tests/gui/browser_page_test.cpp`、`tests/integration/webview2_browser_test.cpp` 和主窗口测试。

实现前先更新设计文档，明确新增接口、线程、生命周期、失败语义和持久化格式；单阶段尽量
只改 1 至 3 个生产文件，必要的模型提取使用独立提交。

## 12. 阶段顺序、提交与停止条件

建议按以下顺序实施，任何阶段暴露设计问题先修正文档再继续：

1. 后台连续播放、声音控制和统一媒体状态。
2. Bing 首页、主动标签、快捷键、网页内查找和标签右键菜单。
3. 浏览器窗口主题、历史/收藏、收藏导入导出和权限管理。
4. 关闭标签恢复、重启会话和启动页。
5. FavIcon、缩放、搜索、分组、固定、睡眠和标签崩溃恢复。
6. 多任务下载中心。
7. 全量回归、真实网站人工验收和 Release 包更新。

每阶段先添加可复现或规格测试，再实现，再回填新建的阶段测试文档和
`docs/02-开发交接.md`。规定测试通过且需要的人工验收完成后自动创建单目的提交并推送。
测试失败、Runtime 证据缺失、含媒体页面退出残留或敏感数据扫描失败时不得提交该阶段。

## 13. 明确暂不加入的功能

- 广告拦截、脚本注入和内容规则订阅：兼容性、维护和网站条款风险过高。
- 浏览器扩展系统：会显著扩大权限、供应链和发布包安全面。
- MediaHub 自行保存密码或 Cookie：继续交给 WebView2 Profile。
- 强制绕过自动播放、DRM 或网站后台暂停：不做对抗网站策略的实现。
- 通用开发者工具入口：不属于播放器日常使用路径；需要时保留开发构建诊断方案。
- 自动打开下载的程序或脚本：不跨越安全边界。
